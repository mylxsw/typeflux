# Bounded built-in web reads

The local engine admits a contiguous leading wave of at most three stock web reads. Classification is synchronous, internal and default-serial; the stock host opts in only for its matching web definitions, after built-in/device collision resolution. State tools, device/custom tools and approval boundaries stay serial. Approval-enabled runs execute only the individually approved call.

Admission, reservation and required snapshots finish before effects start. Workers receive immutable inputs and return indexed outputs; only the engine mutates records. The owned coordinator forwards cancellation to structured children and waits for cleanup. Settlement uses the original record/root even after cancellation, deletion or replacement. A missing journal is an error: only new-run initialization may create it. Result application reloads current ownership, binding, status and exact pending arguments and applies deltas, preserving a concurrent memory purge. Failed result snapshots retain completion evidence and recovery state in memory rather than executing the wave again.

Focused tests cover 3/3/1 overlap, reverse completion, sibling failure, barriers, approval, last legacy allowance, each shortage slot, cancellation/session-task cancellation, uncooperative replacement, deletion, memory purge, missing journals and failed result persistence. The stock host is exercised with a local URLProtocol transport and the real budget store. Final core coverage execution ran 60 tests successfully; changed executable-line coverage was 126/127 (99.21%). Separate discovery, MCP, storage and web boundary scopes and failed-method retries are recorded in the GUL-444 evidence attachment.

Six injected 40ms requests took 360.39ms serial and 138.71ms bounded in the controlled stock-host harness. Peak concurrent requests were 1 and 3; both modes completed and charged six web requests. These are local harness results, not provider speedups or monetary billing measurements.

Discovery used fake MCP servers, 20 repeated calls at 0/10/50 tools, explicit selection, held/disconnected connections, tools-changed invalidation and settings removal. At 50 tools with 4096-byte fields, assembly averaged 1.251ms, schema sorting/serialization 0.628ms, cached registry reads 0.308ms and prompt serialization 1.486ms, with 210734 schema bytes and 215571 prompt bytes. Cached reads were already cheaper than schema/prompt processing. Discovery, auto-connect, selection and server lifecycle remain unchanged.

The three previously reported failing methods reproduced their four assertions at baseline c465316ad7d880aff277b64c8b53055a51b9dac5. Tests now match the modular prompt's quoted environment data and use an owned media worker for image projection; shared previews require lifecycle admission and withhold images without it. Reentrancy assertions account for explicit result checkpoints and for cancellation completing before a replacement inference finishes preparation. They still assert that late work cannot overwrite the replacement or restore purged memory.
