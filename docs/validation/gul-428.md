# GUL-428: Capturing app dialogs and notices

Explicit capture uses the shared window policy in screenshots, scrolling captures and display/region recordings. Automatic AI screen context continues to exclude the app's own windows.

| Surface | Finding and change |
| --- | --- |
| Settings import/export and folder selectors, workflow close confirmations, updater/app alerts, recording save dialogs | Capture panels inherited AppKit's default refusal of input during a modal session. Selection, recording controls, long-image/scroll panels, pins, beautification and permission panels now opt into modal input. |
| Capsules, popovers, hover cards and small notices | Screenshot snapping accepted only layers below 20; recording sources required layer 0 and dimensions above 50 points. Own-process windows now remain selectable at higher levels and smaller sizes. Other apps retain their existing filtering. |
| Screenshot notices, permission notices, ordinary tooltips and completed pins | Broad identifier/class exclusions removed these from the captured pixels. These surfaces are now retained. Capture-tool tooltips remain excluded at their elevated window level. |
| Active screenshot/scroll/recording controls | Still excluded to prevent controls covering the source or feeding back into live capture. |

Validation used macOS 26.6.2, Swift 6.4 and real ScreenCaptureKit access. No provider credentials, microphone or camera were needed.

```sh
swift build
TYPEFLUX_REAL_SCREEN_CAPTURE_TESTS=1 make coverage SUITE="ScreenshotCaptureWindowPolicyTests ScreenshotSelectionTests ScreenCaptureServiceTests ScreenshotCoordinatorTests ScreenshotOverlayTests ScrollCaptureUITests ScreenRecordingNativeCaptureTests"
TYPEFLUX_REAL_SCREEN_CAPTURE_TESTS=1 make coverage SUITE="ScreenshotCaptureWindowPolicyTests ScreenRecordingNativeCaptureTests"
TYPEFLUX_REAL_SCREEN_CAPTURE_TESTS=1 make coverage SUITE="ScreenshotCaptureWindowPolicyTests"
```

All 148 selected methods passed across the completed scopes: 123 XCTest methods, 12 capture-service methods, the recording method with two native cases, and 12 window-policy methods. The policy suite verifies eight real screenshot fixtures: page, launcher, recording preview, recording notice, screenshot notice, permission notice, tooltip and pin. The recording cases verify source discovery, region pixels beneath excluded controls and MP4 export, including a 32-point-high elevated popup. The modal case dispatches native mouse/key events within an AppKit modal session and confirms the source dialog stays open.

The initial coverage command took 397.52 seconds including build, discovery and execution. It was interrupted after a new fixture blocked in the system file-dialog service; the recording cases also hit the encoder's directory-entry limit because the old fixture used the shared temporary directory. Fixtures now avoid initializing file selectors inside SwiftPM and use a private recording directory. The two-suite retry took 87.98 seconds: recording passed, but a nested AppKit event loop ended the SwiftPM helper before the policy suite finished, despite exit status zero. The fixture now dispatches events within the session without running another application loop. The final policy command took 79.78 seconds and reported all 12 methods complete. Passing scopes were not rerun.

Changed executable production-line coverage is **22/22 (100%)**. This uses the union of `llvm-cov` line hits from the successful native recording scope and final policy scope, intersected with added/replacement lines in the production diff. Production sources were identical between those builds; profiles were exported separately to avoid combining changed test-function counters. This is changed-line coverage, not project-wide coverage.

Strict SwiftLint passed for all ten changed production files with the repository baseline, and `git diff --check` passed. The optional whole-file SwiftFormat check did not pass on the touched files (compact function bodies, Swift Testing naming and wrapping); formatting was kept consistent with the surrounding code.

Self-review covered source selection through capture/output, invalid window IDs and dimensions, modal source lifetime, panel cleanup, shared tooltip ownership, and automatic-context exclusions. It also corrected the stale snapshot-window comment. Tests use synthetic native windows; every live business dialog and the macOS 13 fallback were not manually exercised.
