Self-review before delivery

- Complete chain: image-ocr evidence from the persistent lexical query reaches the existing shared renderer. Only current-version textual image evidence requests Vision location. The helper composites actual substring boxes into its oriented output raster; the existing preview view scales both together. Visual-only results remain ordinary images; an unlocated textual hit has a localized fallback. No indexing recipe, migration or vector provenance changed.
- Boundaries/failures: existing preview request/pixel budgets remain in place; OCR output uses existing line/text bounds and a maximum of 64 matched regions. Empty, mismatching and ambiguous repeated text returns no location. Vision geometry is validated for finite, positive, normalized bounds before composition and again at the IPC boundary. Recognition errors return unlocated image pixels within the existing deadline. Native PDF selection/highlighting code remains intact; scanned-PDF geometry is deferred.
- Resources/concurrency: OCR and original-format parsing stay in the disposable helper. The host only constructs fixed RGBA images. Child work is synchronously owned, cancelled and collected through the existing MediaWorker lease; detached renderer work is awaited and its cancellation token reaches the worker. Load/cache generations and permission epochs reject old responses. Same-size/same-mtime replacements now invalidate cache through inode/ctime identity. Generated content is rechecked after rendering. No networking or text-derived file/path execution was added.
- Security/ownership: original images are copied only if the worker's metadata version matches the source descriptor. Versioned copies reject final-component symlinks and compare descriptor/path identity again after copying. Publication still passes the existing launcher visibility/account/selection authorization. Revocation removes located pixels and stale callbacks cannot restore them.
- Consistency: all five existing localizations include the fallback. Documentation distinguishes native production-view snapshots from full launcher-controller/keyboard acceptance, and deterministic vectors from real embedding evaluation. Existing Office/PDF/index evidence is reused only as matching baseline context, not relabeled as new measurements.

Issues found and repaired during implementation review: old highlighted pixels could remain under a newly selected header; old size/mtime-only cache keys could reuse a same-size replacement; metadata could change between its read and snapshot/render completion; repeated passages could identify an arbitrary occurrence. The implementation now clears located pixels, keys and validates the stronger identity, rechecks metadata before publishing, and falls back on repeated passages.

Validation results and any repaired failures are recorded in README.md and validation-summary.json. Lint is compared against the same base instead of silently rewriting unrelated code or the repository baseline.
