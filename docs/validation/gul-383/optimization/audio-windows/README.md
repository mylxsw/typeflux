Audio overlap and durable silence progress — GUL-405 slice 13

Base: accepted PR633 merge `46b60c0031582f182a417460dbdf8811fb78a1d1`. This slice changes standalone audio only. Video audio retains its existing extraction recipe; image/PDF/video vectors are not rebuilt by this migration. Remaining GUL-405 work stays in progress, and GUL-406 remains parked.

The disposable filesystem worker decodes private descriptor-checked snapshots into bounded 16 kHz mono Float32 PCM. Audio windows last at most 30 seconds and start every 25 seconds. Timestamps derive from integer sample positions. A shortened final window is emitted only when it includes samples beyond the preceding window, so exact 30/55-second endings do not produce overlap-only duplicate tails. Output filenames use the stable window start sample. EOF resumes produce no additional segment.

Silence detection skips a window only when every finite sample has absolute amplitude at most `1e-7` (approximately -140 dBFS peak). Nonfinite data is not silently discarded. This deliberately conservative rule is not speech detection: low-level noise may still be encoded. A `1e-5` amplitude fixture is retained. The boundary fixture has active samples on both sides of 30 seconds, and the second window retains the whole event. These are PCM-content and fixed-vector tests, not evidence of real-model semantic quality or transcription.

Private media jobs now persist both the next window start and covered endpoint, independent of encoded segment count. Non-silent window vectors and progress commit in the same transaction. Silent windows advance progress without consuming a segment ordinal or invoking the encoder. An all-silent file can finish as a done job with fixed reason `audio-silent` and zero vectors. Version/recipe changes replace the private generation, and stale-generation progress cannot update the replacement. Existing cancellation, snapshot permissions, metadata revalidation, final publication, pressure budgeting, and document-first scheduling remain in the production path.

The audio recipe includes the model/projector hashes, existing embedding prompt, PCM/window/silence version.
