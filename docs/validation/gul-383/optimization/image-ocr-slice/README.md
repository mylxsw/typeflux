# GUL-405 screenshot OCR slice

Base: merged PR620 main `3675c7309744523b10d5d4c651726f4d319d5c31`. PNG/JPG/JPEG screenshots now supplement the existing image visual segment with local Vision text. OCR runs inside the disposable filesystem worker on the existing descriptor-checked private media snapshot. The worker never follows paths or links depicted in the screenshot. Other image formats retain their existing visual extraction behavior.

The OCR raster is oriented by ImageIO and bounded to 4096 pixels on its longest side. Recognition reuses the PDF's accurate English/Simplified Chinese/Traditional Chinese Vision configuration without language correction. All returned lines are consumed, without the clipboard's fixed line/text cap. The existing UTF-8 32 KiB overlapping batches bound IPC; 1200-byte overlapping chunks retain logical byte offsets and `image-ocr` source. Vision's returned line order is used; this does not reconstruct columns, guarantee arbitrary-font recognition, preserve tiny text in very tall screenshots, or implement geometric highlighting.

Text uses the existing text encoder and lexical index; the original image retains its visual provenance and modality. Staged text batches and visual segments remain private until the final file-version/permission/cancellation checks and atomic publication. Recovery replays recognition of the bounded raster, matches committed private text/offset batches, and skips compatible encoding. The source snapshot survives cancellation. This is not tiled OCR or a persistent Vision observation cache.

The new image job recipe queues prior PNG/JPEG visual results after completed discovery, including legacy files without job rows. Exact same-version/model/projector visual vectors are adopted without inference. Successful unchanged images skip all extraction/encoding. Blank OCR retains the visual and records `image-no-text`; OCR failure retains a visual result with `image-ocr-failed` and permits a targeted retry. Corrupt visual input retains the existing `media-extraction-failed` reason. Permission withdrawal or version replacement clears unavailable content; cancellation cannot publish.

Focused scope: `make coverage SUITE='SemanticImageOCRTests SemanticMediaIndexTests SemanticSearchSnippetTests'`. The new suite covers real reader-process PNG/JPEG OCR through persistent lexical search, hit source/chunk/offset, reopen/reuse, cancellation and visual recipe upgrade, fixed OCR failure and retry, blank/corrupt input, post-recognition replacement/permission withdrawal, staged text generation guards and long bounded output. Existing media indexing checks cover scheduling, staged visual recovery and affected audio/video callers; snippet checks cover shared evidence formatting. Vectors are deterministic fixtures, not real-model quality evidence. The new screenshots are synthetic and contain no personal information.

Prior Office/PDF evidence was not rerun or relabeled. No Release latency, native UI input latency, resource soak or long-term stability claim is made.
