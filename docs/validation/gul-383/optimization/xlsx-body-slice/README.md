# GUL-405: local XLSX worksheet body slice

Based on main `c056cfece5d6b55a1644aec51cc8840524809ed2`, including merged PRs #595, #598, #601, #605, #607 and #610. This seventh partial slice adds XLSX worksheet values to the existing disposable file reader and persistent indexing jobs. GUL-405 remains in progress; GUL-406 remains parked.

The reader follows `xl/workbook.xml` sheet-list order and resolves each relationship through `xl/_rels/workbook.xml.rels`. Sheet IDs, member filenames, ZIP order and relationship declaration order do not determine worksheet ordinals. Tests deliberately put `sheet2.xml` before `sheet10.xml` while ZIP lexical order and relationship declarations put them in the opposite order. Package-relative and package-absolute targets select archive data only. Nothing is unpacked or opened as a URL. External relationships are ignored; a referenced external/missing sheet or shared-string part fails instead of loading it. Duplicate relationship IDs fail deterministically.

Supported values are shared strings (including rich runs), inline strings, and stored cell values, including cached formula results, numeric values, booleans, error text and string/date caches. Formula instructions never enter the extracted body and are never evaluated. Empty style-only cells and formulas without caches contribute no body label or computed value; cached results may be stale. Number/date styles, locale formatting, the Excel date epoch, calculated values, merged-cell expansion, visual layout, charts, objects, macros and external content are outside this subset. Transitional and Strict SpreadsheetML namespaces are recognized. Only XLSX is admitted; XLSM/XLSB/legacy XLS and OLE-encrypted Office containers remain unsupported. A workbook containing an unsupported non-worksheet sheet relationship currently fails rather than silently dropping that sheet.

Each cell begins with a logical label `[worksheet-ordinal:sheet-name!cell-reference]`, followed by its value and a newline. Missing coordinates are marked `?`, never invented. The existing optional ordinal column carries the true one-based sheet-list position, with `xlsx-sheet` identifying its meaning. Both result entries display “Sheet N” rather than “Page N”. Names and coordinates remain body text, not separately structured navigation fields; long-cell tail snippets may lack the leading name/coordinate label, but retain the worksheet ordinal and logical UTF-8 offsets. File versions use the existing held-descriptor identity. No native Excel navigation or exact cell selection is claimed.

Batches retain the scalar-safe 32 KiB body limit and overlap cursor. The durable cursor uses zero-based worksheet plus logical byte offset, supporting both long-cell and cross-sheet restarts without reencoding committed vectors. The [shared-string repair](shared-string-repair/README.md) replaces per-reference parser suspension with groups of at most 128 cell descriptors. Each group measures its referenced shared strings in one sequential table scan, then captures only value windows intersecting the current response. Inline/cache values use the same bounded windows. Full cell values and workbook-sized tables are never retained. Foundation parsers run sequentially, outside each other's callbacks. ZIP metadata, relationships, and worksheet/string-table prefixes are still replayed by group and request; this is not a persistent index or a claim of linear full-workbook extraction. The group size is a memory/work unit, not a row, file or total-content limit. Late XML/CRC failures can follow earlier partial batches; integrity is checked as members are consumed, not by a separate whole-package validation pass.

ZIP encryption, ZIP64, DTD/entity declarations, malformed XML, missing string references and archive damage retain existing fixed reasons and explicit retry/version-repair behavior. Descriptor and namespace checks, scope/ownership, cancellation and post-read file-version/permission revalidation continue to gate publication. Extension-aware discovery revisits already scanned directories for XLSX while preserving compatible vectors. Diagnostics include the new recipe; no model space, persistent index, dependency or schema is added.

Format references: [Microsoft: worksheets](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-sheets), [Microsoft: shared strings](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-the-shared-string-table), [Microsoft: retrieving cell values](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/how-to-retrieve-the-values-of-cells-in-a-spreadsheet).

## Self-review and remaining scope

Self-review traces descriptor → workbook relationships → worksheet/shared strings → bounded scalar-safe body → persistent worksheet/offset cursor → committed vector reuse → body-hit evidence. It fixed Foundation parser reentrancy and empty-cell vector pollution. It checks cache-vs-formula semantics, explicit source labels, strict namespaces, archive-only target normalization, no external/embedded execution, parser/zlib/descriptor/child lifetime, cancellations and post-read authority/version checks. UI text is localized in all five shipped languages. Existing generic pending-detail cursor progress is unchanged.
