## Implementation and measurement boundaries

- Index/query terms share Unicode compatibility and case normalization. Latin accents fold; Japanese voicing remains significant. CJK pretokenization stays enabled. AND coverage, exact identifiers/quoted phrases, BM25 tie ordering and optional modality hints precede file-level TopK.
- Raw normalized cosine controls rejection: floor 0.45, strong absolute score 0.675, or a distinct-file gap of 0.04. Complete lexical evidence remains answerable. Repeated chunks from one file cannot become the runner-up. A single-vector index uses the absolute fallback, with no distribution-based rejection.
- Candidate ordering calibrates text script/media distributions using per-file maxima, four shared prior observations and a 0.02 standard-deviation floor. An audio ordering offset of 0.025 was selected on development queries. The transform never relaxes rejection. A single-class corpus retains raw cosine. Ranking occurs after calibration, so a raw-score truncation cannot remove calibrated winners.
- Each channel owns a WAL reader. The vector reader caches immutable 256-row Float16 pages, invalidated by committed insert/update/delete/file revisions. Float32 remains the compatible persistent format. Accelerate scores one page at a time; a query retains four bytes per row for calibrated selection. Current permissions and identity are checked again before publication.
- Metadata validation has one 80 ms warm or 3 s startup budget across the entire candidate batch. A new interactive validation preempts a stalled root prewarm. Budget-limited results are withheld and marked degraded.
- The native helper submits up to eight sequences in one encoder batch, bounded by 2,048 tokens, preserving request order across splits. Query and indexing helpers stay separate. Extraction prefetch was measured and rejected because it did not improve throughput. Validated mixed-entry body hits also bypass the filename coalescing grace once apps are ready; filename/default-Return rules remain unchanged.

## Quality protocol

`raw-quality-vectors.json` retains the original fixed 200-query oracle and 75 real text embeddings. The 50 absent scan/media-timestamp labels remain failures in production replay, rather than disappearing from its denominator. `captured-media.json` adds 25 generated speech sources, two image sources and 106 development queries.

The first even/odd topic split was unsuitable: it also split translation direction. `calibration-initial.json` preserves that failure. The first new-wording evaluation exposed no-answer failures; `production-holdout-initial.json` is retained. Audio calibration then used the development corpus, but originally failed to evaluate the text queries with media present. The independent 100-source/200-query evaluation consequently reached only 13/25 cross-language recall. `production-final-holdout-initial.json` preserves every failed row. It is now a regression set, not a blind result.

`compare_mixed_calibration.py` and `compare_variance.py` compare global RRF, coverage fusion, class rank fusion, mean calibration and variance calibration on all 256 supported development queries against the complete 102-source mixed corpus. The scripts do not open either later holdout file. Their Python lexical approximation is a sensitivity comparison, not the authoritative production evaluator. `variance-development-trials.json` records all trials and the selected parameters.

After the first independent evaluation failed, `capture_unseen_queries.py` froze 200 new query wordings against the fixed 100-source corpus and captured fresh model vectors. Capture finished while development-only corrections were still being compared; no retrieval result for these new queries was inspected until variance calibration and its 0.025 audio offset were selected from development data. `unseen-query-labels.json` and `unseen-query-vectors.json` retain those inputs. This is a query holdout on shared source facts, not an independent real-world corpus or a new topic holdout. The capture-time scope string refers to the initial script/modality centering implementation; final variance calibration was selected later on development data. No parameter was selected from its results. `production-unseen-query.json` is the first production result for that query set. Each of eight groups has 25 queries; answerable Recall@5 is 92–100%, cross-language is 25/25, and no-answer false positives are 1/25 (4%).

`SemanticRankingComparisonTests` runs the identical replay harness against baseline and current Swift stores. These replays exercise persistence/provenance, retrieval, quantization and ranking. They do not measure extraction, permission checks, model execution or UI latency. Each media fixture has one labelled segment at zero; segment-offset behavior also has dedicated production tests.

## Batch and prefetch experiment

`batch-prefetch.json` retains the valid raw samples: 100 warm samples per batch size/implementation and 100 per extraction strategy. For batch sizes 1/2/4/8, median helper milliseconds were 32.06/64.12/128.93/267.94 before and 32.37/63.73/122.03/243.51 after. The eight-sequence gain is about 9%; maximum component error was 0.0000972, with request order preserved. A mixed 16-sequence split is covered separately.

Serial bounded 32 KiB extraction plus inference had median 115.67 ms; one-item prefetch had 117.97 ms. Reading cost about 0.47 ms. Prefetch was therefore not adopted. The first attempt omitted filesystem request fields; the second did not handle startup protocol frames. Those attempts failed before a complete result checkpoint and are not counted as valid measurements.

## Reproduction

Build the pinned helper as documented in `docs/design/semantic-file-search.md`, then use the checked-in capture/comparison scripts with explicit helper/model paths. Capture requires the optional pinned media projector; no test downloads weights automatically.

For the focused product coverage pass, use `make coverage SUITE="SemanticSearchRankingTests SemanticScoreCalibrationTests SemanticCalibratedEvaluationTests SemanticFileServiceTests SemanticRealtimeSearchTests SemanticHybridSearchTests SemanticLexicalSearchTests SemanticFileValidatorTests SemanticFilePolicyTests SemanticFileStoreTests SemanticFileContentTests SemanticFileIndexerTests SemanticIndexRecoveryTests SemanticIndexFairnessTests SemanticIndexPruneTests SemanticMediaIndexTests SemanticMediaServiceTests"`. Set `TYPEFLUX_SEMANTIC_TEST_MODEL` and `TYPEFLUX_SEMANTIC_HOLDOUT_MODEL` to the pinned model for optional real-model cases. The recorded run used SwiftPM's native backend in an isolated coverage scratch directory because the default SwiftBuild backend did not emit the required test coverage map; build/runner details are retained in run JSON.

For the Release comparison, copy the benchmark test harness and generated fixture inputs/scripts into a detached baseline checkout, retaining its production source and old helper. Run `run_scale_matrix.py --checkout <checkout> --label before|after --mode build`, then `--mode ranking`, followed by `--mode native` and `--mode contention` at each `--size 10000|100000|1000000`. Optional `--asr <installed-assets>` and `--speech <synthetic.wav>` enable actual SenseVoice contention. Run each command in the foreground, sequentially on the same desktop. Compiler work is excluded from timed native rows; total command time remains in `run-*.json`.

The scale fixture is deliberately controlled: two files, one real winning passage vector and repeated orthogonal synthetic noise. Query vectors, native composer edits, service scheduling, filesystem validation and real background document batches use production code and pinned models. It is a chunk-scale latency stress test, not million-file quality evidence. The fixture explicitly selects supported=true, low-power=false, thermal-constrained=false and an allowed temporary-root scope; it still uses the production metadata child for current identity/permission checks. Policy/preemption/revocation behavior is covered separately rather than inferred from these timings. Native drawing forces layout/display and verifies the rendered accessibility tree; it is not a compositor presentation fence. Cold resets the service/helper ten times per entry; OS and shader caches can remain warm. Semantic-cache round zero populates the cache; later rounds measure reuse.

The filename provider deliberately returns no hits, so the observed handbook row must come from body retrieval. Surrounding conversation/app dependencies come from the existing `AskTestFixture`; these measurements do not cover startup of a user's complete filename/app indexes or physical event delivery through the desktop. The real model, content service, sessions, metadata worker and composer are exercised within that controlled boundary.

## Rollback

The experimental setting remains off by default. Disable content search or revert this change to restore the previous implementation. The additive search recipe/page/script metadata does not alter compatible persistent Float32 vectors. Older writers retain schema/vector compatibility, and fallback triggers maintain script metadata. If content search indexes files under both the old and new normalizers during rollback/re-upgrade, use the existing Rebuild action to align lexical terms; the recipe marker is not an old-writer detector. Removing the index uses the existing clear action; source files and filename search are unaffected.

## Self review and retained findings
