GUL-438 implements the existing files tool through descriptor-relative operations.

Threat model and limits:

- Roots are captured from the host's current grants, opened without following user links, and pinned for each operation. Only OS-owned /tmp, /var, /etc aliases are normalized. Ordinary user folders do not inherit private workspace permission restrictions.
- Reads carry a metadata-stamp version independent of content size. Authenticated, versioned base64url JSON continuations expire on host restart. They contain resume state but never authorize a root. Every resume opens under current grants and validates the stamp and root identity. Strict scalar decoding validates consumed data only.
- Read I/O buffers are at most 64 KiB; legacy offset scans use at most 4 MiB per request. Output reserves space for numbered lines and metadata within 60,000 UTF-8 bytes. A partial line keeps its line number and advances by scalar-aligned byte position. CRLF bytes remain intact, including across requests.
- Search walks lazily with 5,000 entries, depth 16, 32 MiB actual aggregate I/O (including oversize probes), 2,000,000 bytes per file, 200 matches and 60,000 output bytes. Only one eligible file buffer is materialized at a time for Foundation Unicode literal case-insensitive matching. Matching files are revalidated before aggregate publication. Skips and exhausted budgets produce an explicitly partial result.
- Existing-file mutations require expected_version. Snapshot reads and precommit digest verification are bounded to 16 MiB. Typeflux serializes writers (including aliases) process-wide. Preparation, revalidation and descriptor-relative commit run inside NSFileCoordinator's writer accessor. Staging uses unique O_EXCL/O_NOFOLLOW files in the pinned parent, preserves ordinary permission bits, and cleans up on failure. New files use renameatx_np(RENAME_EXCL).
- This is not a universal filesystem compare-and-swap. NSFileCoordinator and Typeflux serialization prevent lost updates among cooperating writers, and deterministic observed replacement/content changes are rejected. An arbitrary uncooperative same-user process with write access can still write between the final check and rename; it can also modify Typeflux itself. No rollback is attempted that could overwrite such a third-party change.
- Both AskLocalTools dispatch paths retain/cancel/await their detached worker. Cancellation before commit cleans staging and leaves the destination unchanged. Successful commit receipts are retained even when cancellation arrives after commit.

Self-review covered entry-to-receipt behavior, malformed/overflowing inputs and cursor state, consumed-only encoding checks, output/scan/traversal limits, descriptor ownership, staging cleanup, mutation serialization, authorization/revocation, identity re-walks, and approval/recovery compatibility. Review found and corrected premature search-match publication before revalidation, CRLF line matching through Swift grapheme iteration, the second uncancelled approved dispatch path, and staging-name substitution before commit.

Validation scope: AskBoundedFileToolsTests / AskFileToolsTests exercise file boundaries and compatibility; AskFileDispatchTests / AskLocalApprovalTests exercise actual host dispatch, cancellation, grants and approvals; AskSecureDirectoryTests / AskProjectWorkspaceTests cover reused descriptor dependencies; AskRecoverySafetyTests covers recovery policy. Only focused tests are executed; no UI/full-suite execution or CI waiting.
