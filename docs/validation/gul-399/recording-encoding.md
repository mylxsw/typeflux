## Contract and ownership

- Separate `--recording-export` entry and `MediaRecordingExport` protocol: one ≤1 KiB request, UUID/version/format/finite trim validation, fixed `input.mov` and `output.mp4`/`output.gif`. The disposable extraction and persistent playback contracts remain unchanged.
- Two host admissions before detached work, at most one active encoder per source session, and a dedicated two-child `MediaWorker.recordingExport` domain. Its parent deadline is 600 s; the helper's independent alarm is 605 s. This is an absolute job deadline, not a playback or idle timeout. Shutdown uses the existing bounded two-second retirement wait. Slow/uncooperative host filesystem calls are outside the child deadline and retain admission.
- Local/resident/regular/final-nonsymlink source ≤8 GiB, path ≤4 KiB, original device/inode/size/mtime/ctime checks before/after the 64 KiB streamed copy and before accepting output. Private 0700 attempt directory, 0600 input/request; validated candidate chmod 0600. AV external references are forbidden. Source metadata checks are snapshots, not an immutable filesystem transaction.
- Child validates positive finite duration ≤24 hours; one video track; natural and transformed dimensions ≤8192 axes/16,777,216 pixels; bounded finite transform; fps 0…240; ≤10 million estimated trimmed frames (240 fps budget when nominal fps is unknown). Up to eight audio tracks, eight format descriptions per track, 1…64 channels and finite sample rate ≤384 kHz. Native framework metadata loading itself remains inside the child boundary.
- MP4 retains highest-quality composition, preferred transform, every overlapping audio track, and gain 0.5 per track when multiple source audio tracks exist. The encoder's 8 GiB file-length limit is followed by native output-duration validation (≤0.05 s discrepancy), so a shortened native result is not silently published as the requested trim. Output retains one video track. Low-frame-rate/unsupported files may fail closed; this is recording-file export, not a universal transcoder.
- GIF retains trimmed duration ≤30.01 s, `ceil(duration*10)` frames, 10 fps, maximum 960×960, loop 0, and original delay rules. The original edge can yield **301** frames; the poster reader's bound now accepts 301 and rejects 302. Sequential autorelease pools bound host-visible frame retention; at most 301×960×960 generated pixels. GIF output cap is 50,000,000 bytes.
- Child `RLIMIT_FSIZE` enforces the selected per-file output ceiling before native encoding; SIGXFSZ becomes write failure. It does not bound aggregate native scratch files, AV/ImageIO internal allocation, GPU, other processes, or all system memory. No large-file native export or resource-limit expiration was exercised.
- Progress has one native monitor, at most one event per second, no per-callback tasks. ≤604 sequential ≤1 KiB JSON events, ≤256 KiB total stdout, ≤1 KiB stderr. Parent incrementally consumes the bounded cumulative stream, rejects regressing/nonfinite progress, wrong identity/sequence, extra terminal messages and trailing bytes. There is no progress queue or control/producer replay.
- Parent accepts only acknowledged success, no-follow regular single-link fixed output, exact bounded length and PNG-independent GIF/MP4 signature. It does not reparse the original natively. A pinned session directory and one exclusive rename transfer the validated candidate; user-destination publication still goes through `preparePublication` and the original immediate authorization check. Signatures and a trusted helper's metadata are not a proof against arbitrary malicious native code.
- Failed, cancelled, or unacknowledged attempts preserve the original and all remaining attempt files, including partial output and request UUID. Generic temporary-directory cleanup is enabled only after known validated transfer. No automatic retry, rollback, recapture, re-record, or publication is performed. Native frameworks may internally remove their own failed temporary files; only remaining files can be retained.
- Up to four retained `.encoding-UUID` attempts per session, with a bounded 1024-entry scan. Each failed attempt can retain 8 GiB input plus 8 GiB MP4 output: up to 64 GiB per session, in addition to originals, other recording copies and native scratch. There is no global retained-recording eviction quota or recovery browser in this increment.
- Admission and source-session ownership remain held through **both host completion and actual child collection**. Explicit discard is deferred until that ownership ends, with a matching ownership UUID and directory identity. The deferred action uses the canonical directory checked at request time, not a subsequently retargeted alias. Current authority/session/generation checks in the coordinator still fence publication and copy. Filesystem calls/rename/discard are not atomic against another unsandboxed process or power loss.
- Five-language unconfirmed-export notice preserves truthful failure. No layout change or screenshot. DI/quit fence the new pool; capture, playback, timeline, poster and existing publication behavior are otherwise retained.
