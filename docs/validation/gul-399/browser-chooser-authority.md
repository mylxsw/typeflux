# Browser chooser accepted native branches

The default browser favicon chooser now binds both native branches when its small Context model accepts the request, before pixel reservation and the child Task. Favicon preparation uses its cache's worker; the application/file fallback uses its own worker. Each retains its original authorization through its continuations. A retired outer request cannot join a newer native pending request.

The chooser records which branch returned its pixels and checks that branch before Context publication. A completed favicon cache hit and custom decoder remain independent of native availability, including an unavailable unused fallback. Existing cache hits, sharing, negative cooldown, origin-only policy and bounded native execution remain in place. Health changes do not clear failure identities, retry downloads or replay producers.

Cache preparation performs the existing memory-only source binding at acceptance. That binding may retire older scoped cache clients, as the previous image-entry binding did. It starts no Task, loader, native work or capacity reservation, and performs no filesystem validation. Context rechecks its original attempt after these synchronous source callbacks. The receipt also retains the cache generation, preventing a canceled cache's old chooser from entering its fallback. Actual pending work remains collected at its real return.

The optional concrete native Environment override distinguishes the production default from independent custom/actor decoders while preserving the public decoder getter/setter. View and task identities remain source/access based, without health availability. Explicit reopen follows the existing Context failed-identity dedupe and favicon 60-second cooldown.

## Limits

Tests use the actual small Context model and the same production chooser/cache preparation with private fake loaders, synthetic success JSON and bounded raw RGBA. Body checks construct values only; hosted SwiftUI task launch, Environment installation, settings-notification delivery and rendering are not proved. No actual HTTP, native icon resolution, NSWorkspace/QuickLook, codec/encoder/helper/Vision, clipboard (including named), SystemClipboardContentActions, ConversationModel/AskTestFixture, Downloads/home/apps, windows, capture/audio/TCC, provider/paid work, signing/hardware or unrelated document/resource tests run.

This binds existing native availability; it does not grant source/account/copy/export consent. Existing source callbacks and actual pixel/native/FD/private-copy/child-host collection remain. It does not establish a filesystem/settings/account permission transaction, arbitrary Published/Combine/AppKit/custom clock reentrancy, every UI epoch, or host crash/OOM/power-loss containment. Entered effects cannot be rolled back. Synchronous launcher immediate-lookup callback ownership and artifact card save-dialog error/export lifecycle remain separate.
