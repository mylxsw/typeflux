# Native icon accepted Context consumer authority

This increment binds the default native icon request when the small Context model accepts its source, before pixel reservation and its child task. Direct preparation uses its own preview worker; eligible launcher-cache preparation uses that cache’s worker. Shared pending/native work retains the original authorization. Custom decoders remain independent.

The cache receipt also retains the original global/file generations. A completed cache value needs no new native availability; clearing the relevant source generation retires its receipt. Binding never calls the synchronous system icon lookup. Existing immediate metadata lookup remains a separate lane.

The optional concrete Environment override preserves the public nonoptional decoder getter/setter and custom closure syntax. Explicit view decoders bypass the cache, while an environment override remains subordinate to an eligible cache, as before. Context’s explicit custom decoder takes precedence over concrete preparations. View/task identities still contain source, access epoch, icon generation and revision, without health availability. Failed identity deduplication and explicit reopen behavior remain intact.

## Boundaries

This covers the native icon view’s accepted small-model consumer. The browser favicon chooser’s earlier await/fallback boundary remains separate. Synchronous immediate/NSWorkspace source callbacks, actual SwiftUI hosting/task launch and arbitrary Published/Combine/AppKit reentrancy are not proved here. Native availability is not source/account/copy permission. Existing source callbacks, budgets, FD/private-copy/child-host collection and direct icon policy remain in force. Entered effects cannot be rolled back; this is not a filesystem/settings/account permission transaction or a host crash/OOM/power-loss guarantee.

Private protocol JSON, bounded raw RGBA, injected workers/readers/lookup and small models only. No actual native icon lookup, NSWorkspace, codec/encoder/helper/Vision, HTTP/provider/paid work, clipboard (including named), SystemClipboardContentActions, ConversationModel/AskTestFixture, Downloads/home/apps, windows/devices/capture/audio/TCC/signing or unrelated document/resource tests. Body checks construct values only; they do not host, render or launch a task. No owned presentation layout/ABI/entry/package change, so no screenshot or copied helper probe.
