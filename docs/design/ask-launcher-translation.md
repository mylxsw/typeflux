# 随便问：启动器翻译与快捷结果后续路线 设计方案

> 状态：设计稿，待确认后开发。前置：计算器（M1）已合入，见 `docs/design/ask-launcher-quick-results.md`。配套设计稿：`docs/design/ask-launcher-translation.html`，截图见 `docs/design/ask-launcher-translation/`。

## 0. 一页结论

1. **翻译做成快捷结果的第二个来源**，也是第一个异步来源。它会把原方案里的「来源协议 + 异步档」真正落地，后面的应用搜索、文档搜索直接复用。
2. **三个入口，按意图强弱区别对待**：
   - **选中即译**：在任意应用选中文字，按 ⌥Space，译文已经在启动器里。
   - **前缀翻译**：输入 `fy 你好`、`tr hello >ja`、`翻译成日语 你好`。
   - **自动识别**：直接输入一段外语，下方多一行轻量译文，但不抢回车。
3. **两个引擎，本机优先**：
   - **本机翻译**：macOS 自带的 Translation 框架，离线、免费、不出本机、几十毫秒出结果，作为默认。
   - **AI 翻译**：用户已配置的文本处理模型，或 Typeflux Cloud。用于本机不支持的语言对、macOS 13/14，以及用户主动要求「更地道」时。
4. **隐私铁律**：自动触发（选中即译、自动识别）**只用本机引擎**，绝不把选中的文字自动发到云端。只有用户明确操作（前缀翻译选了 AI、按 ⌘R 用 AI 重译）才走 AI。
5. **结果能直接用**：↩ 复制并关闭；⌥↩ 把译文写回原应用（选中即译时就是**原地替换**选中的文字）；⇥ 切换目标语言；⌘↩ 照旧问 AI。单个英文单词额外给出系统词典释义；可以朗读。
6. **路线调整**：T1 翻译（含快捷结果框架）→ M2 应用搜索 → M3 文档与历史对话 → M4 换算与语音。每个阶段一个 PR，各自可以单独验收。

## 1. 为什么值得做、怎么才算做好

「随便问」里已经有翻译的影子：起手建议「翻译我选中的文字」、选区菜单里的「翻译」、内置 Skill「翻译润色」。但它们都要**开一段 AI 对话**，等模型回复，结果在对话窗口里，用户还得自己复制回去。翻译是高频、短、确定性强的动作，值得更快的路径：

| 指标 | 现在（问 AI） | 目标 |
|------|-------------|------|
| 从选中到看到译文 | 打开启动器 → 选建议 → 等模型（数秒）→ 进对话窗口 | ⌥Space 立刻看到（本机引擎约 0.1 秒） |
| 用上译文 | 在对话里复制，再切回原应用粘贴 | ↩ 复制，或 ⌥↩ 直接替换原文 |
| 隐私 | 选中的文字发到模型 | 默认不出本机 |
| 离线 | 不可用 | 本机引擎可用 |

**不做**：整页 / 文档翻译、OCR 截图翻译（可作为后续，见 §9）、翻译历史记录、自建翻译服务。

## 2. 入口与触发规则

### 2.1 选中即译（最高频）

启动器打开前已经抓取了选中文字（`launcherDraft.selection`）。规则：

- 输入框为空、草稿里有选中文字（1–2000 字）时，起手建议上方出现**翻译卡片**，内容是选中文字的译文。
- 选中文字是外语（与主语言不同）时，卡片**默认高亮**，↩ 就是复制译文。是主语言时，卡片显示译成第二语言的结果，但不默认高亮，起手建议照旧排在第一。
- 一旦开始输入，卡片让位给输入内容对应的结果。
- 只用本机引擎。本机不可用时，卡片显示「用 AI 翻译（⌘R）」，用户确认才发送。

### 2.2 前缀翻译（明确意图）

| 写法 | 含义 |
|------|------|
| `fy 文本` / `tr 文本` / `翻译 文本` / `translate 文本` | 自动判断方向 |
| `fy>ja 文本` / `fy 文本 >ja` / `tr 文本 to french` | 指定目标语言 |
| `翻译成日语 文本` / `译成英文：文本` / `translate to Japanese: 文本` | 自然语言写法 |
| `/translate`（命令面板） | 同 `fy `，在面板里可选目标语言 |

- 语言可以写代码（`en ja ko fr de es ru pt it zh zh-tw`）、中文名（英文 / 英语 / 日语 / 日文 / 韩语 / 法语 / 德语 / 西班牙语 / 俄语 / 繁体 / 中文）或英文名（english / japanese …）。
- 前缀后面还没有内容时（`fy `），显示提示行「输入要翻译的内容 · ⇥ 选择语言」。
- 前缀是明确意图，引擎按设置走（默认自动：本机优先，不支持时用 AI）。

### 2.3 自动识别（低打扰）

- 输入既不是算式也没有前缀，长度合适（≥ 2 个词或 ≥ 4 个汉字，≤ 500 字），并且 `NLLanguageRecognizer` 判定为非主语言（置信度 ≥ 0.8）时，在「问 AI」行**下方**增加一行紧凑的「译：…」。
- **默认高亮仍是「问 AI」**，↩ 照旧发问；需要译文时按 ↓ 再 ↩，或者 ⌥↩ 直接写回原应用。
- 只用本机引擎，防抖 250 ms。本机不可用时这一行不出现。
- 设置里可以关闭。

### 2.4 方向判断

- **主语言**：默认等于界面语言（`AppLocalization`）；**第二语言**：默认英语，主语言是英语时默认简体中文。两者都可以在设置里改。
- 源语言用 `NLLanguageRecognizer` 检测，`languageHints` 偏向主语言和第二语言，让短文本更准；简体和繁体分开处理。
- 源语言是主语言时译成第二语言，否则译成主语言；显式指定的目标优先。
- ⇥ 在目标语言之间轮换：主语言 → 第二语言 → 最近用过的 3 种。卡片上的语言标签也可以点开菜单选择。

## 3. 引擎

```swift
protocol AskTranslationEngine: Sendable {
    var kind: AskTranslationEngineKind { get }            // .onDevice / .ai
    func availability(from: Locale.Language?, to: Locale.Language) async -> AskTranslationAvailability
    func translate(_ text: String, from: Locale.Language?, to: Locale.Language) -> AsyncThrowingStream<String, Error>
}
```

### 3.1 本机翻译（Apple Translation）

- **macOS 26+**：直接 `TranslationSession(installedSource:target:)`，在模型层调用，不依赖视图。
- **macOS 15–25**：系统只允许通过 SwiftUI 的 `.translationTask(configuration)` 拿到 session。做一个不可见的桥接视图 `AskTranslationHost`，挂在启动器卡片上，把请求排队交给它。
- **macOS 13–14**：没有这个框架，只用 AI 引擎；选中即译和自动识别在这些系统上不出现。
- 先用 `LanguageAvailability().status(from:to:)` 判断：
  - `.installed`：直接翻译。
  - `.supported`：语言包未下载。卡片显示「下载 日语 离线翻译（约 xx MB）」，点了调用 `prepareTranslation()` 弹出系统下载框；下载前按 §3.3 处理。
  - `.unsupported`：交给 AI 引擎。
- 会话按语言对缓存复用；启动器关闭时释放。

### 3.2 AI 翻译

- 用「设置 → 模型」里的**文本处理模型**（语音改写用的同一个，经 `LLMRouter`，可以是 Typeflux Cloud 或用户自己的模型）。它本来就是为短文本一次性处理配置的，不用开对话。
- `PromptCatalog` 新增翻译提示词：只输出译文；保留格式、换行、代码、链接、数字和专有名词；目标语言明确；源语言已经是目标语言时原样返回。
- 支持流式时边出边显示，否则整段返回；15 秒超时；每次按键取消上一个请求。
- 文本处理模型未配置时，卡片显示「设置 AI 翻译模型」并跳到设置页。

### 3.3 选择策略

| 设置「翻译引擎」 | 选中即译 / 自动识别 | 前缀翻译 | ⌘R |
|------------------|---------------------|----------|-----|
| 自动（默认） | 本机；不可用则提示 ⌘R | 本机；不可用则 AI | AI |
| 仅本机 | 本机；不可用则提示 | 本机；不可用则提示 | 不可用 |
| AI 优先 | 本机（隐私铁律不变） | AI | AI |

卡片右上角始终标明当前结果来自「本机」还是「AI · 模型名」。

```
│ │ 并让语音输入在会议中更稳定。                            │   │
│ │                              ⧉ 复制  🔊 朗读  ↺ AI 重译 │   │
│ ╰────────────────────────────────────────────────────────╯   │

│   …（其余起手建议）                                            │
│        ↩ 复制译文 · ⌥↩ 替换原文 · ⇥ 换语言 · esc 关闭         │
╰──────────────────────────────────────────────────────────────╯
```

| 按键 | 行为 |
|------|------|
| ↩ | 复制译文并关闭 |
| ⌥↩ | 关闭启动器，把译文写回原应用：选中即译时**替换原选区**，其它情况在光标处插入。复用 `TextInjector.deliver(text:to:)` 和启动器记下的前台应用；写入失败时回退为复制，并给出提示 |
| ⇥ / ⇧⇥ | 下一个 / 上一个目标语言 |
| ⌘R | 用 AI 重新翻译（明确发送到模型） |
| ⌘↩ | 问 AI（把原文和「翻译」意图一起带过去，便于追问「为什么这么译」） |
| ↑ / ↓ | 在卡片、词典行、建议或「问 AI」行之间移动 |

补充：

- **单词释义**：源文本是单个拉丁字母单词时，卡片下面加 1–2 行系统词典释义（`DCSCopyTextDefinition`，离线），可以单独复制。
- **朗读**：`AVSpeechSynthesizer`，使用目标语言的系统嗓音。
- **长文本**：译文最多显示 6 行，超出可以滚动；面板高度有上限，不会顶出屏幕。
- **状态**：
  - 翻译中：保留上一次译文并变暗，加细进度条，不跳高度。
  - 出错：在卡片里说明原因（离线、模型未配置、超时），并给出可执行的下一步。
  - 源语言与目标语言相同：提示「已经是简体中文」，并给出 ⇥ 换语言。

## 5. 架构（同时落地快捷结果框架）

M1 里计算器是写死在 `AskQuickResults.resolve` 里的同步调用。翻译需要异步、可取消、跨按键的生命周期，所以按原设计 §5.2 把框架补齐：

| 组件 | 职责 |
|------|------|
| `AskQuickResultProvider` | 来源协议：`immediateResults(for:)`（同步）+ `results(for:) async`（异步） |
| `AskQuickResultsController`（`@MainActor ObservableObject`，由 `AskConversationModel` 持有） | 按文字和上下文（选中文字、目标应用）调度各来源；异步防抖、按 generation 丢弃过期结果、取消任务；合并排序；**只在结果真的变化时发布**（M1 的录音回归就是因为视图状态多余刷新） |
| `AskCalculatorProvider` | 现有计算器包装成来源，行为不变 |
| `AskTranslationProvider` | 解析前缀和目标语言、检测语言、选择引擎、产出翻译结果 |
| `AskLanguageDetector` | `NLLanguageRecognizer` 封装，可注入 |
| `AppleTranslationEngine` / `AITranslationEngine` | §3 的两个引擎 |
| `AskTranslationHost` | macOS 15–25 的 SwiftUI 桥接视图 |
| `AskQuickResultsView` | 按结果类型渲染：计算卡片、翻译卡片、通用条目行（应用、文档会用到） |
| `AskQuickActionPerformer` | 执行动作：复制、写回原应用、打开、朗读；注入剪贴板和 `TextInjector`，测试可替换 |

- `AskComposer` 里的 `quickResults` 状态和 `refreshQuickResults` 移到 controller，视图只订阅。现有的键盘通道（`onCommandKey` → `quickResultsKey`）保留，新增 ⌥↩、⇥ 轮换、⌘R。
- 启动器的选中文字、目标应用由 `prepareLauncher` 填好，作为查询上下文传给 controller。

## 7. 测试

- **解析**：前缀写法、语言名和代码、空内容、与算式和命令的冲突（`tr` 后面跟算式仍按翻译处理；`/translate` 走命令面板）。表驱动测试。
- **方向判断**：主 / 第二语言组合、显式目标、简繁体、短文本提示。检测器用假实现注入。
- **引擎选择与隐私**：用两个假引擎断言选中即译和自动识别**从不调用 AI 引擎**，前缀翻译和 ⌘R 按策略调用；本机返回 `.supported` 或 `.unsupported` 时的回退分支。
- **Controller**：防抖、过期结果丢弃、关闭启动器时取消、结果不变时不发布。
- **交互**（沿用 `AskQuickResultsInteractionTests` 的做法：真实启动器按键 + 私有剪贴板 + 假 `TextInjector`）：↩ 复制、⌥↩ 写回、⇥ 换语言、⌘R、⌘↩、esc。
- **截图**：`TYPEFLUX_ASK_SNAPSHOTS` 渲染选中即译、前缀翻译、自动识别、加载、出错几种状态。
- **真机冒烟**：在 Mac 上实际启动 app，选中 Safari 里的英文，按 ⌥Space、⌥↩ 验证原地替换（本机翻译需要真机和语言包，自动化测试只用假引擎）。
- 新代码覆盖率 ≥ 90%。

## 8. 路线（更新后）

| 阶段 | 内容 | 可验收的结果 |
|------|------|-------------|
| **T1 翻译**（下一步） | 快捷结果框架（异步档、controller、动作执行器）+ 翻译三个入口 + 两个引擎 + ⌥↩ 写回 + 词典释义 + 朗读 + 设置 | 选中外文按 ⌥Space 立刻看到译文，⌥↩ 原地替换 |
| **M2 应用搜索** | 应用索引（`/Applications` 等，监听安装 / 卸载）、中文名拼音全拼和首字母匹配、↩ 打开、⌘↩ 问 AI | `wx` 找到微信 |
| **M3 文档与历史** | `NSMetadataQuery` 文档搜索（用户目录，按最近使用排序）、历史对话检索（复用 `AskSearchPalette`）、↩ 打开、⌘R 在 Finder 中显示 | 输入文件名片段直接打开 |
| **M4 换算与语音** | 单位 / 日期换算（同步）、汇率（异步、可缓存、单独开关）；语音里的「一百二十乘以三」「把这句翻译成英文」转成算式和翻译前缀 | 说出来也能算、能译 |

每个阶段一个 PR，带测试、截图和设计文档更新。

## 9. 以后可以再加（不在本轮）

- 截图 / 屏幕文字翻译：启动器已经能附带截图，用 Vision 识别文字后走同一套翻译。
- 双语对照复制、术语表（与已有的词汇表打通）。
- 在对话窗口的选区菜单里，「翻译」也改用这套本机引擎做即时预览。

## 10. 需要确认

1. 第二语言默认英语（主语言是英语时默认简体中文），可以吗？
2. 自动识别外语默认开启（只用本机引擎、不默认高亮），还是默认关闭？我建议开启。
3. AI 翻译用「文本处理模型」（与语音改写相同），还是启动器当前选的对话模型？我建议前者：更快，而且不产生对话。
4. 前缀用 `fy` / `tr` / `翻译` / `translate`，还要别的吗？
5. 路线顺序：T1 翻译 → M2 应用 → M3 文档 / 历史 → M4 换算 / 语音，可以吗？
