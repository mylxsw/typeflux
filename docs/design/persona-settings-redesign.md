# 人设页改版 设计方案

> 状态：设计稿，待确认（GUL-340）。可交互设计稿：`docs/design/persona-settings-redesign.html`（顶部切换 6 个状态、深 / 浅色、窄窗口），截图见 `docs/design/persona-settings-redesign/`，改版前截图为 `before.png`。

## 0. 一页结论

1. **把「在哪里用」和「人设本身」分开**：顶部三张卡固定回答「现在在用哪个人设」——听写默认（fn）、辅助输入（⌥ fn）、应用专属（N 个应用）；下面的列表 + 详情只管理人设内容。
2. **应用专属规则不再藏在顶栏按钮里的弹窗**：顶部卡片直接显示规则数量和应用图标，「管理」打开右侧抽屉，在页面内增删改、暂停，不打断编辑。
3. **列表能一眼看出谁在被用**：每行不放头像，只有名称和「✓ 听写默认 / 辅助输入 / Slack 等 2 个应用」标签，不再显示定义摘要；未保存的人设标橙点。「我的人设」排在内置前面。
4. **详情区按身份区分**：内置人设只读展示定义，给「复制一份来修改」；我的人设名称直接在标题处改，只有有修改时才出现底部保存条（⌘S），没有修改时定义输入框占满详情区，切换人设前提示保存。
5. **用一个「设为…」菜单代替含义不清的「设为默认」按钮**：菜单里勾选听写默认 / 辅助输入，或「在某个应用里使用…」（直接带着这个人设打开添加应用）。
6. **「不使用人设」不再是列表里的一项**，只作为听写默认（和应用规则）的选项出现，标注「原样输出」。
7. **新建把空间留给定义**：只有名称和定义两项，定义输入框占满详情区；「起点」是定义标题行右侧的一个小菜单（空白 / 基于 Typeflux / 基于 English Translator / 复制我的人设），覆盖已输入的内容时可撤销；名称和定义都填好才能创建。
8. **删除讲清后果并可撤销**：删除正在使用的人设时，确认框列出「听写默认将改为 Typeflux」「Slack 的应用规则会一并删除」；删除后提示条可撤销。切换默认、删除规则也都能撤销。

## 1. 现状问题（用户视角）

| 问题 | 现在的表现 |
|------|-----------|
| 不知道「现在用的是哪个」 | 默认 / 辅助两个下拉夹在页面顶部，和列表、详情挤在一起；应用专属规则完全看不到，要点顶栏按钮进弹窗 |
| 不知道谁覆盖谁 | 辅助输入、应用专属、默认三者的优先级页面上没写 |
| 「设为默认」含义含糊 | 已是默认时按钮变绿但无法取消；看不出它和顶部「默认人设」下拉是一回事 |
| 列表信息噪音大 | 自定义人设的摘要直接是定义第一行（`# Role`、`ASR post-processing editor…`）；首字头像大量重复「候选」，不提供信息 |
| 内置人设编辑区像坏了 | 只读的大文本框 + 底部一行「内置人设不可编辑」，没有下一步 |
| 「不使用人设」混在人设列表里 | 它是一种使用选择，不是一个可编辑的人设 |
| 删除静默带走规则 | 删除人设会同时删掉应用规则、改掉默认人设，用户事先不知道 |

## 2. 页面布局

```
┌ 语音输入 ────────────────────────────────────────────────────────────┐
│ 概览  词库 128  历史  人设 9                                          │
│ ┌ 听写默认      fn ┐ ┌ 辅助输入    ⌥ fn ┐ ┌ 应用专属                  ┐ │
│ │ [∞ Typeflux    ⇅] │ │ [英 候选：英文… ⇅] │ │ S 邮 X C  3 个应用·1 暂停 管理›│ │
│ └──────────────────┘ └──────────────────┘ └───────────────────────────┘ │
│ 人设库 9      [+ 新建] ┌──────────────────────────────────────────────┐ │
│ [🔍 搜索名称或内容  ]   │ [∞] Typeflux 内置              [设为… ▾] [⋯] │ │
│ 我的人设 · 7            │     整理口述，保留原意                        │ │
│  英 候选：英文口语化表达 │ 使用于 ✓听写默认                              │ │
│     [辅助输入]          │ ──────────────────────────────────────────── │ │
│  职 职场助手 ●          │ 🔒 内置人设由 Typeflux 维护…  [复制一份来修改] │ │
│     [Slack]             │ 人设定义 · 发给模型的改写指令          519 字 │ │
│ 内置 · 2                │ ┌──────────────────────────────────────────┐ │ │
│  ∞ Typeflux [✓听写默认] │ │ …                                        │ │ │
│  E English Translator   │ └──────────────────────────────────────────┘ │ │
│                         │ ● 有未保存的修改   ⌘S 保存 [放弃修改] [保存]  │ │ ← 仅我的人设、有修改时
└─────────────────────────┴──────────────────────────────────────────────┘
```

- **顶部「生效方式」三张卡**：前两张是人设选择器（弹出菜单按「我的人设 / 内置」分组，显示一行摘要）；只有听写默认有「不使用人设（原样输出）」。快捷键徽标读取当前配置的快捷键，未设置时显示「未设置」并可点去快捷键设置。第三张显示规则数、应用图标堆叠和暂停状态，「管理 ›」打开抽屉。窄窗口（< 1000pt）时应用专属卡占满第二行并改为单行。
- **列表**：宽 300pt（窄窗口 250pt），分组「新建中 / 我的人设 · N / 内置 · N」。行：只有名称和使用标签，不放头像；不显示定义摘要（摘要多是提示词第一行，噪音大）。搜索同时匹配名称、摘要和定义，带清除按钮。右键菜单保留「复制为新人设 / 删除」。
- **详情头部**：名称（我的人设为可直接编辑的输入框）+ 内置徽标 + 一行副标题；右侧「设为…」菜单和「⋯」菜单（复制为新人设、删除…）。下面一行「使用于」标签，点应用标签打开抽屉；未被使用时显示「暂未使用 · 设为听写默认、辅助输入或绑定应用」。
- **详情正文**：内置人设：提示条 +「复制一份来修改」+ 只读定义（不再用禁用的输入框）。我的人设：可编辑定义 + 字数。保存条只在有修改时出现（不放提示文字）：「放弃修改」「保存」，⌘S 保存；名称或定义为空时保存不可用。
- **切换保护**：有未保存修改时点别的人设 / 新建 / 复制，弹「保存对『X』的修改？」→ 保存 / 不保存 / 取消。

## 3. 应用专属抽屉

- 右侧 520pt 抽屉，覆盖在页面上（遮罩点击或 esc 关闭）。
- 顶部总开关「启用应用专属规则」（对应现有 `personaAppBindingsEnabled`），关闭后规则整体变灰，顶部卡片显示「全部规则已暂停」。
- 每条规则：应用图标 + 名称 + Bundle ID、人设选择器（可选「不使用人设」；人设已被删除时红字「人设已不存在」）、启用开关、删除（可撤销）。
- 「添加应用」在抽屉内展开应用选择：已启动 / 全部、搜索名称或 Bundle ID，已有规则的应用置灰标「已有规则」；底部「找不到？」可直接输入 Bundle ID 或应用名称。新规则默认用听写默认人设；从详情「设为… → 在某个应用里使用…」进入时默认用当前人设。

## 4. 交互细节

| 操作 | 结果 |
|------|------|
| 改顶部卡片 / 「设为…」菜单 | 立即生效，提示条「听写默认已改为『X』」+ 撤销 |
| 「设为…」里再点已勾选的听写默认 | 改为「不使用人设」（可撤销） |
| 「设为…」里再点已勾选的辅助输入 | 不允许取消（辅助输入必须有人设），提示去上方换一个 |
| 新建 | 列表顶部出现「新建中」行，详情只有名称（自动聚焦）和占满剩余高度的定义；底部只有「取消 / 创建人设」 |
| 换起点 | 定义标题行右侧「起点：空白 ▾」菜单；选内置人设时预填其定义 +「补充要求」，选我的人设时复制其定义；覆盖已输入内容时提示条可撤销 |
| 复制（内置或我的） | 进入新建，名称为「X 副本」并选中，定义预填，起点显示来源人设 |
| 搜索无结果 | 「没有找到『词』」+「新建『词』」按钮（名称预填） |
| 删除 | 确认框列出连带影响 → 删除 → 提示条撤销 |
| esc | 关闭菜单 → 关闭抽屉 |

## 5. 实现计划（一个 PR）

| 范围 | 改动 | 测试 |
|------|------|------|
| 视图拆分 | `StudioPersonaLibraryView` 拆为 `StudioPersonaUsageStrip`（替换 `StudioPersonaUsageSettings`）、`StudioPersonaRosterView`、`StudioPersonaDetailView`、`StudioPersonaAppRulesDrawer`；`SettingsView` 顶栏去掉人设页的两个按钮，现有 `personaAppBindingsSheet` 内容迁到抽屉 | 渲染冒烟测试（内置 / 我的 / 新建 / 无结果 / 抽屉），深浅色截图附 PR |
| 视图模型 | `StudioViewModel+PersonaLibrary` 新增：`personaUsages(for:)`（默认 / 辅助 / 应用规则，含暂停状态）、`personaDeletionImpacts(for:)`、`beginCreatingPersona(template:)` / `applyPersonaDraftTemplate(_:)` / `duplicatePersona(_:)`、`selectPersonaGuardingDraft(_:)`、`toggleDefaultPersona(_:)` | 单元测试覆盖每个新方法的分支（使用标签组合、删除影响、起点预填与撤销、脏数据保护） |
| 撤销 | 默认 / 辅助切换、人设删除、规则删除提供一次撤销（快照恢复人设、默认、辅助和规则） | 删除后撤销恢复全部状态 |

数据模型不变（`PersonaProfile`、`PersonaAppBinding`、默认 / 辅助 ID 都沿用），不影响云同步。

## 6. 待确认

1. 「我的人设」排在内置前面可以吗？（理由：常改的是自己的人设；内置只有两个。）
2. 辅助输入保持「必须选一个人设」，还是也允许「不使用人设」？现在的逻辑是必须选，设计稿沿用。
3. 是否需要在详情里加「试一试」（说一段 / 粘一段文本，预览这个人设的改写效果）？会调用文本模型，设计稿没有放，建议作为后续单独需求。
