# 启动器关键字 & 工作流编辑器：UI 重构方案

> 状态：设计稿，等确认后实现（GUL-229）。配套可交互设计稿：`docs/design/launcher-keywords-workflow-editor.html`（`?solo=<id>` 只显示一屏，`?light=1` 浅色）。截图在 `docs/design/launcher-keywords-workflow-editor/`：`kw-list` `kw-edit` `kw-add` `ed-keywords` `ed-input` `ed-script` `ed-output` `ed-test` `ed-ai`，以及 `light-*`；改版前的截图是 `before-*.png`。
> 只改 UI 和交互，不改数据：`AskKeyword`、`settings.askLauncherKeywords`、`workflow.json`、运行器和信任规则都不变。

## 0. 一页结论

| | 现在的问题 | 方案 |
|---|---|---|
| 关键字页 | 三类关键字三种排版，所有字段都摊开在页面上；保存方式不统一；提示词被截断；工作流的关键字看不到 | **一张列表**：关键字 · 功能 · 做什么 · 开关；点一行打开**编辑对话框**；「添加关键字」先选功能 |
| 编辑器 · 标题 | 系统标题栏「工作流编辑器」+ 一条工具栏 + 分割线，标题和内容是两块 | 隐藏系统标题栏（`fullSizeContentView`），红绿灯放进左栏，工具栏和内容连成一体 |
| 编辑器 · 风格 | 方框流程条、深色块、系统默认控件，和设置页不像一个产品 | 用设置页同一套组件：12px 圆角卡片、浅描边、`accentSoft` 选中、28px 按钮 |
| 编辑器 · 每一步 | 选项卡片三个一排，文字被挤成「没参数 / 时用」；运行设置放在「输出」里；关键字步骤混着基本信息 | 单选列表（标题和说明在一行）；运行设置挪到「脚本」；名称、说明、图标点标题编辑 |
| 编辑器 · 按钮 | 灰色方块「保存」、过饱和的「▶ 测试」、带蓝色下拉箭头的「＋新建」，大小不一 | 统一 28px 高、8px 圆角；一个主按钮「运行测试 ⌘R」，其余都是次要按钮或图标按钮 |

## 1. 现在是怎么工作的

### 1.1 启动器关键字（设置 → 启动器 → 启动器关键字）

在启动器开头输入「关键字 + 空格（或冒号）」进入对应的插件，只输关键字时按 ↩ 处理选中的文字（`AskKeywordMatcher`）。关键字由三个内置插件提供，用户可以增删改：

| 插件 | 默认关键字 | 每个关键字能设什么 | 页面上的样子 |
|---|---|---|---|
| 翻译 `AskTranslatePlugin` | `fy` `tr` `翻译` | 目标语言（默认「自动判断方向」） | 关键字输入框 + 语言下拉框 + 开关 + 「−」 |
| AI 指令 `AskPromptPlugin` | `rw` 润色、`sum` 总结、`ex` 解释 | 名称、提示词（`{input}` 是要处理的文字） | 关键字 + 名称 + 开关 + 「−」，下面一个两行的提示词框 + `{input}` + 「保存」 |
| 网页搜索 `AskWebSearchPlugin` | `g` `bd` `gh` | 名称、搜索网址（必须有 `{query}`，只能是 http/https） | 关键字 + 名称 + 开关 + 「−」，下面一个网址框 |

另外还有：
- 「第二语言」：一个全局设置。内容已经是界面语言时，「自动判断方向」译成它。它现在夹在翻译和 AI 指令两组中间。
- 「恢复默认关键字」。
- 关键字规则：最长 12 个字符，不能有空格或冒号，不能以 `/` 开头，不区分大小写不能重名。**工作流的关键字和它们共用一个命名空间**（`AskConversationModel.launcherKeywords`：内置的优先，和内置重名的工作流关键字会被忽略）。
- 保存方式：关键字、名称、网址在按 ↩ 时保存；提示词要点「保存」；下拉框和开关立即保存。

### 1.2 工作流编辑器（独立窗口）

`AskWorkflowEditorView`：左边是工作流列表，中间是流程条和当前步骤，右边是 AI 助手 / 测试运行。

1. **关键字**：表格（关键字、显示名称、`名字=值` 形式的预设参数、拖动排序、删除），下面是「基本信息」（名称、说明、图标）。
2. **输入**：「参数」三选一（必填 / 可选 / 不需要），「选中的文字」三选一（没参数时用 / 总是带上 / 不要），参数构造器（一格一个 argv，可以插入 `{query}` `{selection}` `{option:名字}`），实时显示示例的 argv 和 stdin。
3. **脚本**：文件标签和代码区（行号、着色、查找、出错的行标红）。
4. **输出**：「脚本输出什么」四选一（文本 / 不输出只做事 / 自动 / 条目列表 W2），「什么时候运行」（按 ↩ / 边打边出 W2），启动器预览，以及**运行设置**（超时、运行时和解释器、脚本文件、环境变量）。
5. 顶部：图标、名称、`id · 版本`、状态徽标、未保存提示、「保存」、「▶ 测试」、「···」、启用开关。表单 / `workflow.json` 切换在流程条下面。
6. 右侧：AI 助手（对话修改，给出修改提案，看过差异再应用）；测试运行（先保存再运行，结果分为预览 / stdout / stderr / 传入了什么，失败时可以「让 AI 修复」）。

## 2. 问题

### 2.1 关键字页

1. **同一张卡片里有三种行结构**：翻译是「关键字 + 下拉框」，AI 指令是「关键字 + 名称」再加一个大文本框和两个按钮，网页搜索是「关键字 + 名称」再加一个网址框。眼睛没有固定的列可以对齐，看起来很乱。
2. **所有可编辑的内容都摊开在页面上**。9 个关键字的页面需要滚动好几屏，只想看看「有哪些关键字」时也被迫看全部配置。
3. **保存方式不一样**：有的按 ↩ 保存，有的点「保存」，有的立即生效。改了提示词不点保存就丢了，而且没有任何提示。
4. **提示词框只有两行，长提示词被截断**，第二行只露出一半（截图 `before-keywords.png`）。
5. **名称的占位文字和真实内容分不清**：灰色的「润色」是占位文字，看起来像是禁用状态。
6. **每一行都有开关和「−」两个控件**，删除按钮一直显示，容易误点，视觉上也很吵。
7. **「添加关键字」直接生成 `fy2` 这样的名字**，再让用户去改，不知道新关键字是干什么的。
8. **工作流的关键字不在这里**，但它们会和这里的关键字冲突，用户看不到全貌。
9. 「第二语言」是全局设置，却夹在翻译关键字和 AI 指令中间，看起来像某个关键字的选项。

### 2.2 工作流编辑器

1. **标题和内容分成两块**：系统标题栏（只写着「工作流编辑器」）、工具栏、分割线叠在一起，顶部有三条横线。
2. **风格老旧，和设置页不一致**：流程条是四个深色方框加小箭头；单选卡片是厚边框的灰块；下拉框、按钮都是系统默认样式；`workflow.json` 切换是一个大的分段控件。设置页早就换成了卡片、描边、`accentSoft` 选中的风格。
3. **每一步的排版不直观，文字换行很别扭**：
   - 「输入」里的选项卡片三个一排，宽度不够，「没参数时用」被拆成两行，「可以只输关键字」也换了行。
   - 流程条节点里的摘要被截断，图标很小。
   - **运行设置（超时、运行时、脚本文件、环境变量）放在「输出」里**，和输出没关系，找不到。
   - 「关键字」步骤下面混着名称、说明、图标。
   - 预设参数要用 `a=1, b=2` 这种文本格式输入。
4. **按钮土，而且不统一**：「保存」是灰色实心块，「▶ 测试」是很饱和的蓝色，大小和圆角各不相同；左下角的「＋ 新建」带一个蓝色的下拉箭头；启用开关、「···」和按钮挤在一起，没有分组。

## 3. 方案

### 3.1 关键字页（截图 `kw-list`、`kw-edit`、`kw-add`）

**列表**：一张卡片，每行固定四列，**只看不改**：

```
关键字      功能             做什么                                 启用
[fy]       文 翻译           自动判断方向（中文 ↔ 英语）              ●
[rw]       ✦ 润色            Polish the following text: fix …       ●
[g]        ⌕ Google          www.google.com/search?q={query}        ●
[wf]       ⌘ Python·输出文本  在工作流编辑器中编辑                     ↗
```

- 按功能分组（翻译 / AI 指令 / 网页搜索 / 工作流），组标题带一句说明。
- 顶部：分段筛选（全部 · 翻译 · AI 指令 · 网页搜索 · 工作流，带数量）、搜索框（匹配关键字、名称、内容）、主按钮「＋ 添加关键字」。
- 「做什么」只显示一行，放不下用省略号。停用的行变淡。
- 开关保留在行上（最常用的操作，立即生效）；删除挪进对话框和右键菜单。
- **工作流的关键字也列出来**，只读，点一下打开工作流编辑器。关键字冲突在这里一眼就能看到。
- 「第二语言」挪到列表下面单独的「翻译」卡片里；「恢复默认关键字」变成卡片下面的文字按钮（点了要二次确认）。

**编辑对话框**（`sheet`，点一行打开）：

| 字段 | 翻译 | AI 指令 | 网页搜索 |
|---|---|---|---|
| 关键字 | ✓（等宽，实时校验，冲突时写明和谁冲突，包括工作流） | ✓ | ✓ |
| 其他 | 翻译成：下拉框 + 一句说明「自动判断方向」 | 名称；提示词（6 行起，可拉高）+ 插入 `{input}` +「恢复预设」 | 名称；搜索网址（校验 `{query}`、http/https）+ 常用引擎快捷填入 |
| 效果 | 启动器里的样子：`[rw · 润色] hello world` | 同左 | 同左 |

- 底部统一：「删除」（左）· 启用开关 · 「取消」·「保存」。只有一种保存方式；有错误时「保存」不可用；Esc 关闭，⌘↩ 保存。
- 名称和提示词显示真实值：预设的提示词直接填进输入框，而不是作为占位文字；保存时和预设一样就不写进 `options`，行为和现在一样（预设以后更新了还能跟着变）。

**添加**：「＋ 添加关键字」弹出菜单：翻译 / AI 指令 / 网页搜索 / 新建工作流…。选前三项打开同一个对话框，关键字为空等用户填；「新建工作流…」打开工作流编辑器的新建面板。

### 3.2 工作流编辑器（截图 `ed-*`）

**窗口和顶部（解决「两块」）**

- `NSWindow` 加 `.fullSizeContentView`，`titlebarAppearsTransparent = true`，`titleVisibility = .hidden`。红绿灯落在左栏顶部，系统标题栏不再单独占一行。
- 顶部一行，高 56：图标 · **名称 ▾**（点击弹出名称、说明、图标的编辑框）· `id · 版本` · 状态徽标 ‖ 未保存 ·「保存 ⌘S」（次要）·「▶ 运行测试 ⌘R」（唯一的主按钮）‖ 启用开关 ·「···」· 显示/隐藏右栏。
- 顶部和内容之间只有一条很淡的线（`border-soft`），和设置页的分隔一样。

**流程条 → 编号步骤**

- `① 关键字 — ② 输入 — ③ 脚本 — ④ 输出`：编号圆点 + 标题 + 一行摘要；选中的步骤是一张浮起的卡片，编号变成强调色；有问题的步骤，编号上有红点。
- 每一步平分宽度，摘要尽量短（「wf · wc」「可选 · 或选中」「main.py」「文本 · 30 秒」）。
- 表单 / `workflow.json` 切换变成步骤右边的一个小按钮「{ } JSON」。

**每一步**

- **关键字**：表格放进卡片，列是「关键字 · 显示名称 · 预设参数」；预设参数变成小标签（`mode=chars ×`、`＋ 参数`），不再用文本格式；「＋ 添加关键字」是卡片的最后一行。基本信息挪到顶部的名称弹框里。
- **输入**：「关键字后面的内容」和「选中的文字」并排放两张卡片，**每张卡片是一个单选列表**，标题加粗，说明灰色，放在同一行（「可以不输入 只输关键字也能运行」），不会再被拆开。参数构造器、插入标签和「试一下」放在同一张卡片里，下面实时显示 argv 和 stdin。
- **脚本**：文件标签改成胶囊样式；代码区是一张圆角卡片，背景和窗口统一，当前行轻微高亮。右上角「运行设置 · Python 3.9 · 30 秒」展开**运行设置**（运行时、解释器、脚本、超时滑块、环境变量键值表），**从「输出」挪到这里**。卡片底部是状态栏：问题数 · 解释器 · 光标位置 · 编码 · 缩进。出错的行标红，下面一行写原因。
- **输出**：左边是「启动器怎么展示脚本的输出」单选列表（还不能用的选项标「即将支持」）和「什么时候运行」分段控件；右边是启动器预览，选「只做事」时预览会跟着变。

**右栏**

- 顶部是一个分段控件（✦ AI 助手 | ▶ 测试运行），测试失败时「测试运行」后面带红点。
- AI 助手：没有对话时显示 3 条示例需求，点一下就发送；提案卡片显示：改了哪些文件、各多少行、试跑结果、风险标签，以及「查看差异 / 放弃 / 应用」。
- 测试运行：输入框带关键字前缀和「运行」按钮；结果用分段控件切换预览 / stdout / stderr / 传入了什么；失败时显示「第 12 行出错｜定位｜✦ 让 AI 修复」；下面是最近运行。

**左栏**：选中项用 `accentSoft` 底色；底部「＋ 新建工作流」是普通按钮（点开菜单：用 AI 生成 / 从模板 / 复制当前），旁边是「在 Finder 中显示」图标按钮。

## 5. 需要确认的地方

1. 关键字编辑用**对话框**（本方案）还是**在列表里展开**？对话框更适合长提示词，保存方式也清楚；展开不用离开列表，但会回到「一页摊开」的问题。
2. 工作流的关键字是否在关键字页**只读显示**（本方案），还是不显示？
3. 编辑器的启用开关留在顶部（本方案），还是挪进「···」，只用状态徽标表示？
