现状问题

  • 浮窗与背后窗口融在一起：边框 10% 白、阴影弱，叠在深色应用上几乎看不出边界。
  • 上下两截：输入区与底栏两种底色 + 分隔线，像两个拼起来的控件。
  • 左侧 ✦ 徽标过重：26pt 深蓝方块抢了输入框的焦点；占位符与光标起点差 2pt，光标压在「输」字上。
  • 底栏 6 种控件样式：纯文字模型名（字号更大）、带脑图标的推理档、虚线「附带截图」、描边「Google Chrome」、描边麦克风、灰色发送钮 —— 重量不一，信息层级不清。
  • 虚线截图 chip 像坏掉的按钮：不可用原因只在 tooltip 里。
  • 「Google Chrome」看起来可点击，实际只是上下文来源标签。
  • 没有任何键盘提示，而这是一个纯键盘唤起的面板。

结构：上下文 → 输入 → 操作

  • 单一底色（#262626），圆角 16，1pt 16% 白描边 + 顶部 1pt 内高光 + 大阴影 0 24 60 / 55%，在任何窗口上都能「浮」起来。去掉底栏分隔线。
  • 上下文行（34pt）：左侧为来源应用图标 + 应用名 · 窗口标题（12pt、三级灰，只读标签，不做成按钮）；右侧为「附带截图」开关。上下文从底栏上移，底栏只留「模型 + 动作」。
  • 输入区：16pt，移除 ✦ 徽标；占位符与光标同一起点（左内边距 18）。1 行起，最多 6 行后内部滚动。
  • 底栏（44pt）：模型与推理档统一为 12.5pt 幽灵 pill（hover 才出底色），中间用 3pt 圆点分隔；右侧：语音提示「按住 Fn 说话」→ 麦克风 → 发送。三个圆形控件统一 30pt。
  • 空输入时发送钮为 8% 白底 + 三级灰图标（不可用），只有可发送时才出蓝色。
