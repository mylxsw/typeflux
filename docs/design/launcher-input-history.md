# 启动器：每次呼出都是空白 + ↑ 回溯最近输入

> 状态：设计（GUL-362）。可交互设计稿：`docs/design/launcher-input-history.html`（浏览器直接打开）。截图在 `docs/design/launcher-input-history/` 下。

## 1. 需求

1. 每次按快捷键呼出启动器，都从初始状态开始：输入框是空的。
2. 输入框为空时按 ↑，显示「最近输入」，可以快速填回以前的输入。

现在的启动器会保存草稿（`launcherDraft` 由 `persistDrafts()` 持久化），所以下次打开时还留着上次的文字。

## 2. 呼出：总是空白

每次呼出启动器时：

- 清空 `launcherDraft.text`，退出关键词模式（`plugins.update(text: "")`），清掉用户手动加的附件，首页高亮回到默认项。
- 自动带上的上下文（选中文字、当前网页）照常按当时的状态重新获取，和现在一样。
- 关闭时输入框里还有文字（去掉首尾空白后至少 2 个字），这段文字记入历史，标为「未发送」。草稿不再留在输入框里，但按 ↑ 就能找回，不会丢。

## 3. 最近输入

### 3.1 打开

- 输入框为空时按 ↑，启动器下半区（首页的位置）换成「最近输入」列表，并高亮第 1 条。
- 首页如果有高亮行，只有高亮在第一行时 ↑ 才打开历史；否则 ↑ 先把高亮往上移。首页现在的 ↑ 循环到最后一行的行为改为打开历史。
- 输入法组字中（`hasMarkedText()`）不响应。输入框有内容时，↑ 还是在结果列表里移动。

不用浮层叠在结果上：启动器是单列卡片，在原位替换下半区，内容不会叠在一起透出来，高度也跟内容走（规则同 `AskLauncherSuggestions.height`）。

### 3.2 行

每行是 44pt 高，和首页的行一样：

| 部分 | 内容 |
|------|------|
| 图标 | 当时的去向：问 AI ✦、计算 =、应用图标、文件图标、关键词（译 / ✎ / ≡ …）、网页搜索、未发送 ✎（橙色） |
| 文字 | 原样的输入。关键词前缀显示成标签（`fy` + 参数）；多行文字用 `↵` 连成一行，超长截断 |
| 附注 | 计算结果 `= 33,400`，或打开的目标 `→ Zed`，或「未发送」标签 |
| 右侧 | 相对时间；高亮时前面多一个「填入 →」 |

按住 ⌘ 时，前 9 条显示编号，复用 `AskLauncherShortcutBadge`。

### 3.3 键盘与鼠标

| 按键 | 行为 |
|------|------|
| ↑ / ↓ | 按屏幕方向移动，不循环 |
| ↩ / → / ⇥ / 单击 | 填入：输入框换成这条文字，光标放在末尾，关闭历史，结果列表立即按新文字计算 |
| ⌘1…⌘9 | 填入第 n 条 |
| ⌘↩ | 直接用这条文字问 AI，不填入（启动器里 ⌘↩ 一直是问 AI） |
| ⌘⌫ | 删除高亮的一条 |
| 打字 | 筛选历史（子串，以及中文的拼音首字母），输入框前显示「↺ 最近」标签 |
| ⌫（筛选为空时） | 关闭历史，回到首页 |
| esc | 有筛选文字时先清空；筛选为空时回到首页；再按一次才关闭启动器 |
| 右键 | 填入 / 问 AI / 拷贝文字 / 删除 / 清除全部 |

底栏提示：首页为「↑ 最近输入 · ↩ 执行 · esc 关闭」；历史打开时为「↩ 填入 · ⌘↩ 问 AI · ⌘⌫ 删除 · esc 返回」。

填入以后，不直接重放当时的动作，而是重新计算结果：文件可能已经被删、应用可能已经更新，用户看到的结果总是当下的，再按一次 ↩ 执行。

### 3.4 空状态

没有历史时，按 ↑ 也会打开列表，显示「还没有输入历史」，并说明会记什么。筛选没有结果时，显示「没有匹配…」，并提示 ⌫ / esc。

## 4. 记录规则

| 项 | 规则 |
|----|------|
| 什么时候记 | 执行时记：↩ 执行任一结果、⌘↩ 问 AI、运行关键词、⌘N。放弃时也记：关闭时输入框里有文字，记为「未发送」 |
| 记什么 | 输入文字（含关键词前缀）、去向种类、去向标签（结果值 / 应用名 / 文件名）、时间。不记选区、截图、附件和 AI 回答 |
| 去重 | 文字相同（忽略首尾空白和大小写）只保留一条，移到最前；同样的文字执行后，覆盖原来的「未发送」 |
| 不记 | 只有空白，或只有关键词本身（如 `fy`）的输入 |
| 容量 | 默认 100 条（设置里可选 50 / 100 / 200），单条最长 500 字 |
| 存储 | 只存在本机，放在 `UserDefaults` 的 `ask.launcher.inputHistory` 下，和 `ask.launcher.keywordUsage` 放在一起；不上传，也不同步 |

## 5. 设置（启动器 → 通用）

- 「记住输入历史」开关，默认开。关闭后不再记录，也不显示 ↑ 提示；按 ↑ 时显示空状态，提示可以在设置里打开。已有记录保留，直到用户清除。
- 「保留条数」：50 / 100 / 200。
- 「清除输入历史…」，需要确认。

## 6. 实现提示

- 纯模型 `AskLauncherInputHistory`（条目、去重、容量、筛选、拼音首字母匹配），注入一个存储协议，方便单测。
- 在 `AskConversationModel+LauncherHome` 里增加 `launcherHistoryMode`，下半区的优先级为：`/` 命令面板 > 历史 > 首页 > 快捷结果。
- 呼出入口（`AskLauncherWindowMode` / 显示启动器的地方）调用 `resetLauncherForPresentation()`；关闭入口在清空之前，先记录「未发送」。
- 「执行」的记录放在执行快捷结果（`AskConversationModel+QuickResults`）、`submitLauncher()`、运行关键词这几处汇合的地方。

## 7. 和竞品相比

| | 竞品 | Typeflux |
|---|---|---|
| 呈现 | 浮层盖在结果列表上，底下的文字会透出来 | 在原位替换下半区，不叠层 |
| 信息 | 只有文字 | 带去向：结果值、打开了什么、关键词、未发送 |
| 查找 | 只能翻 | 打字筛选，支持拼音首字母 |
| 管理 | — | ⌘⌫ 删除、清除全部、可以关闭 |
| 草稿 | 呼出时不保留 | 呼出时也是空白，但放弃的草稿可以按 ↑ 找回 |
