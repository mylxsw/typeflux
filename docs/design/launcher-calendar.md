# 启动器日历：关键字 `cal`（GUL-364）

> 状态：设计稿，待确认。配套可交互设计稿：`docs/design/launcher-calendar.html`（`?s=<id>` 打开某一屏，`?light=1` 浅色，`?solo=1` 只显示一屏，`?weeks=1` 显示周数）。截图在 `docs/design/launcher-calendar/`：`hint` `month` `agenda` `jump` `range` `search` `year` `perm` `weeks`，以及 `light-month` `light-agenda`。
>
> 设计稿里的「今天」固定为 2026-10-14 10:24，日程是模拟数据；农历用浏览器的中国历计算，节气用公式计算，2026 年的放假安排是内置数据。

## 0. 一页结论

| | 方案 |
|---|---|
| 入口 | 新的内置关键字 **`cal`**，别名 **`日历`**、**`rl`**（可以在关键字页改名、加别名）。只输入关键字时，第一行显示今天的日期、农历、周数和下一个日程；↩ 进入，`cal` 加空格直接进入并开始输入 |
| 界面 | 启动器内**左边月历、右边当天详情**。月历标出今天、农历 / 节日 / 节气、法定假日「休」、调休上班「班」，以及日程颜色点；右边是选中这天的农历、周数、假期，以及当天的日程 |
| 输入框 | 输入框是**万能入口**，按内容自动判断：日期 → 跳过去；两个日期 → 算间隔（含工作日）；年份 → 年视图；其他文字 → 搜索日程 |
| 日程 | 用 EventKit 读取系统日历（包括 iCloud、Google、Exchange 等已添加到「日历」App 的账户）。**只读**；新建和编辑交给「日历」App |
| 权限 | 不授权也能用：日期、农历、节假日、间隔都在本机计算。日程区显示说明卡，**用户点了才弹系统授权框** |
| 键盘 | ←→↑↓ 选日期，⌘←→ 换月，⌘T 回到今天，⇥ 切到日程，↩ 打开（日程有会议链接时直接加入会议），⌘C 复制，⌥↩ 把日期插入到原来的应用 |

## 1. 现在的基础

- 关键字插件实现 `AskLauncherPlugin`。「只输入关键字按 ↩ 进入本地功能」的一类插件（`entersOnReturn`）有剪贴板 `clip`、笔记 `nb`、系统监控 `top`，日历也属于这一类。
- 系统监控已经有「插件自带一块启动器界面」的做法：`AskComposerViews` 判断 `pluginDisplay.systemMonitor`，渲染 `SystemMonitorLauncherView`，并把按键交给 `SystemMonitorLauncherModel`。日历照搬这条路。
- 关键字匹配（`AskKeywordMatcher`）、别名、英文名（`AskKeywordAliases.englishName`）、关键字设置页都是现成的，新增插件只需要注册。
- 启动器宽度 680（`AskMetrics.launcherWidth`），高度由 `AskLauncherHeightAnimator` 跟着内容变化。
- App 没有开沙盒，但开了 Hardened Runtime。读日历需要新增权限说明和 entitlement（见 §5.3）。

## 2. 需求理解

1. 在启动器里输入 `cal` 就能看日历：不用切到「日历」App，也能快速看「今天几号、星期几、第几周」「某天是星期几」「离某天还有多少天」「今天 / 某天有什么安排」。
2. 用户是中文用户，「看日历」里很重要的一部分是**农历、节气、法定假日和调休**（「下周六要不要上班」），这是系统「日历」App 的弱项，也是这个功能相对 Raycast / Alfred 的差异点。
3. 这一阶段先出方案和可交互设计稿，用来沟通、确认范围。

## 3. 交互

### 3.1 输入关键字（截图 `hint`）

- 输入 `cal`、`日历` 或 `rl`，「关键字」区第一行是「日历」，图标是今天日期的小日历。副标题：`今天 10月14日 周三 · 农历九月初五 · 第 42 周 · 3 个日程，下一个 14:00 设计评审：日历功能`。没授权时不显示日程部分。
- ↩ 进入；`cal` 加空格直接进入，空格后面的文字就是参数（`cal 下周五`）。规则和其他关键字一致。
- 「日历」App 照常出现在应用结果里。

### 3.2 月视图（截图 `month`）

从上到下：

1. **输入行**：关键字标签 `日历`（红色，`calendar` 图标）+ 输入框（占位文字「日期、节日或日程：12-25、下周五、春节、评审…」）。选中的不是今天时，右上角出现「今天 ⌘T」。
2. **月份标题**：`2026年10月 丙午年 · 马年`，右侧 `‹ 今天 ›`。点标题进入年视图。
3. **左：月历**（6 行固定高度，换月时启动器不跳动）
   - 每周从哪天开始跟随系统设置（`Calendar.current.firstWeekday`）。
   - 每格：日期数字 + 一行小字。小字的优先级：假期第一天显示假期名 > 节日 > 节气 > 农历日（初一显示月份名，如「九月」）。
   - 今天：数字是红底白字。选中：蓝色描边。周末数字颜色稍淡；不在本月的日期变淡。
   - 法定假日：浅绿底 + 右上角「休」；调休上班：浅橙底 + 右上角「班」。
   - 日程：格子底部最多 3 个颜色点（按日历的颜色去重）。
   - 底部图例：放假、调休上班、各日历颜色。
   - 可选：左侧显示 ISO 周数（截图 `weeks`，默认关）。
4. **右：当天详情**
   - `10月14日 周三 [今天]`；不是今天时标签变成「明天 / 3 天后 / 5 天前」，跨年时加年份。
   - `农历九月初五 · 第 42 周 · 第 287 天`。
   - 标签行：`休 · 国庆节假期第 3/7 天`、`班 · 国庆节调休上班`、节日、节气。今天没有特殊信息时，显示「距元旦放假还有 N 天」；当年假期都过完、下一年还没公布时，显示「2027 年放假安排尚未公布」。
   - 日程列表（§3.3）。
5. **底栏**：`←→↑↓ 选择日期 · ⌘←→ 切换月份 · ⇥ 日程 · ↩ 在日历中打开 · ⌘C 复制 · ⌥↩ 插入日期 … esc 返回`。

按键：

| 按键 | 作用 |
|---|---|
| ←→ | 前一天 / 后一天（输入框为空时；有文字时是移动光标） |
| ↑↓ | 前一周 / 后一周 |
| ⌘← ⌘→ | 上个月 / 下个月（保留日期，31 号到 2 月变成月末） |
| ⌘T | 回到今天，并清空输入框 |
| ⇥ | 焦点在月历和日程列表之间切换（这天有日程时） |
| ↩ | 在「日历」App 中打开这天 |
| ⌘C | 复制日期，例如「2026年10月14日 周三」（格式见 §6） |
| ⌥↩ | 关闭启动器，把日期写回原来的应用（`TextInjector`，和其他插件的 ⌥↩ 一致） |
| ⌘N | 在「日历」App 中打开这天，用来新建日程 |
| 单击 / 双击日期 | 选中 / 在「日历」App 中打开 |

### 3.3 日程（截图 `agenda`）

- 全天日程在前，其余按开始时间排序。每行：日历颜色条、开始 / 结束时间、标题、地点（有会议链接时带视频图标）。
- 今天的日程显示状态：`进行中 · 还剩 6 分钟`（绿色）、`3 小时 36 分后`（蓝色），已结束的变淡。
- ⇥ 进入日程列表时，默认选中**下一个还没结束的日程**。选中的一行展开：备注摘要（与会人数、组织者）和操作按钮：
  - **加入会议 ↩**：从 `URL`、`location`、`notes` 里识别 Zoom / Google Meet / Teams / 腾讯会议 / 飞书的链接，用默认浏览器或对应 App 打开。
  - **在日历中打开 ⌘O**（没有会议链接时是 ↩）：用 `ical://ekevent/<calendarItemExternalIdentifier>` 打开，打不开时退回到打开那一天。
  - **复制 ⌘C**：「设计评审：日历功能，2026年10月14日 周三 14:00–15:00，会议室 3F-B」。
- 这天没有日程：「这天没有日程」+「在日历中新建 ⌘N」。
- 一天日程很多时，列表在右栏内滚动，启动器高度不变。

### 3.4 输入框：跳转、间隔、年视图、搜索

输入框里的文字按下面的顺序识别，标签同步显示当前模式（`日历 → 间隔`、`日历 → 搜索日程`、`日历 → 2027 年`）：

| 输入 | 识别为 | 例子 |
|---|---|---|
| 完整日期 | 跳到这天 | `2027-02-07` `2027/2/7` `2027年2月7日` |
| 月日 | 今年的这天 | `12-25` `12/25` `12月25日` |
| 相对日期 | 从今天算 | `今天` `明天` `后天` `昨天` `+30` `-7` `+2w` `30天后` `3周后` `下周五` `周一` `下下周三` |
| 节日 / 节气 | 下一个（含今天） | `春节` `除夕` `中秋` `端午` `元旦` `国庆` `圣诞` `冬至` `清明` |
| 年月 | 跳到这个月 | `2026-12` `2026年12月` `3月` `下个月` |
| 年 | 年视图 | `2027` |
| 两个日期 | 间隔 | `今天 到 12-31` `10/1 10/8` `2026-10-14 ~ 春节` |
| 其他 | 搜索日程 | `评审` `上海` |

英文界面同时支持 `today` `tomorrow` `next fri` `dec 25` `christmas` 等写法。识别规则是纯函数，好写测试。

**跳转（截图 `jump`）**：月历跳到那个月并选中那天，右侧标签显示「下一个春节 · 116 天后」。之后用方向键继续选日期时，输入框自动清空。

**间隔（截图 `range`）**：月历高亮这段日期，右侧显示：

- 相隔天数（大字）、周数和天数、约几个月；
- 含首尾共几天、工作日、休息日（**按法定节假日和调休计算**，只按周末算的部分会明确说明）；
- ↩ 复制「78 天」，另一个按钮复制「57 个工作日」。

**年视图（截图 `year`）**：12 个小月历，标出今天、放假（绿）、调休上班（橙）、主要节日（红），每个月标「休 N 天」。下一年的放假安排没公布时，顶部提示「2027 年放假安排尚未公布（通常在前一年 11 月发布），公布后随应用更新」。←→↑↓ 选月份，↩ 或点击进入那个月。

**搜索日程（截图 `search`）**：文字不是日期时，按标题、地点、日历名搜索**过去 30 天到未来 90 天**的日程，分「接下来」「已过去」两组，匹配的文字高亮。↑↓ 选择，↩ 在「日历」中打开，⇥ 回到月视图并选中这个日程，⌘C 复制。没有结果时提示它也不是能识别的日期，并给出几个输入例子。

### 3.5 权限（截图 `perm`）

- 第一次进入时**不主动弹授权框**。日程区显示一张卡：「显示你的日程 · 允许访问日历后，这里会显示当天的日程和会议链接。日程只在本机读取，不会上传。」按钮「允许访问日历」点了才调用 `requestFullAccessToEvents`（macOS 14+；13 用 `requestAccess(to: .event)`）。
- 拒绝后，按钮变成「打开系统设置」（`x-apple.systempreferences:com.apple.preference.security?Privacy_Calendars`）。
- 「不再提示」：隐藏这张卡，之后不显示日程区；可以在关键字设置里重新打开。
- 授权后，监听 `EKEventStoreChanged`，用户在「日历」App 里改了日程，下次打开就是新的。

### 3.6 esc 和退格

esc 逐层退出：日程焦点回到月历 → 清空输入框（保留当前选中的日期）→ 退出关键字（回到 `cal` 提示行）→ 关闭启动器。输入框为空时按 ⌫ 也会退出关键字，和其他关键字一样。

## 4. 数据

### 4.1 日期、农历、节气、节日

| 内容 | 来源 |
|---|---|
| 公历、周数、一年中的第几天 | `Calendar.current`（每周从哪天开始跟随系统）；周数用 `Calendar(identifier: .iso8601)` |
| 农历月日、干支年、生肖 | `Calendar(identifier: .chinese)`，系统自带，不需要数据表 |
| 节气 | 用公式按年计算（21 世纪通用的寿星公式，精确到天），单独做成纯函数，用 2020–2030 年的已知节气日期测试 |
| 公历节日 | 内置表（元旦、情人节、妇女节、劳动节、青年节、儿童节、教师节、国庆节、平安夜、圣诞节），母亲节、父亲节按「第几个周日」算 |
| 农历节日 | 内置表（春节、元宵、龙抬头、端午、七夕、中元、中秋、重阳、腊八、小年），除夕取「正月初一的前一天」（腊月可能只有 29 天） |

### 4.2 法定假日和调休

- 国务院每年 11 月左右公布下一年的安排，**没有可以计算的规律**，只能用数据。
- 第一版：数据放在 `Resources/Holidays/cn.json`，按年份存「放假区间 + 名称」和「调休上班日」，随版本更新。没有数据的年份只按周末计算，并在界面上明确说「尚未公布」，**不猜**。
- 第二版（待确认）：Typeflux Cloud 提供同样格式的 JSON，App 每天最多检查一次，能在不发版的情况下更新。下载失败时用内置数据。
- 显示条件：界面语言是简体或繁体中文，或者地区是中国大陆时默认开启；设置里可以手动开关（§6）。

### 4.3 日程

- `EKEventStore.events(matching:)` 按需读取：月视图读这个月前后各一周，搜索读过去 30 天到未来 90 天。读取放在后台，结果按天缓存，日程变化（`EKEventStoreChanged`）时清空缓存。
- 只读取用户在设置里勾选的日历（默认全部，除了「节假日」类订阅日历，避免和内置假期重复）。
- 会议链接：按域名识别（zoom.us、meet.google.com、teams.microsoft.com、meeting.tencent.com、vc.feishu.cn 等），只用于显示「加入会议」，不上传。

## 5. 实现（确认设计后）

### 5.1 结构

| 步骤 | 改动 | 主要文件 |
|---|---|---|
| C1 日期逻辑 | `CalendarDayInfo`（农历、节日、节气、周数）、`SolarTerms`、`ChineseFestivals`、`HolidaySchedule`（读 `cn.json`，判断休 / 班 / 工作日，统计区间工作日）。全部是纯值类型 | `Sources/Typeflux/Calendar/` 新目录 |
| C2 输入识别 | `CalendarQueryParser`：把输入框文字变成 `.date / .month / .year / .range / .search`，中英文两套规则，注入「今天」方便测试 | 同上 |
| C3 日程 | 协议 `CalendarEventProviding`，生产实现 `EventKitEventProvider`（权限、读取、缓存、变化通知）；`MeetingLinkDetector` 识别会议链接 | 同上 |
| C4 插件 | `AskCalendarPlugin`（`entersOnReturn = true`，`runsWithoutInput = true`，`usesSelectionInput = false`），默认关键字 `cal`，别名 `日历` `rl`，英文名 `calendar`；hint 行显示今日摘要 | `Ask/QuickResults/Plugins/Calendar/` |
| C5 启动器界面 | `CalendarLauncherView`（月视图、日程、间隔卡、年视图、搜索列表）、`CalendarLauncherModel`（选中日期、焦点、模式、按键处理 ← → ↑ ↓ ⌘← ⌘→ ⌘T ⇥ ↩ ⌥↩ ⌘C ⌘N ⌘O esc）；`AskComposerViews` 像系统监控那样把按键交给它 | `Calendar/`、`Ask/AskComposerViews.swift` |
| C6 动作 | 打开「日历」App 的某天 / 某个日程、加入会议、复制、写回；写回复用现有 `.writeBack` | `Calendar/`、`Ask/AskConversationModel+Plugins.swift` |
| C7 设置与本地化 | 关键字编辑页增加日历选项（§6）；中文简体、中文繁体、英文、日文、韩文的文案 | `Settings/AskKeyword*`、`Resources/*.lproj` |

### 5.2 性能

- 打开 `cal` 不读 EventKit 之外的任何东西，月视图（42 格）的农历、节气、假期在主线程计算也只需要微秒级；日程读取在后台，先显示月历，日程到了再填进去，不阻塞第一帧。
- 农历和节气结果按天缓存，在启动器关闭时释放。

### 5.3 权限与打包

- `Info.plist`（`app/Info.plist` 和 `Sources/Typeflux/Resources/Info.plist`）新增 `NSCalendarsFullAccessUsageDescription`（macOS 14+）和 `NSCalendarsUsageDescription`（macOS 13）。
- Hardened Runtime 需要 entitlement `com.apple.security.personal-information.calendars`，加到 `app/TypefluxRuntime.entitlements` 和 `TypefluxAppRelease.entitlements`。
- 不需要写日历的权限（`requestWriteOnlyAccessToEvents` 不用）。

### 5.4 测试

- 纯逻辑全部写单元测试，覆盖率按项目要求（≥ 90%）：输入识别（每种写法、跨年、闰年 2 月 29 日、非法日期 `2-30`、「下周日」在周日时的含义）、节气公式（对照 2020–2030 已知日期）、农历节日（含腊月只有 29 天时的除夕）、假期和工作日统计（含调休上班日、没有数据的年份）、会议链接识别、复制格式。
- 日程用假的 `CalendarEventProviding` 注入：没有权限、被拒绝、空日历、全天和跨天日程、进行中 / 已结束状态。
- 界面按 `LauncherSettingsPolishTests` 的做法输出深色、浅色截图，测试带 `.exclusiveUIState`。

## 8. 待确认

1. **关键字**：建议 `cal` + 别名 `日历`、`rl`。是否同意？
2. **日程范围**：第一版只读、不在启动器里新建或编辑（⌘N 交给「日历」App）。是否需要「`cal 明天 3 点 评审`」这样用自然语言新建日程？建议放到第二版，那时还要申请写日历权限。
