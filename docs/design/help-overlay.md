# help 关键词：全屏使用指南（GUL-390）

> 状态：设计稿，待确认。配套可交互设计稿：`docs/design/help-overlay.html`（`?solo=<id>` 只显示一屏，`?light=1` 浅色，`?s=<id>` 打开某一屏，`?noanno=1` 隐藏标注）。截图在 `docs/design/help-overlay/`：`1-entry` `2-home` `3-keywords` `4-detail` `5-shortcuts` `6-search` `7-empty` `8-faq`，以及 `light-*`。
>
> 这一阶段只出设计，不改代码。

## 0. 一页结论

| | 方案 |
|---|---|
| 入口 | 启动器关键词 `help`（别名 `帮助`、`?`）+ ↩；`help 截图` 打开后直接搜索。另有启动器底栏 `?` 按钮、对话命令 `/help`、菜单栏「使用指南…」，以及一个默认不占用的全局快捷键 |
| 形态 | 鼠标所在屏幕上的全屏遮罩（模糊 + 半透明），盖住所有窗口；esc 或点空白处关闭 |
| 内容 | 6 个分区：快速上手 · 关键词 · 快捷键 · 启动器技巧 · 对话命令 · 常见问题 |
| 核心原则 | **显示用户当前的配置**，不是写死的文案：改过名的关键词、自建关键词、工作流、停用项、用户实际绑定的快捷键都如实显示 |
| 找答案 | 打开即可打字搜索，关键词 / 名称 / 按键 / 命令 / 问题一起搜；搜不到时一键「问 AI」 |
| 从看到做 | 每个关键词都有「试一试」：关闭指南、打开启动器、填好关键词和示例 |

## 1. 需求理解

用户对应用感到困惑时，要能**快速**查到「这个功能怎么用」：

1. 不知道有哪些功能 → 需要一个能一眼扫完的总览。
2. 知道有这个功能，忘了关键词或快捷键 → 需要搜索，而且要搜得到用户自己改过的名字。
3. 用了但没效果 → 需要排查（权限、服务状态、常见问题）。
4. 看懂了 → 最好能马上试，不用再记住再去操作。

现状：
- 启动器有 `prefix`（关键词目录），只列关键词，不讲用法，也不包含快捷键和常见问题。
- 对话命令 `/help` 的行为是「什么都不做，命令面板本身就是列表」（`AskConversationModel+Commands.swift` 的 `case .help: break`）。
- 快捷键分散在「设置 → 快捷键」，关键词在「设置 → 启动器 → 关键词」，没有一个地方能一起看。
- 现有的三十多个内置关键词（含别名）、18 个系统命令、6 个内置快捷键 + 5 个可选功能快捷键、十几个启动器按键，对新用户来说门槛很高。

## 2. 入口（截图 `1-entry`）

| 入口 | 行为 |
|---|---|
| 启动器输入 `help` / `帮助` / `?` | 首行显示「使用指南」，↩ 打开。走现有关键词机制：新增插件 `AskHelpPlugin`（`runsWithoutInput`、`entersOnReturn` 均为 true，`usesSelectionInput` 为 false），用户可以在关键词设置里改名、加别名、停用 |
| `help 截图` / `? fy` | 打开指南并把后面的文字放进搜索框 |
| 启动器底栏 `?` 按钮 | 打开指南 |
| 对话命令 `/help` | 现在什么都不做，改为打开指南 |
| 菜单栏「使用指南…」 | 打开指南 |
| 全局快捷键 | 新增 `AppHotkeyAction.openHelp`，**默认不设置**（与其他 `AppHotkeyAction` 一致，不抢用户按键），在快捷键页可绑定 |

从启动器打开时，启动器先关闭；在指南里 esc 关闭后**不**回到启动器（用户可能只是查一下）。「试一试」类操作才会重新打开启动器。

## 3. 形态

- 一个无边框、覆盖整个屏幕（含菜单栏和 Dock 区域）的 `NSPanel`，出现在**鼠标所在的屏幕**上；背景是 `NSVisualEffectView`（`.fullScreenUI` 材质）+ 半透明遮罩。
- 打开时成为 key window，焦点在搜索框；任何字符键都直接输入到搜索框（不用先点）。
- 内容区域最大宽度 1180pt 居中；屏幕很小时（< 1100pt 宽）左侧导航收成图标。
- 动画：淡入 + 轻微缩放 160ms；遵循「减少动态效果」设置。
- 关闭：esc（先关详情、再清空搜索、最后关闭指南）、点遮罩空白处、右上角「esc 关闭」。
- 跟随应用的深 / 浅色外观（截图 `light-home` `light-detail`）。

## 4. 内容

### 4.1 布局（截图 `2-home`）

- 顶部：标题「Typeflux 使用指南」+ 搜索框（⌘F 聚焦）+ 关闭。
- 左侧：分区导航（⌘1–⌘6 跳转，滚动时高亮当前分区），下面是「在线文档」「反馈问题」和版本号。
- 右侧：所有分区在一页里顺序排列，可以一直往下滚。
- 底部：当前可用的按键提示，随状态变化（总览 / 搜索中 / 详情）。

### 4.2 快速上手

4 张卡片讲清 4 个入口，每张卡片上方画出按键（语音输入的 `fn` 有「按住」进度动画）：

| 卡片 | 按键（读取当前绑定） | 点击 |
|---|---|---|
| 语音输入 | `fn` 按住 | 关闭指南，提示「在原来的应用里按住 fn 说一句话」 |
| 随便问 | `fn` ×2 | 关闭指南并打开随便问 |
| 启动器 | `⌘Space` | 关闭指南并打开启动器 |
| 关键词 | `fy` + `Space` | 跳到关键词分区 |

下方「你可能还不知道」：从 `AskKeywordUsage` 中挑 3 个**从没用过**的内置关键词（按固定的推荐顺序取前 3 个，不随机，保证截图和文档稳定）。全都用过时隐藏这一行。

### 4.3 关键词（截图 `3-keywords`）

- 数据来自 `settings.askLauncherKeywords` + 工作流关键词 + 系统命令，与启动器、`prefix` 用同一份数据（复用 `AskPrefixPlugin.entries` 的来源）。用户改过的名字、别名、自己建的关键词、工作流都会出现；停用或不可用的显示为灰色并写明原因。
- 按用途分组：文字与翻译 · 搜索 · 截图与录屏 · 效率工具 · 我的关键词与工作流 · 系统命令。分组由插件决定（插件新增一个 `helpCategory`），用户自建的关键词跟随其插件，但统一放在「我的关键词与工作流」。
- 筛选：全部 / 各分组 / 可用选中文字 / 还没用过。
- 卡片：关键词 + 别名、名称、一句话说明、标签（可用选中文字、AI、自定义 / 工作流、已绑定的快捷键、还没用过、新）。
- 系统命令数量多、用法一致，用紧凑的三列列表展示，说明「输入英文全名或中文名都能找到」。

### 4.4 关键词详情（截图 `4-detail`）

点卡片（或 ↩）从右侧滑出详情：

- 做什么；是否可以处理选中的文字。
- **示例**：每条示例可点击 = 关闭指南 + 打开启动器 + 填入示例（不自动运行，用户按 ↩）。示例由插件提供（新增 `helpExamples`），自建关键词用通用示例「`关键词` + 文字」。
- 结果上的按键（来自插件已有的动作快捷键，如翻译的 ⌥↩ 替换、⇥ 切换服务、⌘R 单词卡、⌘S 收藏）。
- 全局快捷键：已绑定则显示按键和执行方式；没有则「给它设一个快捷键 →」跳到快捷键页的添加对话框并预选这个关键词。
- 使用次数、内置 / 自建。
- 底部：「去设置」（打开这个关键词的编辑对话框）、「在启动器中试一试 ↩」。

### 4.5 快捷键（截图 `5-shortcuts`）

四块，全部读取**当前**绑定：

1. **全局**：所有 `BuiltInHotkey` + `AppHotkeyAction`。未设置的显示「未设置 · 设置…」——让用户知道功能存在。
2. **关键词快捷键**：`KeywordHotkey` 列表，含执行方式摘要；「＋ 添加」。
3. **启动器里**：↩、⌘↩、Space/⇥、⌥↩、⌘C、→、⌘K、⌘U、↑、/、?、esc。
4. **结果上 / 对话窗口**：⌘S、⌘B、⌘O、⌘R、⌘Z；↩、⇧↩、⌘N、⌘K、⌘U、⌘↩、⌘,。

第 3、4 块是固定按键，来自一份集中定义的表（见 §6），避免和代码脱节。

### 4.6 启动器技巧 · 对话命令

- 启动器技巧：不用关键词也能做的事——算式、应用名、文件名、↑ 最近输入、任意问题交给 AI、先选中文字再打开。
- 对话命令：`AskCommand.all` 生成的 `/` 命令列表（随上下文变化的子菜单不展开），并说明技能和 MCP 也在 `/` 里。

### 4.7 常见问题（截图 `8-faq`）

- 顶部**状态检查**：麦克风、辅助功能权限（`PrivacyGuard`）、语音识别服务、文本处理模型。有问题的项标橙色，并给出「去授权 / 去设置」。授权后状态实时刷新。
- 下面是可展开的问题列表；和当前状态相关的问题（例如辅助功能未授权 → 「按住 fn 没有反应」「文字没有写进去」）自动展开第一个并标「可能和你有关」。
- 答案里的「设置 → …」都是可点击的跳转（关闭指南、打开对应设置页）。

## 5. 搜索（截图 `6-search` `7-empty`）

- 搜索范围：关键词（含别名）、名称、说明、快捷键名称和按键、系统命令、对话命令、常见问题。
- 按键匹配：`cmd`/`command` → ⌘，`opt`/`option`/`alt` → ⌥，`ctrl` → ⌃，`shift` → ⇧，`enter`/`return` → ↩，并忽略空格；所以「cmd k」能找到 ⌘K。
- 中文名称也匹配拼音首字母（复用启动器已有的拼音匹配）。
- 结果按类型分组，每组显示数量；↑↓ 选择，↩ 打开详情（关键词）或跳转（快捷键、问题），⌘↩ 试一试。
- **搜不到**：显示「问 AI：Typeflux xxx」（⌘↩）——关闭指南，打开启动器，把问题连同一份帮助摘要（由 §6 的数据生成的 Markdown，包含用户当前的关键词与快捷键）作为上下文发送给 AI；下方推荐几个常搜词。
- esc 清空搜索并回到总览。

## 6. 实现要点（确认设计后）

| 模块 | 内容 |
|---|---|
| `Ask/QuickResults/Plugins/AskHelpPlugin.swift` | 关键词 `help`，别名 `帮助`、`?`；`plan` 返回 `.openHelp(query:)` 动作 |
| `Help/HelpCatalog.swift` | 纯数据：把关键词、插件元数据、快捷键绑定、对话命令、固定按键表、常见问题组装成 `HelpSection` / `HelpEntry`。不依赖 UI，便于测试 |
| `Help/HelpSearch.swift` | 纯函数：查询规范化（按键别名、拼音）+ 打分 + 分组 |
| `Help/HelpOverlayController.swift` | 全屏 `NSPanel`、屏幕选择、焦点和 esc 栈 |
| `Help/HelpOverlayView.swift` 等 | SwiftUI 视图，分区 / 卡片 / 详情 / 搜索结果 |
| `AskLauncherPlugin` | 新增可选的 `helpCategory`、`helpExamples`、`helpKeys`，提供默认实现，现有插件逐个补充 |
| `AppHotkeyAction.openHelp` | 默认不设置 |
| `/help`、菜单栏 | 改为调用 `HelpOverlayController.show(query:)` |
| 本地化 | 所有文案进 `Localizable.strings`，跟随界面语言 |

测试：`HelpCatalogTests`（改名 / 停用 / 自建 / 工作流关键词、未设置的快捷键都正确显示；分组完整，每个内置插件都有分类）、`HelpSearchTests`（按键别名、别名匹配、拼音、空结果）、`AskHelpPluginTests`（关键词匹配与 `help xxx` 的查询传递）、`AskCommandsTests` 中 `/help` 的新行为。目标覆盖率 ≥ 90%。

## 7. 待确认

1. 关键词别名 `?` 是否会和用户以「?」开头的提问冲突？按现有匹配规则，只有「`?` + 空格」或只输入「`?`」才进入，问句「?怎么…」不受影响。如仍担心可以去掉这个别名，只保留底栏按钮。
2. 「问 AI」兜底会消耗一次模型调用；本机对话模式下使用本地模型。是否需要在帮助里注明？
3. 「在线文档」链接指向 typeflux-docs 站点的哪个页面。
4. 常见问题的初版条目（目前 7 条）由产品确认后再定稿。
