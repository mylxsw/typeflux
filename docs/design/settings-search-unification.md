# 设置页搜索与列表行统一规范 设计方案

> 状态：设计稿，待确认（GUL-394）。可交互设计稿：`docs/design/settings-search-unification.html`，截图在 `docs/design/settings-search-unification/`。
> 范围：设置窗口里所有「搜索框 + 可搜索列表」的页面。外观沿用 Liquid Glass 的配方（`ask-workspace-liquid-glass.html`、`notebook-redesign.html`），控件尺寸沿用 `SettingsControlMetrics`。

## 0. 一页结论

1. **只保留一个搜索控件**：`SettingsSearchField`。胶囊形，高 30pt，左侧放大镜，右侧在有内容时显示清除按钮和「N 项」结果数。现在的 8 种写法全部换成它。
2. **只有两种摆放位置**：
   - **A. 页面工具条**：在 Tab 下方单独占一行。左边是搜索框（可伸缩，最宽 320pt），接着是筛选，右边是主操作。用于整页都是列表的页面。
   - **B. 列表栏顶部**：放在左右分栏里左侧列表的最上面，与列表同宽，高 28pt。用于「左边列表、右边详情」的页面和选择器弹窗。
3. **筛选也只有一种写法**：选项不多于 4 个时用分段控件（`StudioSegmentedControl`），每段带数量；多于 4 个时用一个胶囊下拉菜单。筛选总是紧跟在搜索框右边。
4. **列表行统一成 `SettingsListRow`**：按 macOS 系统设置的「分组圆角列表」来做：一组放在一张圆角卡片里，行与行之间用细线分隔。行由「图标 + 标题/副标题 + 标签 + 尾部附件」组成，尾部附件固定 5 种：状态、开关、箭头、按钮、菜单。
5. **网格只给「发现」类页面用**（示例库）。凡是用户自己管理的数据（词库、关键词、技能、记忆、人设、模型服务）一律用列表。词库从网格卡片改为紧凑列表行。
6. **搜索行为统一**：输入时实时过滤，命中的文字高亮；分组保留标题并更新数量，空分组隐藏；没有结果时显示统一的空状态，并提供「清除搜索」。⌘F 聚焦搜索框，Esc 第一次清空、第二次失焦。

## 2. 搜索控件 `SettingsSearchField`

```
 ╭──────────────────────────────────────────╮
 │ 🔍  搜索模型或服务商           12 项   ⊗  │   30pt，胶囊
 ╰──────────────────────────────────────────╯
```

| 属性 | 规格 |
|---|---|
| 形状 | 胶囊（`Capsule`）。macOS 26 的搜索框和 Liquid Glass 控件都是胶囊形 |
| 高度 | A 位置 30pt（`SettingsControlMetrics.height`），B 位置 28pt |
| 宽度 | A：`minWidth 200`，`maxWidth 320`，随窗口伸缩；B：与列表栏同宽 |
| 填充 | `StudioTheme.controlSurface`。搜索框放在内容区，不放在悬浮层上，所以**不用玻璃**：玻璃只留给侧栏、工具条、弹出层 |
| 边框 | 常态 0.5pt `StudioTheme.border`；聚焦时 3pt 外圈 `accent` 30% 透明度的焦点环 + 1pt `accent` 描边（与系统焦点环一致，不再用 2pt 实线） |
| 图标 | `magnifyingglass` 12pt，`textTertiary`；聚焦时变为 `textSecondary` |
| 文字 | 13pt，占位文字统一为「搜索{对象}」，例如「搜索模型或服务商」「搜索词条」「搜索技能」 |
| 结果数 | 有输入时在右侧显示「N 项」（11pt，`textTertiary`），没有输入时不显示 |
| 清除 | 有输入时显示 `xmark.circle.fill`，点按清空并保持焦点 |
| 快捷键 | ⌘F 聚焦当前页面的搜索框；Esc：有内容时清空，没内容时失焦；↓ 把焦点移到第一条结果 |
| 首次出现 | 页面打开时不自动聚焦（沿用现在 `SettingsSearchBox` 的处理） |
| 无障碍 | `accessibilityLabel` 用占位文字；结果数变化时通过 `accessibilityValue` 读出 |

实现上是把现有的 `SettingsSearchBox` 改成这个规格并改名，加上 `placement: .toolbar / .sidebar` 和可选的 `resultCount`。

## 3. 摆放位置

### A. 页面工具条（整页列表）

```
 模型
 模型配置  语音识别  大语言模型                         ← Tab（不变）
 ┌───────────────────────────┐ ┌全部 21│已配置 4│未配置 17┐          [+ 添加自定义服务商]
 │🔍 搜索模型或服务商           │ └────────────────────────┘
 └───────────────────────────┘
 已配置 · 4 项
 ╭────────────────────────────────────────────────────────────────────────╮
 │ ▣ Typeflux Cloud                                           ● 已配置  ›  │
 │────────────────────────────────────────────────────────────────────────│
 │ ▣ 阿里云 ASR                                                ● 已配置  ›  │
 ╰────────────────────────────────────────────────────────────────────────╯
```

- 工具条在 Tab 下面，距 Tab 12pt，距第一个分组标题 16pt，**不再放在标题栏右上角**。
- 从左到右：搜索框 → 筛选 → 弹性空白 → 次要操作（如「更多」菜单）→ 主操作（蓝色，只放一个）。
- 窗口变窄时，筛选先收成下拉菜单，搜索框最后才缩小到 200pt。
- 适用于：模型（语音识别 / 大语言模型）、词库、技能、记忆、关键词。

### B. 列表栏顶部（左右分栏 / 选择器）

```
 ╭ 人设库 9            + 新建 ╮
 │ ╭──────────────────────╮  │
 │ │🔍 搜索名称或内容        │  │
 │ ╰──────────────────────╯  │
 │ 我的人设 · 7              │
 │  候选：英文口语化表达       │
 │  …                        │
```

- 搜索框在列表标题行下面，左右与列表行对齐，距标题 8pt、距第一行 10pt。
- 适用于：人设库、应用专属人设的应用选择器、示例库的分类栏、工作流编辑器的节点列表。

## 4. 筛选

- **不多于 4 个选项** → `StudioSegmentedControl`，每段写「名称 + 数量」，例如「全部 129｜自动 65｜手动 0｜其他应用 64」。数量随搜索更新，表示「这个筛选下能搜到几条」。
- **多于 4 个选项** → 胶囊下拉按钮（`SettingsActionMenu` 的样式），按钮上显示当前选项和数量，例如「全部 · 37 ⌄」。
- 筛选始终在搜索框**右边**。关键词页现在是在左边，要改过来。
- 搜索和筛选同时生效（取交集）。切换 Tab 时清空搜索，保留筛选。

## 5. 列表行 `SettingsListRow`

```
 ╭────────────────────────────────────────────────────────────────────╮
 │ ┌──┐ data-analysis  内置                               ◯━━  ›       │  两行：52pt
 │ └──┘ 用代码分析表格数据，报告经过验证的结果，可附图表。                    │
 │────────────────────────────────────────────────────────────────────│ ← 细线从标题左侧开始
 │ ┌──┐ 翻译  fy  tr  translate                           ◯━━  ›       │
 │ └──┘ 自动判断方向（简体中文 ↔ 英语）                                     │
 ╰────────────────────────────────────────────────────────────────────╯
```

| 部分 | 规格 |
|---|---|
| 分组卡片 | `ModelSurface`：`cardSurface` 填充，圆角 12，0.5pt 边框。分组标题用 `SettingsListSectionLabel`（12pt 半粗 + 「N 项」） |
| 行高 | 单行 36pt；带副标题 52pt；左右内边距 12pt |
| 前置图标 | 28×28 圆角 7 的色块里放 15pt 符号，或服务商图标。没有图标的数据（如词条）不留空位 |
| 标题 | 13pt 半粗，`textPrimary`，单行截断 |
| 标签 | 标题右侧的小胶囊（10.5pt，高 16pt）：「内置」「默认」「新」，以及关键词的触发词（等宽字体） |
| 副标题 | 11.5pt，`textSecondary`，最多 1 行；需要显示更多时放进详情 |
| 尾部附件 | 只有 5 种，最多放 2 个：**状态**（圆点 + 文字）、**开关**（`.toggleStyle(.switch)`，`controlSize(.mini)`）、**箭头**（`chevron.right`，表示可进入详情）、**按钮**（文字按钮，如「添加」）、**菜单**（`ellipsis`，悬停时显示） |
| 分隔线 | 0.5pt，从标题左侧开始到右边缘，最后一行没有 |
| 交互 | 悬停 `hover` 填充；整行可点（有箭头时进入详情）；开关和按钮不触发整行点击；选中行（B 位置的列表）用 `accentSoft` 填充 + 圆角 7 |
| 命中高亮 | 搜索词在标题和副标题里用 `accent` 色加粗（不用黄色底，避免在玻璃上发脏） |

### 紧凑行（词库）

词库的词条没有副标题，数量又多，用 30pt 的紧凑行：`词条 ……………… 来源标签  ⋯`。宽度超过 760pt 时自动分两列，两列都是同一个列表的延续（不是卡片网格）。来源（自动添加 / 手动添加 / 其他应用）用小标签显示，不再用前面的星形图标。

## 6. 空状态

- **列表本来就是空的**：图标 + 一句说明 + 主操作按钮（如「添加笔记」）。
- **搜索没有结果**：`magnifyingglass` 图标 + 「没有找到 "xxx"」+ 「清除搜索」按钮；如果当前有筛选，再加一个「在全部中搜索」。
- 空状态放在列表区域的垂直居中位置，不放在卡片里。

| 页面 | 位置 | 筛选 | 行 |

## 8. 实现计划（确认后执行）

一个 PR 交付：

1. `SettingsControls.swift`：`SettingsSearchBox` → `SettingsSearchField`（胶囊、焦点环、结果数、Esc 和 ↓ 行为、`placement`）；新增 `SettingsListRow`、`SettingsListGroup`、`SettingsFilterBar`、`SettingsSearchEmptyState`、命中高亮的 `Text` 构造函数。
2. 逐页替换 §7 的页面，删除自绘的搜索框和行。
3. 测试：搜索过滤和计数的纯函数单测（每页的过滤逻辑已经在 view model 里，抽成 `SettingsSearchMatcher`，覆盖大小写、中英文、空白、多字段匹配）；Esc / 清除行为的状态单测；用现有的截图流程（`docs/SCREENSHOTS.md`）出浅色 / 深色截图对比。
4. 文案：新增的「N 项」「没有找到」「清除搜索」「在全部中搜索」补齐中英文本地化。
