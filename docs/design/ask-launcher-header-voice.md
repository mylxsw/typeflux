# 随便问：启动器头部与语音输入 设计方案

> 状态：已确认并实现（GUL-214）。配套设计稿是 `docs/design/ask-launcher-header-voice.html`，截图在 `docs/design/ask-launcher-header-voice/`。

> GUL-235 更新：移除输入框左侧的应用/窗口名称和截图缩略图。鼠标悬停底栏截图按钮时显示已捕获图片，点击仍切换截图附加状态；保留原有截图和记忆图标，不新增底栏设置图标，上下文设置仍可用 ⌘K 打开。下文与设计稿保留 GUL-214 的历史方案。

> GUL-235 后续更新：悬浮启动器不再支持 `/` 命令或 ⌘/ 快捷键，输入框文案也移除命令提示；`/` 和 `、` 作为普通提问文本输入。聊天窗口仍支持 `/` 命令。

## 0. 一页结论

1. **启动器先是搜索框，然后才是 AI 输入框**。布局从「标签行 / 输入 / 工具栏 / 提示行」四层改成「输入行 / 结果 / 底栏」三层。空闲时外框从约 168pt 降到 100pt（输入行 58pt + 底栏 42pt）。
2. **来源和截图合成一个上下文标记**，放在输入框左侧：
   - 应用图标，加一个去掉应用名的短窗口标题（最宽 150pt），再加截图缩略图。
   - 开始输入后，标记只剩图标（约 64pt）。
   - 应用全名、开关、预览、「使用当前应用」都放进点开后的浮层（⌘K）。
3. **模型和工具放到底栏**，和按键提示合成一行，提示内容跟着高亮项变。
4. **语音输入不再调暗面板**：
   - 输入行变成录音行：音量圆点、实时转写、计时、取消、结束。
   - 结果区换成同样高度的聆听面板：用真实音量画波形，下面是怎么结束、怎么取消，再给两个示例说法。
   - 识别出的文字和手动输入走同一条快捷结果路径。

## 1. 现状问题（对照 issue 截图）

| # | 问题 | 原因 |
|---|------|------|
| H1 | 应用名占地方：`Google Chrome · Issues \| Multica - Google Chro…` | 标签同时显示应用名和完整窗口标题，而浏览器的窗口标题本来就以应用名结尾，等于显示了两遍。 |
| H2 | 标签单独占一行，输入框被挤到第二行 | `AskAttachmentStripView` 放在编辑器上方。 |
| H3 | 「整屏截图」单独一个标签 | 截图只是一个开关，用了和来源一样宽的标签。 |
| H4 | 不像一个能搜索的窗口 | 占位文字只写了「输入问题」，模型选择器在中间，权重比结果还高。 |
| V1 | 录音时面板像被禁用了 | `recordingDim` 把建议、工具栏和标签都降到 0.4 不透明度。 |
| V2 | 看不出「在听」 | `AskWaveform` 是固定动画，不跟音量走，状态挤在发送按钮旁边。 |
| V3 | 说完之前什么都看不到 | `AskVoiceInput` 只在结束后调用一次 `transcribe()`，没有中间结果。 |
| V4 | 边框杂乱 | 外圈蓝框，加上右下角一直在走的高光点（`AskVoiceBorder` 的 sheen）。 |

## 2. 新布局

```
┌──────────────────────────────────────────────────────────┐
│ [◉ Issues | Multica ▭ ⌄]  搜索应用、计算，或直接提问 · / 命令   🎙 ↑ │  输入行 58pt
├──────────────────────────────────────────────────────────┤
│  结果 / 起手建议 / 聆听面板                                   │
├──────────────────────────────────────────────────────────┤
│ ＋ MiniMax M3⌄ │ ◎ ✺ ☁                     ↩ 打开 · ⌘↩ 问 AI · esc │  底栏 42pt
└──────────────────────────────────────────────────────────┘
```

### 2.1 上下文标记 `AskContextToken`

- **组成**：
  - 应用图标 18pt。
  - 短标题：12.5pt，次要文字颜色，最宽 150pt，超出时尾部截断。
  - 分隔线。
  - 截图缩略图 27×18pt。
  - 展开箭头。
  - 有选中文字时，再加一段 `❝ 2 行`。
- **短标题规则**：
  - 去掉窗口标题结尾的 ` - <应用名>`、` — <应用名>`，以及中间的 ` - Google Chrome` 这类后缀。
  - 去掉后为空，就显示应用名。
  - 写成纯函数，方便测试。
- **收起**：输入框一有内容，就隐藏短标题，宽度过渡 0.18s；开启「减少动态效果」时直接切换。
- **状态**：

  | 状态 | 标记上的显示 |
  |------|------------|
  | 上次的来源 | 图标右下角加 🕘 角标，替代原来的「上次」文字 |
  | 关掉截图 | 缩略图加斜线并变淡 |
  | 正在截图 | 缩略图位置显示进度 |
  | 截图失败 | 缩略图换成 ⚠，标记描橙色边；浮层里有「去授权 / 重试」 |
  | 没有任何上下文 | 隐藏整个标记 |

- **交互**：
  - 点击标记或按 ⌘K，打开浮层。
  - 输入框为空时按 ⌫，先关掉截图，再按一次去掉来源。
  - ⌘Z 和现有的撤销提示都照常可用。
- **浮层**：
  - 来源、截图、选中文字各一行开关，截图带大图预览。
  - 最后一行是「使用当前应用（X）」。
  - 底部写隐私说明 `ask.context.source.metadataOnly`。
  - 复用现有的 `AskContextItem` 数据，不改附件模型。

### 2.2 输入行

- 编辑器字号 15 → 17pt，单行时高度 58pt。多行时输入行变高，上限照旧。
- 占位文字改成「搜索应用、计算，或直接提问 · / 命令」。追问输入框的占位文字不变。
- 右侧保留麦克风和发送按钮。只有高亮项是 AI 时，发送按钮才是实心蓝色；高亮项是本地结果时，↩ 执行本地动作。

### 2.3 结果区

- 结果加分组小标题：应用 / 计算 / 翻译 / AI。「问 AI」放在最后。
- 行组件（计算器、应用、翻译卡片）不用改。

### 2.4 底栏

- 左侧：＋、模型菜单、截图/记忆开关、隐私开关。沿用现有的 34pt 控件（和对话窗口共用），所以底栏是 42pt，上下各留 4pt。
- 右侧：原来独立的提示行（`ask.quick.hint*`），内容跟着高亮项变。
- 对话窗口（非启动器）的输入框继续用现在的工具栏，这次只改启动器外观。

### 2.5 图标按钮规范（启动器和对话窗口通用）

- 图标按钮（＋、存储位置、截图、记忆、麦克风、停止）不画圆形底色、描边或光晕，状态只体现在图标颜色上：
  - 开启：强调色。
  - 悬停：图标从次要文字色变成主文字色。
  - 录音中：麦克风变成强调色的停止方块。
- 发送按钮是主操作，暂时保留实心圆。

## 3. 语音输入

### 3.1 聆听中

- **录音行**：
  - 上下文标记的位置换成麦克风圆点，大小跟着音量变（0.9–1.15 倍）。
  - 输入区显示实时转写：已确定的部分是主文字颜色，还会变的尾巴是次要文字颜色。
  - 右侧依次是计时 `0:04`、✕ 取消、■ 结束（实心蓝色）。
- **聆听面板**：
  - 高度取原来的结果区高度，最小 140pt（不超过起手建议的高度），所以空启动器开始录音时面板不会跳。
  - 32 根柱的波形，取真实音量。
  - 一行操作说明：松开快捷键或点 ■ 结束，esc 取消。
  - 两个示例说法，用来说明这个窗口能做什么。
  - 底部一个小胶囊，写明哪些上下文会一起发送。
- **外框**：1px 蓝框加 3px 浅色外发光，去掉一直在走的高光点。
- **底栏**：工具沿用现有的 0.4 不透明度，提示改成「↩ 结束并填入 · esc 取消」。

### 3.2 识别中，以及不支持实时转写的服务

- 圆点换成进度环，输入区显示流光文字「正在识别…」，波形停住并变灰，■ 不可点。
- 服务不支持实时转写时（本机 Whisper、普通接口），聆听阶段输入区显示「正在听…」，波形照常跟着音量动。

### 3.3 结束后

- 文字写进输入框，和手动输入走同一条路径，快捷结果立即计算。说「打开 Warp」，第一条就是 Warp。
- 默认不自动发送。
- 出错时，输入行显示一行红色原因和「重试」，面板不关。

### 3.4 实现要点

- `AskVoiceRecording` 增加两个可选回调，默认空实现，现有调用方不用改：
  - `levelHandler(Float)`：转发 `WorkflowController` 已有的音量回调。
  - `partialTranscript(String, stable: Int)`：复用 `LiveTranscriptionPreviewer`。
- `AskVoiceInput` 发布两个新属性：`level` 和 `partial`。实时文字只在录音行里显示，**不写进编辑器**，直到最终结果出来，这样不会破坏现有的「原文没变才写入」检查。
- `AskWaveform` 改为读取 `level` 的环形缓冲。开启「减少动态效果」时显示静态柱。
- 启动器只在底栏工具上保留 `recordingDim`，建议和结果不再调暗，而是换成聆听面板。对话窗口保持不变。

## 4. 不做

- 不改附件、来源的数据模型和发送逻辑。
- 不改对话窗口的输入框布局。
- 不做语音唤醒，也不在识别后自动发送。

## 5. 验收

- 空闲启动器高度为 100pt（不含结果区）。窗口标题以应用名结尾时，不再重复显示应用名。
- 输入第一个字符后，标记宽度不超过 70pt。
- 录音时输入行和聆听面板保持完全不透明，只有底栏工具降到 0.4；波形跟着麦克风音量动；支持实时转写的服务在 300ms 内出现第一段文字。
- 短标题函数、⌫ 逐步去掉上下文、录音状态切换都有单元测试，新增代码覆盖率不低于 80%。
