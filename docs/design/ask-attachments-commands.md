# 随便问：附件上传与 `/` 命令 设计方案

> 状态：设计稿，待确认后再进入开发。配套可交互设计稿：`docs/design/ask-attachments-commands.html`（浏览器直接打开）。

> GUL-235 后续更新：下文保留原始方案；`/` 命令与 ⌘/ 入口现在只用于聊天窗口，悬浮启动器已移除命令支持及占位提示。

## 1. 背景与现状

当前「随便问」输入框（`AskComposer`，`Sources/Typeflux/Ask/AskComposerViews.swift`）分两层：

- 编辑行：多行文本 + 引用条（Quote pills）+ 附件条（只展示**会被发送**的内容，GUL-163）。
- 底栏：本机模式 · 模型菜单 · 思考强度 ┃ 上下文图标（截图 / 来源 / 选中文字 / 记忆）…… 用量环 · 麦克风 · 发送。

存在的问题：

1. **附件只有"自动截图"一种**。用户不能主动上传图片或文件，也不能临时让它读某个文件夹。数据结构上 `AskDraft.screenshot` / `AskSendRequest.image` 是**单个** data URL；服务端 `typeflux-api/internal/ask/engine.go` 只接受**一张 ≤ 2 MB 的 JPEG**，并以 base64 内联在消息里。
2. **没有命令入口**。新对话、切模型、思考强度、截图开关、记忆开关、搜索、设置……都散落在界面各处的按钮/菜单/快捷键里；已安装的 Skills 与 MCP 服务器用户只能"寄希望于模型自己用上"，无法显式指定。

参考对象（Osaurus）：输入框左下角 `+`（Attach Files / Add Folder）与 `/` 两个按钮；输入 `/` 弹出命令面板，带"built-in"标记、键位提示和 New Command 入口。

## 2. 设计目标

| # | 目标 | 不做（本期） |
|---|------|-------------|
| G1 | 能主动添加图片、文本类文件、PDF，支持多选、拖拽、粘贴 | Office 文档（docx/xlsx/pptx）直接解析、音视频 |
| G2 | 能把一个文件夹临时授权给本次对话（复用已有文件工具） | 整个文件夹打包上传 |
| G3 | `/` 命令统一承载界面上已有的操作，键盘可达 | 新增界面上本不存在的功能 |
| G4 | 已安装的 Skills、MCP 服务器出现在命令里，可显式指定本条消息使用 | 用户自定义命令（列为二期） |
| G5 | 启动器（Launcher）与工作区共用同一套交互（同一个 `AskComposer`） | — |

设计原则沿用现有约定：**看到什么就发送什么**（附件条 = 发送内容）；控件不因状态跳位；录音时其它控件让位（`recordingDim`）。

## 3. 入口布局

底栏最左侧新增两个圆形按钮，其余保持不动：

```
[＋] [／] │ 本机 · MiniMax M3 ▾ · 默认 ▾ ┃ 🖼 📄 🧠 …        2% 🎤 ⬆
```

- `＋`：附件菜单。快捷键 `⌘U`。
- `／`：打开命令面板（等价于在空输入框里键入 `/`）。快捷键 `⌘/`。
- 两个按钮与现有控件同高（`AskMetrics.composerControlHeight`），录音中同样变暗、禁用。

## 4. 附件

### 4.1 添加方式

| 方式 | 说明 |
|------|------|
| `＋` → **文件或图片…** | `NSOpenPanel`，多选；过滤为支持的类型 |
| `＋` → **文件夹…** | `NSOpenPanel` 选目录（应用未沙盒化，直接记录路径） |
| `＋` → **粘贴剪贴板图片** | 仅当剪贴板有图片时可用，否则置灰 |
| 粘贴：`⌘V`、右键菜单「粘贴」、编辑菜单「粘贴」/「粘贴并匹配样式」 | 三种入口走同一条路径。剪贴板里有文件（如在 Finder 中拷贝）或只有图片（如截图）时作为附件；同时有文字时按文字粘贴（Notes、Word 拷贝文字会附带一张图片，不能被误当成附件） |
| 拖拽到输入框 | 文件、文件夹、图片都作为附件；拖拽是明确意图，所以浏览器里拖出的图片即使带着网址文字也按图片处理；纯文字仍插入文本 |
| 拖拽到输入卡片其它位置或对话区 | 同上，卡片描边高亮，对话区显示虚线投放区 |
| `/file`、`/folder` | 见命令章节 |

屏幕截图仍由底栏现有的截图开关控制，`＋` 菜单里不重复。

### 4.2 支持类型与本地处理

所有处理在本机完成，**发送前不上传任何内容**。

| 类型 | 扩展名 | 处理 | 限制 |
|------|--------|------|------|
| 图片 | png jpg jpeg webp heic gif(首帧) tiff | 长边缩到 ≤ 2048 px，转 JPEG（质量 0.85），去掉 EXIF/GPS | 单条消息最多 **8 张**（含屏幕截图），每张压缩后 ≤ 2 MB |
| 文本/代码 | txt md csv tsv json yaml xml log html，及常见源码扩展名 | UTF-8 读取（失败尝试 GB18030），作为 `<attachment name=…>` 文本块 | 单文件原始 ≤ 5 MB，提取后 ≤ 200k 字符，超出截断并在卡片上标"已截断" |
| PDF | pdf | PDFKit 提取文字；无文字层（扫描件）且模型支持图片时，把前 8 页渲染成图片 | 同文本；页数显示在卡片上 |
| 文件夹 | 目录 | **不上传**。加入本次对话的文件工具根目录（`AskFileTools` roots），只读；写入走现有审批 | 每个对话最多 5 个 |
| 其它 | docx xlsx 等 | 卡片显示"暂不支持此格式"，不会被发送 | — |

单条消息附件总数上限 10 个（不含文件夹）。提取后的文字计入上下文用量环，加入附件后环会即时更新；预计超过模型上下文时，发送按钮禁用并提示"附件过大，请移除部分文件"。

### 4.3 附件条

沿用并扩展现有 `AskAttachmentStripView`（编辑行上方，横向滚动）：

- **图片**：56×56 圆角缩略图，悬停出现 `×`；点击 Quick Look 预览。屏幕截图仍是第一个，带"屏幕"角标。
- **文件**：图标 + 文件名（中间截断）+ 次要信息（`12 KB`、`PDF · 14 页`、`已截断`）。
- **文件夹**：文件夹图标 + 名称 + "只读"角标；悬停卡片显示完整路径。
- 状态：
  - 处理中：卡片上细进度条（大文件、PDF 渲染时）。
  - 失败：红色描边 + 原因（"文件过大"、"无法读取"、"暂不支持此格式"），可移除。
  - 当前模型不支持图片：图片卡片右上角黄色 ⚠，附件条下方出现提示条 `当前模型不能读取图片 · 切换到 GPT-5 mini`，点击即切换。本机模式下沿用 GUL-164 的规则自动挑选视觉模型（`AskVisionSwitch`），没有可用视觉模型时提示"没有能读取图片的模型"。
- 一键清空：附件 ≥ 3 个时末尾出现"全部移除"。

### 4.4 已发送消息

用户气泡上方显示附件：图片以网格缩略图（1 张大图 / 2–4 张 2 列 / 更多 3 列），文件以紧凑卡片。点击图片 Quick Look；点击文件卡片在 Finder 中显示（本机仍存在时）。"重新编辑/排队编辑"时附件随草稿一起恢复。

### 4.5 数据与接口改动（实现阶段参考）

客户端：

```swift
struct AskAttachment: Codable, Equatable, Sendable, Identifiable {
    enum Kind: String, Codable { case image, text, pdf, folder }
    var id: String
    var kind: Kind
    var name: String
    var byteSize: Int
    var image: String?      // JPEG data URL（image，或扫描版 PDF 的页面）
    var text: String?       // 提取的文字（text / pdf）
    var truncated: Bool?
    var bookmark: Data?     // folder：security-scoped bookmark，不发送到服务端
}
// AskDraft 增加 attachments: [AskAttachment]? ；草稿持久化时大块数据写入
// Application Support 下的缓存文件，草稿只保留引用，避免草稿 JSON 膨胀。
```

`AskSendRequest` 增加 `attachments`（不含 folder），现有 `image` 字段保留给屏幕截图，保证旧版本服务端兼容。

服务端（typeflux-api）：

- `SendRequest` / `Message` 增加 `Attachments`；校验数量、单张 ≤ 2 MB、文字总量。
- 图片不再内联进消息行：落对象存储，消息只存 key，构造 provider 消息时再签名或转 data URL（可参考 `feedback_report_images` 的存储方式）。
- `providerMessage` 把多图拼成多个 `image_url` part，文本附件拼成 `<attachment>` 块；`contextUsage` 计入附件。
- 本机模式（`AskLocalEngine`）同步支持多图与文本附件。

## 5. `/` 命令

### 5.1 触发

- 在**行首或空白之后**键入 `/` 时弹出；`a/b`、URL 路径、粘贴进来的 `/usr/bin` 不触发；语音转写出的文字不触发。
- 点击 `／` 按钮或 `⌘/`：在光标处插入 `/` 并弹出。
- 面板出现在输入框上方，宽度与输入框一致，最多显示约 7 行，超出滚动。启动器中面板出现时，暂时隐藏启动器建议列表。

### 5.2 键位

| 键 | 行为 |
|----|------|
| `↑` `↓` | 移动高亮（跳过禁用项，首尾循环，与启动器建议一致） |
| `↩` | 执行 / 进入二级 |
| `⇥` | 补全命令名（带参数的命令补全后等待输入参数） |
| `←` / `⌫`（二级列表中） | 返回上一级 |
| `esc` | **只关闭面板**，不关闭启动器/窗口；再按一次才是原有的关闭行为 |
| `⌫` 删掉 `/` | 关闭面板 |

### 5.3 匹配

按命令名、中文标题、别名做前缀 > 词首 > 子序列匹配（如 `/mo`、`/模型`、`/sw` 都能找到 `/model`）。命中字符高亮。无输入时顶部显示"最近使用"（最多 3 条），其余按分组排列。没有匹配时显示"没有匹配的命令 · 按 ↩ 直接发送"。

### 5.4 四种命令形态

| 形态 | 执行后 | 例子 |
|------|--------|------|
| **动作** | 立即执行，`/xxx` 从输入框移除 | `/new` `/search` `/settings` `/file` |
| **二级选择** | 面板切到子列表，选中后生效 | `/model` `/think` |
| **开关** | 切换状态，面板关闭，输入框上方短暂提示"已附带屏幕截图" | `/screenshot` `/memory` `/selection` `/local` |
| **标记** | 在输入框里插入一个胶囊（可用 `⌫` 整体删除），随本条消息发送 | 技能、MCP、快捷提问、`/remember` |

### 5.5 命令清单（第一期）

全部对应界面上**已存在**的功能；不可用时置灰并在右侧写明原因（例如"对话进行中"、"当前模型不支持图片"）。

**对话**

| 命令 | 说明 | 形态 | 对应现有功能 |
|------|------|------|-------------|
| `/new` | 新对话 | 动作 | ⌘N |
| `/search` | 搜索对话 | 动作 | ⌘K |
| `/title` | 重命名当前对话 | 动作（参数） | 侧栏重命名 |
| `/regenerate` | 重新生成上一条回答 | 动作 | 消息下方 ↻ |
| `/copy` | 复制上一条回答 | 动作 | 消息下方复制 |

**模型**

| 命令 | 说明 | 形态 |
|------|------|------|
| `/model` | 切换模型（二级：同模型菜单，含视觉标记、"随便问默认"标记） | 二级 |
| `/think` | 思考强度（二级：默认 / 低 / 中 / 高，随模型能力变化） | 二级 |
| `/local` | 切换本机模式 | 开关 |

**上下文与附件**

| 命令 | 说明 | 形态 |
|------|------|------|
| `/file` | 上传文件或图片 | 动作 |
| `/folder` | 添加文件夹（本次对话只读） | 动作 |
| `/screenshot` | 附带当前屏幕截图 | 开关 |
| `/selection` | 附带选中的文字 | 开关 |
| `/memory` | 本条使用记忆 | 开关 |
| `/remember <内容>` | 让随便问记住（写入 `AskMemoryNoteStore`） | 标记（参数） |

**快捷提问**（即启动器里的建议，`AskSuggestion.all`）

| 命令 | 插入 |
|------|------|
| `/explain-screen` | "讲讲这一屏在做什么"，并附带截图 |
| `/translate` | "翻译我选中的文字" |
| `/summarize-page` | "读一下这个网页并总结" |

**技能**（`AskSkillLibrary.skills()`，内置 + 用户安装）

- 每个技能一条：`/<skill-name>`，副标题为技能 description，角标"内置"或"已安装"。
- 选中后插入胶囊 `⚡ meeting-notes`。发送时请求带 `skills: ["meeting-notes"]`，服务端/本机引擎**直接把技能正文加载进本轮**，不再等模型自行决定调用 `skill` 工具。

**MCP**（`MCPRegistry` 中已启用的服务器）

- 每个服务器一条：`/<server>`，副标题显示工具数与连接状态（已连接 / 未连接 / 出错，后两者置灰）。
- 选中后插入胶囊 `🔌 github`。发送时请求带 `mcp_servers: ["github"]`，本轮**优先**提供该服务器的工具，并在系统提示里说明用户希望使用它。
- 服务器若声明了 MCP Prompts（`prompts/list`），以二级列表展示 `/<server>:<prompt>`，选中后把 prompt 内容插入输入框（带参数的按 prompt 定义逐个输入）。

**其它**

| 命令 | 说明 |
|------|------|
| `/help` | 列出全部命令与快捷键 |
| `/settings` | 打开随便问设置 |

面板底部常驻：左侧键位提示 `↑↓ 选择 · ↩ 执行 · ⇥ 补全 · esc 关闭`，右侧 `管理技能与 MCP →`（打开 Studio 对应页面）。

### 5.6 边界

- 对话进行中（`isBusy`）：`/model`、`/think`、`/regenerate` 置灰（与现有菜单禁用规则一致）；`/new`、`/search`、开关类可用；发送进入现有排队（GUL-151）。
- 正在编辑排队消息：动作类中会离开当前编辑的（`/new`、`/search`）先确认。
- 录音中：`/` 按钮禁用，面板不弹出。
- 技能/MCP 数量多：分组内超过 6 条折叠为"显示全部 N 个"，搜索时不折叠。
- 同名冲突：内置命令优先；技能/MCP 与内置同名时显示为 `/skill:<name>`、`/mcp:<name>`。
- 胶囊只在消息开头或任意位置均可，发送时从正文中剥离，作为结构化字段发送；正文为空但有胶囊和附件时也允许发送。

## 8. 实现说明（第一版）

开发中按现有代码做了以下取舍，与上文不同之处以此为准：

- **存储**：服务端目前把整段对话存成一个 JSON，截图本来就内联在消息里。第一版附件沿用这种方式，并限制每条消息的附件内容不超过 4 MB（请求体上限相应提高到 10 MB）。图片改存对象存储需要新的私有存储设施，作为后续任务。
- **附件条**：沿用现有附件条的胶囊样式（缩略图或图标 + 文件名 + 页数/已截断/只读），没有改成 56px 方块，以保持和截图、选中文字等胶囊一致。
- **附件错误**：无法添加的文件不进入附件条，在输入框下方用提示条说明原因（格式不支持、过大、无法读取、超出数量或大小）。
- **技能 / MCP**：选中后显示为附件条里的胶囊，而不是嵌在文字里；发送时技能连同其指令一起发送，模型无需再调用 `skill` 工具；MCP 服务器以提示的形式要求优先使用其工具。
- **触发**：除 `/` 外，中文输入法在斜杠键上输入的「、」也能打开命令面板（仅限行首或空白之后）。
- **未包含**：`/title`（目前没有重命名对话的功能）、MCP Prompts（客户端尚未实现 `prompts/list`）、自定义命令。
