# iOS：离线可用、本地模式与手动选模型（GUL-418）

交互设计稿：`docs/design/ios-offline-local-mode.html`。用浏览器打开后，顶部工具条可以切换服务状态（在线 / 服务不可用 / 无网络）、登录状态和明暗主题；在手机里可以直接点击操作，右侧会说明当前页面的规则。

本文是**规划方案**，确认后再拆成子任务执行，现在不改代码。

## 现状（代码核对结果）

| 问题 | 现在的行为 | 位置 |
|---|---|---|
| 服务端不可用 | `restore()` 之后马上 `refreshHome()`，列表、模型目录、账号信息都只来自网络；失败只显示一条错误，侧边栏是空的，模型目录为空时输入框直接提示“选择可用的云端模型”，什么都发不出去 | `Apps/iOS/TypefluxIOS/ChatStore.swift` |
| 历史记录 | 对话列表和对话内容只放在内存里，进程退出就没了；文档也写明“首版不承诺离线历史和草稿恢复” | `docs/IOS_CHAT.md` |
| 本地使用 | 不登录就不能发送（`send()` 未登录时直接弹登录）；没有自定义服务商，也没有设备端推理 | `ChatStore.send()` |
| 选模型 | 选择器已经能切换云端模型，但每次新对话都重置成目录第一项 `default`（即“Typeflux Cloud”，服务端按后台配置路由）；打开历史对话也不会恢复这段对话上次用的模型；没有“设为默认”；回答下方看不到实际用的是哪个模型（服务端消息已有 `model_ref` / `model_id`，iOS 没解码） | `ChatStore.changeSelection()`、`ChatModels.swift` |

Mac 端已经具备可复用的思路：`AskConversationCache`（sqlite3，按账号隔离）、`AskLocalMode` 的“云端 / 仅本机 / 临时”三种存储、`AskCustomInference` / `AskProviderInference` 的四种 API 风格（OpenAI 兼容、Anthropic、Gemini、Ollama）以及禁止重定向转发密钥的策略。

## 目标与原则

1. **服务端在不在线，App 都能打开、能浏览、能用。** 服务端不可用只影响“需要服务端的那一次请求”，报错要说清楚原因和替代办法，不能整页空白或卡死。
2. **云端历史在本机有副本。** 云端仍是唯一真源；本机副本只读展示、可搜索，联网后以服务端快照覆盖。
3. **不登录也能用。** 和 Mac 一样，配置自己的大模型服务商后，App 就是一个纯本地应用，对话只存本机。
4. **模型由用户决定。** “自动”保留为默认项，但用户可以手动选任何可用模型、设为默认，并在每条回答下看到实际使用的模型。
5. 不做自动重放：离线时发出的云端消息**不排队、不自动补发**（延续现有“不自动重放 POST”的规则，避免重复扣费和重复执行），只保留草稿，让用户手动重试。

## 方案

### 1. 本机存储层（基础）

- 新增 `ChatLocalStore`（放在 `Packages/TypefluxChat`，用系统自带的 `SQLite3`，不引入新依赖，可以直接 `swift test` 覆盖）。表结构参照 Mac `AskConversationCache`：`conversations(owner, id, storage, title, updated_at, revision, model_ref, data)`、`drafts(owner, conversation_id, text, image)`、`catalog(owner, kind, data, fetched_at)`、`account(owner, profile, credits, fetched_at)`。
- `owner`：登录账号的 user ID；本地模式用固定的 `local`。退出登录和注销账号时删除该账号的云端副本；`local` 的数据不随账号变化。
- `storage`：`cloud`（云端副本）或 `local`（仅本机，真源就是这里）。
- 写入时机：列表刷新、打开对话、运行结束、收到 SSE 快照时按 `revision` 只增不减地写入（与内存里的 `accept()` 规则一致）。
- 容量：云端副本默认保留最近 200 段对话的完整内容，更早的只留标题；图片 data URL 单独存文件并设上限。设置里显示占用并可“清除本机缓存”（只清云端副本，不清本机对话）。
- 安全：数据库与图片目录使用 `FileProtectionType.completeUntilFirstUserAuthentication`；云端副本标记为不备份（可重新下载），本机对话参与备份。

### 2. 服务端不可用时的行为

新增连接状态 `ChatConnectivity`：`online / serverUnavailable / offline`。`NWPathMonitor` 判断设备是否联网；请求的传输错误、超时、5xx 判定为服务不可用；401 仍按现有逻辑处理，**网络错误绝不导致退出登录**。

| 场景 | 表现 |
|---|---|
| 启动 | 先从本机副本渲染侧边栏、模型目录和账号卡片，再后台刷新；刷新失败只在顶部显示一条可关闭的横条“Typeflux 服务暂不可用，正在显示本机副本 · 重试” |
| 浏览历史 | 打开对话先显示副本，标题胶囊下方小字“离线副本 · 更新于 10:42”；能复制、分享、搜索 |
| 云端对话发送 / 重新生成 / 继续 | 请求失败后在输入框上方显示错误卡片：“服务暂不可用，消息没有发出，草稿已保留。”按钮：重试、改用我的模型（如果已配置服务商，会新开一段本机对话并带上草稿） |
| 运行中断线 | 沿用现有重连退避；超过次数后显示“实时更新已暂停”，回到前台或联网后自动刷新快照 |
| 积分 / 购买 | 显示上次的余额和“更新于”；购买入口在服务不可用时置灰并说明原因（StoreKit 交易本身照常排队到下次在线发放，现有逻辑已支持） |
| 本机对话 | 完全不受影响，直接调用用户配置的服务商 |
| 恢复联网 | 自动刷新列表与当前对话；横条消失；不自动发送任何东西 |

草稿持久化：每段对话（含新对话）的草稿和待发图片写入 `drafts`，进程被杀也能恢复。

### 3. 本地模式：配置自己的服务商

- **入口**：首次启动的欢迎页增加第二个按钮“使用自己的模型（无需账号）”；设置 → 模型服务商；模型选择器底部“添加服务商”。
- **支持的类型**：OpenAI、Anthropic、Google Gemini、DeepSeek、OpenRouter、通义千问（DashScope）、Moonshot、Ollama / LM Studio（局域网）、自定义 OpenAI 兼容地址。前七个是预设地址的 OpenAI 兼容或原生协议，后两个需要填地址。
- **配置流程**：选类型 → 填地址（预设类型自动填好）和 API Key → “测试并获取模型”（调用 `/models`、Anthropic / Gemini 原生目录、Ollama `/api/tags`）→ 勾选要显示的模型，可标记“支持图片”“支持推理强度” → 保存。
- **密钥**：Keychain，`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`，不同步、不进备份、不上传服务器；请求禁止重定向（沿用 Mac `AskModelRedirectPolicy`）；局域网 HTTP 只允许私有地址，并在 Info.plist 增加 `NSAllowsLocalNetworking` 与本地网络权限说明。
- **推理**：设备直连服务商，流式输出；与云端对话共用同一套消息渲染、思考时间、复制 / 分享 / 重新生成。v1 不提供工具（网页搜索等），选择器里注明。标题用同一模型在第二轮回复后生成一次（对齐 Mac）。
- **代码组织**：四种协议的请求编码与流式解析放进 `TypefluxChat` 的新模块 `ChatProviders`，带单元测试；Mac 端在本项目中**不迁移**，避免回归，之后可单独评估合并。

### 4. 存储与模型的关系

延续 Mac 的规则：**存储位置在第一条消息前决定，之后不可更改。**

| 选择的模型 | 对话存在哪里 | 侧边栏图标 |
|---|---|---|
| Typeflux Cloud（自动或具体云端模型） | 云端，多设备同步，本机有副本 | 无（默认） |
| 我的服务商的模型 | 仅本机，不同步到 Mac / Web | 🔒 |

- 已开始的云端对话只能在云端模型之间切换；本机对话只能在“我的模型”之间切换（选择器里另一组置灰并说明原因）。
- 侧边栏增加“全部 / 云端 / 本机”筛选（与 Mac `AskHistoryFilter` 一致，只有两种对话都存在时才显示）。
- 未登录时只有本机对话；登录后两者并存，本机对话不会被上传。

### 5. 手动选择模型

- **选择器分组**：自动（Typeflux 推荐，由后台路由）/ Typeflux Cloud 各模型（显示倍率、图片能力，沿用现有行）/ 我的服务商（按服务商分组）。底部“添加服务商”。
- **设为默认**：选择器里的模型行可“设为默认”，设置里也有“默认模型”一项；新对话使用默认模型，不再固定为目录第一项。
- **按对话记住**：每段对话记住最后使用的模型（写入本机 `model_ref`，云端对话还可从服务端消息的 `model_ref` 推断），重新打开时恢复。
- **不可用的处理**：默认模型被后台下架、服务不可用、密钥失效时，不静默替换；输入框上方说明原因并提供“改用自动”或“去设置”。
- **显示实际模型**：解码消息的 `model_ref` / `model_id`，在回答的操作行显示模型名（选“自动”时也能看到实际路由到的模型）。

### 6. 其他新功能的移动端支持（建议候选，按需勾选）

| 功能 | 服务端现状 | 建议 |
|---|---|---|
| 临时对话（GUL-370） | API 已支持 `temporary` 与 `/keep` | 新对话菜单增加“临时对话”，不进历史、不写本机副本 |
| 重命名对话 | API 已支持 | 侧边栏长按 / 左滑菜单增加“重命名” |
| 回答实际模型 | 消息已带 `model_ref` | 见第 5 节 |

图片生成、记忆、技能、笔记引用等依赖桌面能力或更大交互改动，不放进本次范围。

| 阶段 | 子任务 | 依赖 | 主要改动 |
|---|---|---|---|

## 验证

- `swift test --package-path Packages/TypefluxChat --enable-code-coverage`：存储层（迁移、owner 隔离、revision 只增、容量淘汰、退出清理）与四种协议的编码 / 流式解析（`URLProtocol` 桩）覆盖率 > 80%。
- `make ios-test`：`ChatStore` 用会抛 `URLError` / 5xx 的假服务覆盖启动、浏览、发送失败、恢复联网、不退出登录、不自动重放；UI 测试在 `--synthetic-preview` 下增加“服务不可用”和“本地模式”两套离线场景。
- 真机：飞行模式、服务端停机（本地 Docker 停掉 API）、局域网 Ollama 三种场景手动验收。

## 需要你确认的问题

1. **“后台模型切换”的理解**：我的理解是后台（Dashboard 的 Cloud models / 路由）已经能配置多个模型，iOS 默认用“自动”由后台决定，你希望用户能手动选、设默认、并看到实际模型。如果你指的是别的（比如语音输入也要能选云端识别模型），请说明。
2. 本机对话 v1 **不带网页搜索等工具**，可以接受吗？
3. 云端副本默认保留 **最近 200 段**完整内容，是否合适？
4. 第 6 节的临时对话、重命名是否放进本次？
