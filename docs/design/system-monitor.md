# 系统监控：启动器内置关键字 + 可常驻的独立窗口（GUL-323）

> 状态：设计稿，待确认。配套可交互设计稿：`docs/design/system-monitor.html`（`?s=<id>` 打开某一屏，`?light=1` 浅色，`?solo=1` 只显示一屏，`?still=1` 停止刷新便于截图）。截图在 `docs/design/system-monitor/`：`hint` `overview` `cpu` `mem` `kill` `alert` `full` `compact` `mini` `menu`，以及 `light-*`。
>
> 这一阶段只出设计，不改代码。设计稿里的数据是模拟的，每秒刷新一次。

## 0. 一页结论

| | 方案 |
|---|---|
| 入口 | 新的内置关键字 **`top`** / **`监控`**（可以在关键字页改名、加别名）。输入关键字后，结果的第一行就显示 CPU、内存、磁盘、网络的实时摘要；按 ↩ 进入 |
| 启动器里 | 4 张指标卡（数值 + 最近 60 秒折线）+ 进程列表。输入框用来筛选进程。点卡片、⌘1–⌘4 或 ⇥ 可以**聚焦**某一项，展开详情 |
| 进程 | 按 CPU / 内存 / 磁盘排序；↑↓ 选择，↩ 切换到该应用，⌘C 复制 PID，⌘⌫ 结束（⌥ 强制结束），确认在同一行里完成 |
| 独立窗口 | **⌘O**（和结果窗口的 ⌘O 一致）把监控拿出启动器，变成一个默认**置顶、不抢焦点、在所有桌面显示**的小窗口。有 3 种形态：**完整 / 紧凑 / 迷你条** |
| 常驻 | 窗口的位置、大小、形态和选项都会记住；可以设置「下次启动时恢复此窗口」 |
| 告警 | CPU 持续高于 90%，或者内存压力变高时，卡片变色，并且用一行文字说明主要是哪个进程造成的。第一版不发系统通知 |

## 1. 现在的基础

- 启动器的关键字插件实现 `AskLauncherPlugin` 协议。有一类插件「只输入关键字时按 ↩ 进入本地功能」（`entersOnReturn`），例如剪贴板 `clip`、笔记 `nb`，系统监控也属于这一类。
- 结果窗口（`AskResultWindowController`）已经有「⌘O 从启动器拿出来变成独立窗口」和「置顶」（`pinned` → `window.level = .floating`）这两个现成的做法，独立监控窗口沿用同样的交互习惯。
- 启动器宽度固定为 680（`AskMetrics.launcherWidth`），高度由 `AskLauncherHeightAnimator` 跟着内容变化。
- App 没有开沙盒，可以直接读取系统统计数据（见 §5），不需要新增权限。

## 2. 需求理解

1. 在启动器里输入关键字并确认后，显示系统的运行状态：CPU、内存、磁盘、网络，以及进程信息。
2. 按一个键就能把监控**拿出来**，变成独立窗口，不影响用户继续使用启动器和其他应用；这个窗口可以一直浮在桌面上，实时刷新。
3. 这一阶段先出 UI 样式和交互设计，而且设计稿要能交互。

## 3. 启动器中的监控

### 3.1 输入关键字（截图 `hint`）

- 输入 `top` 或 `监控`，「关键字」区的第一行就是「系统监控」。副标题直接显示实时摘要：`CPU 23% · 内存 65% · 磁盘 62% · ↓ 6.3 MB/s ↑ 181 KB/s`，右侧是一条 CPU 折线。用户不用进入，也能先看一眼。
- ↩ 进入；输入「`top` + 空格」会直接进入，空格后面的文字就是进程筛选条件（`top chrome`）。这和其他关键字的规则一致（`AskKeywordMatcher`）。
- 「活动监视器」照常出现在应用结果里，不会被关键字挡住。

### 3.2 概览（截图 `overview`）

从上到下：

1. **输入行**：关键字标签 `系统监控`（青色，`gauge` 图标）+ 输入框（占位文字「筛选进程：名称或 PID」）+ 右上角按钮「独立窗口 ⌘O」。
2. **状态行**：`● 实时 · 每 1 秒 · MacBook Pro · M3 Pro · 36 GB`，右侧是已运行时间、电池、散热状态（`ProcessInfo.thermalState`）。
3. **4 张指标卡**，每张卡片显示：名称 + 快捷键提示 ⌘1–⌘4、主数值、一行补充说明，底部是最近 60 秒的折线：

| 卡片 | 主数值 | 补充说明 | 折线 |
|---|---|---|---|
| CPU | 总使用率 % | 核心数 · 1 分钟平均负载 | 使用率 |
| 内存 | 已用 %，名称旁有内存压力圆点（绿 / 橙 / 红） | 已用 / 总量 GB | 使用率 |
| 磁盘 | 启动磁盘已用 % | 读 / 写速度 | 读（青色）+ 写（橙色） |
| 网络 | 下载速度 | 上传速度 · 网络接口 | 下载（绿色）+ 上传（橙色） |

4. **进程列表**：表头右侧可以按 CPU / 内存 / 磁盘排序（也可以直接点列名）。列包括：图标 + 名称（系统进程标「系统」）、CPU、内存、磁盘读写、PID。默认显示前 8 个，聚焦某一项时显示前 5 个。CPU ≥ 40% 显示橙色，≥ 100%（超过一个核）显示红色。
5. **底栏**：`↑↓ 选择进程 · ⌘⌫ 结束 · ⇥ 切换指标 … ⌘O 独立窗口 · esc 返回`。

**排序暂停**：每秒重新排序会让行跳来跳去，用户点不准。所以当鼠标停在列表上、用 ↑↓ 选择后的 3 秒内，或者正在确认结束进程时，**只更新数值，不重新排序**，表头会显示「⏸ 排序已暂停」。

### 3.3 聚焦某一项（截图 `cpu` `mem`）

点卡片、⌘1–⌘4，或者按 ⇥ / ⇧⇥ 循环切换（不聚焦 → CPU → 内存 → 磁盘 → 网络）。被聚焦的卡片会显示描边，关键字标签变成 `系统监控 → CPU`。卡片下方展开详情，进程列表也会自动按这一项排序：

| 聚焦 | 左：60 秒大图 | 右：明细 |
|---|---|---|
| CPU | 使用率 | 每个核心的柱状图（分性能核和能效核）、用户 / 系统占比、1 / 5 / 15 分钟平均负载、进程数 / 线程数、散热状态 |
| 内存 | 使用率 | App 内存 / 联动内存 / 被压缩 / 缓存文件的堆叠条、内存压力、已用交换 |
| 磁盘 | 读写速度 | 每个宗卷的容量条和剩余空间（包括外接盘和 Time Machine） |
| 网络 | 上下行速度 | 网络接口、本机 IP、开机以来的累计流量、60 秒内的峰值 |

内存的颜色和 macOS 一样，**看内存压力，不看占用百分比**：缓存把内存占满是正常现象，不应该显示成红色。再点一次卡片或按 esc 可以收起详情。

### 3.4 进程操作（截图 `kill`）

- 选中一行后（点击或 ↑↓），这一行会显示 PID、CPU、内存，以及几个操作按钮：**切换到应用 ↩**（不是 App 的进程显示为「在访达中显示」）、**复制 PID ⌘C**、**结束 ⌘⌫**。
- 结束进程前，会在**同一行**里确认：「结束『Google Chrome』？会请它正常退出，可能弹出保存提示」，↩ 确认，esc 取消。按住 ⌥（⌥⌘⌫）是强制结束，提示文字会改成「会立即退出，未保存的内容会丢失」。
- 实现方式：App 用 `NSRunningApplication.terminate()` / `forceTerminate()`，其他进程用 `kill(pid, SIGTERM / SIGKILL)`。
- 系统进程（`root` 或其他用户的进程，以及 `kernel_task`、`WindowServer` 等）的「结束」按钮不可用，按 ⌘⌫ 时会提示「…是系统进程，不能从这里结束」。Typeflux 自己也不能结束。
- 筛选：输入框里的文字匹配进程名称（不区分大小写）或完整 PID。没有匹配时显示「没有名称或 PID 匹配『x』的进程」。

### 3.5 高负载（截图 `alert`）

- 阈值：CPU ≥ 80% 显示橙色，≥ 90% 显示红色；内存按压力显示（正常、偏高、紧张）。
- CPU 持续 30 秒以上高于 90% 时，卡片下方出现一行说明：「CPU 已持续 30 秒高于 90%，主要来自 **node**（PID 4821，367%）」，旁边有「查看进程」按钮，点了会直接选中这个进程。
- 第一版只在监控界面里提示，不发系统通知（见 §7 待确认）。

### 3.6 esc 和退格

esc 按下面的顺序逐层退出：取消结束进程的确认 → 取消选中 → 收起聚焦 → 清空筛选文字 → 退出关键字（回到启动器首页）→ 关闭启动器。筛选框为空时按 ⌫ 也会退出关键字，和其他关键字一样。

## 4. 独立窗口

### 4.1 拿出来（截图 `full`）

- 在启动器里按 **⌘O**，或者点右上角「独立窗口」：启动器收起，同时出现监控窗口（带缩放动画），并提示「已在独立窗口中常驻显示」。窗口会继承当前聚焦的指标，用来决定进程列表的排序。
- 默认放在屏幕右上角；之后都放在用户上次拖到的位置（按显示器分别记住）。
- 窗口已经打开时，再进入 `top`，按钮会变成「**前往窗口** ⌘O」：启动器收起，窗口描边闪一下，提示它在哪里。监控窗口**只有一个**。
- 窗口特性：`NSPanel` + `.nonactivatingPanel`（点它不会抢走当前应用的焦点）、默认 `.floating`（置顶）、`collectionBehavior` 包含 `.canJoinAllSpaces` 和 `.fullScreenAuxiliary`（切换桌面、全屏时都在）、按住任意位置都能拖动。

### 4.2 三种形态

标题栏中间有一个分段控件，可以在三种形态之间切换：

| 形态 | 尺寸 | 内容 | 适合 |
|---|---|---|---|
| **完整**（`full`） | 380 宽，可以调整大小 | 4 行指标（名称 · 折线 · 数值 + 补充说明）+ 前 6 个进程（按 CPU / 内存排序） | 排查问题时放在旁边 |
| **紧凑**（`compact`） | 272 × 约 170 | 2×2 小卡片：数值 + 折线。标题栏平时隐藏，鼠标移上去才显示 | 长期放在屏幕角落 |
| **迷你条**（`mini`） | 一条胶囊，约 32 高 | `CPU 15% ～ · 内存 68% · 磁盘 26M · ↓ 3.0M ↑ 109K`。鼠标移上去会出现「展开」和「选项」按钮，双击展开成完整形态 | 贴在菜单栏下面，几乎不占地方 |

- 点完整形态里的任意一行指标，会打开启动器并聚焦这一项，方便查看详情、结束进程。独立窗口本身**不提供**结束进程的操作，避免误点。
- 颜色规则和启动器一致：数值超过阈值时变成橙色或红色，紧凑卡片会加一层浅红背景。

### 4.3 置顶与窗口选项（截图 `menu`）

- 标题栏的 📌 用来切换置顶（`⌘⇧T`）。取消置顶后，监控窗口就是普通窗口，会被其他窗口盖住。在设计稿里点左侧的代码窗口可以看到区别。
- `···` 菜单：
  - 置顶显示 ✓
  - 在所有桌面上显示 ✓
  - 下次启动时恢复此窗口 ✓（默认打开：用户把监控拿出来，通常就是想让它一直在）
  - 显示项目：CPU / 内存 / 磁盘 / 网络（多选）
  - 刷新频率：1 / 2 / 5 秒（默认 1 秒）
  - 不透明度：100% / 85% / 70%
  - 在启动器中打开 · 打开「活动监视器」· 关闭窗口 ⌘W
- 关闭窗口后，提示「在启动器输入 top 可再次打开」。「下次启动时恢复」这一项记录的是窗口关闭时的状态：窗口开着退出 App，下次启动会恢复；手动关掉了，下次就不打开。

## 5. 数据与实现（确认设计后）

### 5.1 数据来源（都不需要额外权限）

| 指标 | API |
|---|---|
| CPU 总量 / 每个核心 | `host_processor_info(PROCESSOR_CPU_LOAD_INFO)`，用两次采样的 tick 差值计算；性能核和能效核的数量来自 `sysctl hw.perflevel0/1.logicalcpu` |
| 平均负载 | `getloadavg` |
| 内存 | `host_statistics64(HOST_VM_INFO64)`（App 内存、联动内存、被压缩、缓存文件）；压力来自 `sysctl kern.memorystatus_vm_pressure_level`；交换来自 `sysctl vm.swapusage` |
| 磁盘容量 | `URLResourceValues.volumeTotalCapacity` / `volumeAvailableCapacityForImportantUsage`，宗卷列表来自 `FileManager.mountedVolumeURLs` |
| 磁盘读写 | IOKit `IOBlockStorageDriver` 的 `Statistics`（读写的字节数），用差值计算速度 |
| 网络 | `getifaddrs` 的 `if_data.ifi_ibytes / ifi_obytes`，用差值计算速度；默认接口由 `SCDynamicStore` / `NWPathMonitor` 获得 |
| 进程 | `proc_listallpids` + `proc_pidinfo(PROC_PIDTASKINFO)`（CPU 时间、内存）+ `proc_pid_rusage`（磁盘读写），用两次采样的差值计算；名称和图标优先用 `NSRunningApplication`，没有时用 `proc_name` |
| 其他 | 已运行时间 `sysctl kern.boottime`、电池 `IOPSCopyPowerSourcesInfo`、散热 `ProcessInfo.thermalState` |

读不到其他用户进程的详细数据时，对应的列显示「—」，不报错。

### 5.2 结构

| 步骤 | 改动 | 主要文件 |
|---|---|---|
| M1 采样 | 协议 `SystemMetricsSampling`，生产实现 `DarwinSystemMetricsSampler`；纯逻辑的 `SystemMetricsCalculator` 负责把两次原始计数换算成速度和百分比（方便测试） | `Sources/Typeflux/SystemMonitor/` 新目录 |
| M2 共享数据 | `SystemMonitorStore`（`@MainActor ObservableObject`）：60 个点的环形缓冲、阈值状态、持续高负载检测、排序和暂停排序逻辑。启动器和独立窗口**共用同一份**数据 | 同上 |
| M3 插件 | `AskSystemMonitorPlugin`（`entersOnReturn = true`，`runsWithoutInput = true`，`usesSelectionInput = false`），默认关键字 `top` / `监控`，英文名 `systemmonitor`；hint 行显示实时摘要 | `Ask/QuickResults/Plugins/SystemMonitor/` |
| M4 启动器界面 | `SystemMonitorLauncherView`：指标卡、聚焦详情、进程列表、按键处理（↑↓ ⇥ ⌘1–4 ⌘⌫ ⌘C ⌘O esc） | 同上 |
| M5 独立窗口 | `SystemMonitorWindowController`（只有一个实例的 `NSPanel`）+ 三种形态的视图；位置、形态、选项存到 `SettingsStore`（`systemMonitor.window.json`）；启动时按「恢复」选项打开 | `SystemMonitor/` |
| M6 结束进程 | `ProcessTerminator`：判断进程能不能结束（系统进程、其他用户的进程、Typeflux 自己都不能），然后选择 terminate 或 signal | `SystemMonitor/` |

### 5.3 性能与资源

- **只在看得见的时候采样**：启动器里的监控界面关掉、独立窗口也没有打开时，计时器完全停止。窗口被完全遮住（`occlusionState` 不可见）或者屏幕锁定时，降到每 5 秒一次。
- 进程采样比较重：只在启动器显示进程列表，或者完整形态的独立窗口打开时才采样；紧凑形态和迷你条只采系统总量。
- 目标：1 秒刷新时，Typeflux 自身的 CPU 占用 < 1%。采样放在后台队列，只在主线程更新界面。
- 定时器、IOKit 迭代器、`getifaddrs` 返回的链表都要在使用后释放；窗口关闭时释放 store 的订阅。

### 5.4 测试

- 纯逻辑类型（差值换算、计数器回绕或重置、阈值和持续高负载检测、排序暂停、筛选、能否结束的判断、窗口选项编解码）全部写单元测试，覆盖率按项目要求（≥ 90%），采样器用假数据注入。
- 界面按 `LauncherSettingsPolishTests` 的做法输出深色、浅色截图；中文简体、中文繁体、英文、日文的本地化同步更新。

## 7. 待确认

1. **关键字**：建议用 `top` + `监控`。也可以考虑 `sys` / `mon`。是否同意？
2. **结束进程**：第一版是否包含？包含的话，只能在启动器里操作，而且需要确认；系统进程不能结束。
3. **独立窗口的形态**：第一版做完整、紧凑、迷你条三种，还是先只做完整和迷你条？
4. **菜单栏数值**（在菜单栏图标旁显示 CPU 和内存）：这一版不做。迷你条已经覆盖了「随时看一眼」的需求，以后可以作为第四种形态加进来。
5. **系统通知**：持续高负载时是否发 macOS 通知？建议第一版不做，避免打扰。
6. **GPU / 温度传感器**：需要使用私有 API 或 SMC，这一版不做，只显示散热状态。
