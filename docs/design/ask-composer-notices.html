随便问 · 输入框提示信息重新设计

问题：「已切换到 coding/auto」这类提示统一用 AskBanner 堆在输入框下方。它会把输入框往上顶，还盖住了下面那行快捷键提示（截图红框处两行文字叠在一起）。模型切换、思考强度、截图、附件失败、语音出错、对话失败等七八种信息都挤在这一处，用户分不清哪条提示对应哪个操作。
方案：输入框下方不再显示任何内容。每条信息按它说的是什么，放回它所属的位置：状态确认在对应控件上就地反馈，需要处理的问题放进卡片内部的提示条，对话级事件写进对话流，快捷键说明改到占位符和悬停提示里。聊天页输入框和快捷浮窗（launcher）共用这套规则。

现状（Issue 截图）

现状问题

  • 位置不对：提示和造成它的控件离得很远。切换的是左下角的模型按钮，确认却出现在整张卡片下方。
  • 布局跳动：每出现一条 banner，AskComposer 的 VStack 就增高一截，输入框往上顶，对话内容也跟着移动。2 秒后提示消失，又跳回去。
  • 和快捷键提示重叠：AskComposerHint（↩ 发送 · ⇧↩ 换行 · 按住 ⌥(R) 语音输入）固定在最底部，和 banner 叠在一起，两边都看不清。
  • 重复：「已切换到 coding/auto」只是在复述底栏模型按钮上已经显示的内容。
  • 所有提示长得一样：成功确认、要处理的警告、可以撤销的自动切换，都用同一种灰色条。最多能同时叠 5 条（截图提示、命令反馈、附件、语音、错误）。

整体变化

  • 截图里是刚通过 / 命令切到 coding/auto 的那一刻：模型按钮本身变成蓝色软底和描边，名字后面加一个 ✓。1.6s 后恢复正常样式。眼睛本来就在看这个位置，不需要再读一行字。

规则

  • 改了哪个状态，就在哪个控件上反馈。runCommand 不再调用 confirm(text)，改为 pulse(.model / .reasoning / .local / .screenshot / .selection / .memory)。底栏用 model.pulse 判断哪个控件需要高亮。
  • 动效：0→120ms 描边和软底淡入，✓ 从 0.6 缩放到 1；保持 1.2s；再用 300ms 淡出。开启「减少动态效果」时去掉缩放，只保留颜色变化。
  • 无障碍：视觉上没有文字了，但仍然通过 NSAccessibility.post(.announcementRequested) 把原来的确认文案（如「已切换到 coding/auto」）读给 VoiceOver。现有本地化 key 全部保留，作为播报文案使用。
  • B3 小胶囊放在底栏 spacer 里，靠右对齐，紧贴麦克风。宽度不够时（launcher 很窄、底栏控件很多）只显示 ✓ 图标，悬停可看文字。它不会改变卡片高度。
  • 连续触发时，后一次直接替换前一次，不排队。和现在 confirm 的“新的覆盖旧的”语义一致。

C3 · 语音出错：麦克风按钮变红 + 提示条；同时有多条提示时只显示一条，其余收进「+1 条提示」

规则

  • 位置：在卡片内部、编辑区上方，和 AskQueueEditingHeader、附件条同一层。距离卡片左右各 8pt，圆角 11，高度 34。它属于输入框本身，不会落到卡片外面。
  • 只放需要用户知道或处理的事：被自动撤销的选择、被拒的附件、语音或发送失败。成功类确认一律不进这里。
  • 双重标记：提示条说明原因，来源控件同时显示状态（截图 chip 的 ! 角标、红色麦克风、橙色幽灵附件）。用户关掉提示条后，控件上的状态仍然保留，悬停可再次看到原因。
  • 同一时间最多一条。优先级：发送错误 > 语音 > 附件 > 截图。其余条数在底栏显示为「+N 条提示」，点击展开成列表。现在的实现会同时叠出最多 5 条，这是布局跳动的主要原因。
  • 关闭方式：提示条有 ×；导致它的状态被修正后自动消失（换回识图模型、重新授权麦克风、移除了出问题的附件），不需要额外等待。
  • 提示条展开或收起时，卡片向上长（底边保持不动），沿用 0.25s spring 动画。输入光标和底栏都不移动。

规则

  • 自动切换识图模型（visionSwitch）记录的是「这条对话从哪一条开始换了模型」，属于对话历史，所以写成对话流中的一行系统分隔线。「改回 X」在下一条消息发出前都能点；发出后链接变成普通文字，只作记录。
  • 失败、停止、未完成（error、run.status == failed/cancelled、resumable）对应的是某一条回答，所以作为卡片附在那条回答末尾。「重试 / 继续处理」就在出错位置，不用再去输入框附近找。

  • 选中会话加载失败（selectionLoadFailed）不是某条回答的问题，改为在对话区居中显示空状态：「加载失败 · 重试」。
