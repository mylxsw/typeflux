现状问题

  1. 「工具」Tab 是大杂烩：一个滚动页里塞了联网搜索（含完整 Cloudflare 表单）、文件访问、代码执行、启动器计算器 / 应用搜索、启动器关键字、启动器工作流、操作电脑权限，共 7 类，其中 4 类跟 Agent 无关。
  2. 三层导航：一级侧栏 → Tab → 「扩展」里的二级分段控件（技能 / MCP），MCP 还是另一套代码渲染，头部与动作区不一致。
  3. 概览与正文重复：6 张能力卡只做跳转，与 Tab 内容重复；状态只在概览和 Tab 小红点出现。
  4. 样式不统一：有的块是「卡片 + 图标行」，有的是「小标题 + 卡片」；规则有时是卡片内 chip、有时是卡片外 chip；搜索表单缩进 66pt 的独立表单列；权限行没有图标；记忆规则是三张说明卡。
  5. 默认全展开：没配置的 Cloudflare 表单默认占据首屏，真正常用的开关被挤到下面。

方案：主从布局 + 统一页面模板

  • Tab 改为左侧二级列表：每项能力一页，列表直接显示状态点和一行状态，「需要处理」不必再进概览找。
  • 按心智分组：概览 / 能力（搜索、文件、代码、操作电脑）/ 扩展（技能、MCP）/ 个性化（记忆）。去掉「扩展」里的二级分段。
  • 启动器功能迁出：计算器、应用搜索、关键字、工作流移到一级导航「启动器」。它们由启动器触发，不经过 Agent。
  • 统一页面模板：页头（图标 · 标题 · 一句话说明 · 状态徽章 · 总开关）→ 「设置」卡片 → 「安全规则」卡片 → 脚注。所有行都是「左：标题 / 说明，右：控件」。
  • 渐进展开：搜索服务关闭时只显示一行；选了服务才出现凭据；Cloudflare 的 BYOK 别名收进「高级选项」。
  • 概览精简：只保留对话存储选择和「需要处理」清单，不再重复能力卡。

落地影响（代码）

  • AgentConfigurationTab 改为按能力的 AgentSettingsPane；AgentCapability.destination 直接映射到 pane。
  • AgentUnderlineTabs → 二级列表组件，复用 AgentCapabilityStatus 显示状态点。
  • 抽出 AgentPaneHeader / AgentRulesCard，替换现有 chip、规则卡等多种写法。
  • AskLauncherPluginSettingsView、AskWorkflowSettingsView 及两个开关移到新的 launcherPage，设置项和存储键都不变。
  • 窗口很窄（< 900pt）时，二级列表折叠成页面顶部的下拉菜单。
