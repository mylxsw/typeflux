## Local content search (GUL-383)

Launcher → Built-in Search → Files has an inline experimental content-search card, disabled by default. Setup and management stay inside the current settings page. Content search shares the filename search directories and exclusions; changing that scope reconciles both indexes. Apple Silicon, macOS 14+ and Metal are required; unsupported devices cannot enable the setting, including through a persisted preference. Filename search remains available independently.

Hidden files, configured exclusions, credential paths, symlinks, non-local mounts, packages and cloud-only placeholders are skipped. Full Disk Access is checked before indexing and again before returning results. Documents include UTF-8 text/Markdown/CSV/TSV/reStructuredText and text-layer PDFs. Scanned PDFs still require OCR. Document reads run in a cancellable filesystem child with descriptor checks. UTF-8 reads and PDF text output advance through 32 KiB batches, with page/UTF-8 offsets and overlap across text batches; files have no total byte, character, page or chunk quota. PDFKit opens PDFs lazily through the held descriptor; its page decoder can still allocate a full page string. Discovery, file jobs and media encoding checkpoints persist in SQLite. Directory walks are revalidated after restart because folders may have changed while the process was absent; completed file extraction and encoding batches are reused.

Documents are processed before images, then audio, then video. Media work waits for 15 seconds without keyboard, pointer or scroll activity before each file and segment. Recording/processing, Low Power Mode and serious thermal pressure pause background indexing. Changed document paths are drained at each media segment boundary and during idle waits, using a separate file reader while staged media segments remain intact. New document events are coalesced for 150 ms when no indexing is active and also preempt between document batches. An already running document embedding batch (at most eight chunks) finishes before background work yields to a query. Committed documents remain searchable while media is indexing, downloading its model or waiting for idle time. A media-model failure leaves document search available and offers retry.

The filesystem child makes a private, descriptor-checked snapshot before decoding media. Images are reduced to at most 1008 pixels, standalone audio uses 30-second mono 16 kHz windows with a 25-second step and conservatively skips near-digital silence. Video samples its video track every 0.5 seconds plus a tail request one 600th of a second before the track end, using actual AVFoundation output timestamps. A 16×16 RGB thumbnail skips frames only when mean difference is at most 2/255 and peak difference is at most 12/255 compared with the last retained frame. Small visual details and moments between sample times can still be missed. Video audio retains the existing non-overlapping extraction path. Derived files are private and removed after embedding. The verified snapshot survives cancellation/pressure interruption; successful publication removes it, and orphan cleanup removes abandoned generations. Completed media vectors and segment positions are staged durably on disk and reused after cancellation/restart; the video request cursor, last actual timestamp, bounded thumbnail reference and tail completion are saved separately from encoded segment ordinals, atomically with retained vectors. Duplicate-only requests advance without JPEG output or embedding; a file becomes searchable only after every segment succeeds and its source metadata is revalidated. Unchanged media with matching provenance reuses its vectors without waiting for idle time. A decoder failure preserves completed private segments for the same verified file version. Corrupt/unsupported files are skipped; storage and runtime failures remain visible errors. Large media does not inherit the document-size bound.

The independent `SemanticSearch/semantic-files.sqlite` WAL database stores metadata, chunk text, PDF page numbers, media timestamps, FTS5 terms and normalized 768-dimensional Float32 vectors. The timestamp migration preserves existing document embeddings. Unicode compatibility and case normalization is shared by indexing and queries; Latin accents fold while Japanese voicing remains significant. The additive lexical recipe migration rebuilds FTS terms while retaining compatible vectors. After mixed old/new-normalizer writes during rollback/re-upgrade, use Rebuild to align lexical terms; the recipe is not an old-writer detector. CJK pretokenization is retained; lexical recall uses bigrams instead of common one-character overlaps and ignores English stopwords. Complete term coverage, quoted phrases, exact identifiers, BM25 ties and type hints guide lexical ranking. Semantic ordering calibrates per-file maxima across text-script/media classes, shrinking small classes toward the shared distribution; absolute raw cosine and distinct-file margins control rejection. Single-class and single-vector indexes retain their raw score fallback. Each extracted batch publishes FTS with its checkpoint transactionally; compatible vectors follow in true multi-sequence encoder batches of at most eight and 2,048 tokens. Measured one-item extraction prefetch did not help and is not used. Jobs retain pending/partial/done/skipped/failed state, retry attempts and fixed failure codes. Long files rotate behind other queued documents after each batch. File identity, nanosecond modification/change times, a generation token and the extraction recipe prevent stale responses from joining a newer version. Segments record UTF-8 offsets or PDF pages/media times, modality, segment kind and model/projector/prompt/sampling/chunking versions. Additive migration preserves compatible payloads, but legacy documents are extracted again because their old completion rows cannot prove tail coverage. Incompatible vector profiles are invalidated atomically. Media with unknown or incompatible projector provenance is excluded from vector queries while paused or rebuilding; compatible legacy document vectors remain available. Cancelled scans never prune unvisited files; a failed subtree protects only that subtree, and individual extraction failures do not prevent pruning confirmed ranges. Query scope/type/extension/folder filters apply before ranking and current file identity is checked before publication.

Filename hits publish first in mixed search and `f` mode. A quiet, nonselectable spinner row says that file contents are still being searched, including when no names match. Existing hits remain selectable and previewable while content arrives; selection survives late publication. Name hits retain their scores and match ranges, with content evidence merged onto the same file. Content-only hits cannot take the mixed launcher's default Return action. Content rows show a passage and page where available; opening/revealing/copying continues to act on the source file.

The right-side preview also works in `f` mode, including partial filename results. A content PDF opens the actual matched page and highlights the passage directly on its rendered page, with Unicode/whitespace normalization. Preview cache keys include the passage/page/timestamp so the same file can display a different match. Files without page evidence retain the first-three-page preview. Audio/video previews start at the matched segment. PNG/JPEG indexing also stores on-device OCR text. Audio/video embeddings do not provide transcription text.

Body FTS uses an independent read-only WAL connection and publishes through both launcher entries before any semantic debounce or model work. Pausing indexing, a missing/broken model, thermal pressure and active transcription preserve this low-cost channel. Queries use a separate interactive helper, a 45 ms semantic debounce (160 ms in Low Power Mode), a 16-entry query-vector cache and a 60-second helper idle timeout. Opening the launcher prewarms this helper. Only the latest pending query runs; identical queries share the resulting cached vector. Cancelling obsolete input does not kill a healthy in-flight model; lifecycle changes and voice activity do. Transport failure permits one helper restart, with a 3-second response and 15-second startup deadline per attempt. A failed query degrades that query without changing indexing/model availability. SQLite VM progress callbacks cancel broad FTS sorting before its first row; callbacks are removed before transaction cleanup. Vector search owns a separate read-only WAL connection. It refreshes immutable 256-row Float16 pages by committed page revision, expands one page to Float32 scratch and scores it with Accelerate matrix/vector multiplication. Insert, update, delete, file-version changes and ID reuse invalidate the affected pages atomically. The on-disk Float32 format and model profile remain compatible. Validated mixed-entry body results bypass filename coalescing once apps are ready, preserving the default Return rule. Opening the launcher also prepares the snapshot; scope and file eligibility are checked for each query, and passages are materialized only for top results. Permission validation shares one 80 ms warm budget across the candidate batch (3 seconds for a fresh metadata helper), in addition to cancellation. Interactive validation cancels a stalled root prewarm before waiting for the shared helper. Unvalidated candidates are withheld and a budget-limited semantic result is marked degraded; authorization is never cached. Indexing helpers have lower scheduling priority; document inference releases its model before media starts. The index remains local: no file or query is uploaded.

The model is `ggml-org/embeddinggemma-2-GGUF`, revision `bfcd298762cc34d0357ece5ebdd31791a3a374d8`. Both downloads are verified and atomically installed, with progress/cancellation/retry:

The extra media projector is downloaded lazily when idle media work first needs it. Clearing the content index turns the feature off and keeps verified models; removing models deletes both weights and the content index. Neither action changes source files or the filename index.

## Building and validation

`swift build` retains the normal macOS 13 app target. `bash scripts/build_semantic_helper.sh` builds the separate arm64/macOS 14 Metal/MTMD helper using pinned llama.cpp `4d756bc72bf00a4aacf410ae15a2d315f3db400d` (b11461). Developers need CMake and Xcode; `TYPEFLUX_CMAKE` can select CMake. Bundle scripts install/sign the helper under `Resources/LocalRuntimes/SemanticSearch`; Intel-only releases omit it. Users need no build tools or Python. DigUp's MIT attribution and bundled dependency notices are retained.

Focused suites cover content policy/store/indexing, media scheduling/extraction/runtime, content previews/progress and the affected filename/keyword/settings callers. Normal tests use isolated fixtures without downloads. Set `TYPEFLUX_SEMANTIC_TEST_MODEL` and `TYPEFLUX_SEMANTIC_TEST_PROJECTOR` to the pinned local weights to enable actual helper IPC image/audio inference; `TYPEFLUX_SEMANTIC_SCREENSHOTS` writes native appearance snapshots. The helper's English/Chinese retrieval smoke test is:

```sh
python3 scripts/validate_semantic_helper.py --helper .build/semantic/TypefluxSemanticHelper --model <pinned-model.gguf> --report <report.json>
```

Retrieval currently uses exact local vector scanning. OCR, transcription text, ANN extensions and cloud embeddings are outside this implementation.

## Optimization diagnostics (GUL-402)

`ContentSearch` signposts record accepted input, scheduling, helper queue completion, model load/encode, FTS/vector retrieval, metadata checks and main-actor publication. `LauncherSearch` and the mixed view update event cover the surrounding UI path. Events contain durations and opaque IDs, never query text or file paths. Both `f` and the dedicated `ss` content entry carry the trace through a 16 ms plugin debounce and publish validated FTS before semantic completion. Publication and view callbacks are not GPU-frame latency.

The 200-query synthetic bilingual regression oracle, raw helper timings, provider benchmark and retained baseline coverage gaps live in `docs/validation/gul-383/optimization/`. Rebuild labels with `python3 scripts/create_semantic_query_fixture.py`. The opt-in `SemanticSearchEvaluationTests` and `SemanticLatencyTests` use real pinned weights only when their documented environment variables are set. Model setup is never automatic during ordinary tests. GUL-403 adds durable long-file continuation and recovery; its focused fault cases and real event measurements live in `optimization/index-recovery/`. GUL-404 adds ranking calibration and vector snapshots in `optimization/ranking-scale/`; OCR/media text coverage remains in the subsequent content-coverage batch.

Full discovery and targeted event replay share the durable work queue. Document batches consume new events before choosing the next path, including while preempting a media segment; partial files rotate rather than recursively draining a single live event. Scan cleanup atomically removes committed content, jobs, media checkpoints and queued work for confirmed stale paths. Unconfirmed failed/pending directory subtrees retain their checkpoints and reasons until a successful scan or a scope change confirms removal.

Completed discovery now records its search scope, watched-volume event-stream identity and FSEvents position in the content database. A normal restart replays changes since that position and resumes queued jobs without walking unchanged directories. The position advances only after its work succeeds; changes during discovery replay from the position captured before the walk. Directory changes rescan their own subtree (a rename checks its parent), and failed directory reads remain protected and are retried on the next launch. A scope change, invalid event history, dropped events or the user's **Rescan** action starts a full discovery while keeping existing content searchable. **Clear Content Index** remains the separate destructive action.
