# 对话 · 临时对话（GUL-370）

交互设计稿：`docs/design/ask-temporary-chat.html`（用浏览器打开；窗口上方的工具条可以切换场景、登录状态和明暗主题）。

## 目标

用户有时只想问一个一次性的问题，比如查一个敏感话题、试一下 prompt、临时翻译一段内容。这类对话不应该：

- 出现在侧边栏历史、⌘K 搜索、iOS 或 Web 的对话列表里；
- 被写入本机缓存、草稿或启动器的输入历史；
- 读取或更新记忆（memory）。

关闭后这段对话就不存在了，也没有可以恢复的入口。

## 概念：存储位置的第三个选项

GUL-193 已经把“对话存在哪里”做成每个对话自己的属性：云端同步，或者仅存本机。临时对话作为第三个选项加进去，复用同一套交互：

| 存储 | 图标 / 颜色 | 历史 | 模型 | 生命周期 |
|---|---|---|---|---|
| 云端同步 | ☁ 蓝色 | 列表 + 多设备同步 | 云端模型 + 自己的模型 | 永久 |
| 仅存本机 | 🔒 紫色 | 本机列表 | 只能用自己的模型 | 永久 |
| **临时** | ⏳ 青色，虚线描边 | **不进入任何列表** | 云端模型 + 自己的模型 | **离开这段对话或退出应用时丢弃** |

“存储位置只能在发出第一条消息前选择”的规则同样适用：已经开始的临时对话不能改成普通对话，普通对话也不能改成临时对话。唯一的例外是下面的“保留这段对话”，它是用户主动、一次性的升级操作。

## 入口

- 侧边栏的 ✎ 按钮：不再拆成“✎ + ⌄”两个按钮，点击 ✎ 直接弹出下拉，选择新对话 ⌘N / 新私密对话 ⇧⌘N / **新临时对话 ⌥⌘N**。快捷键直接新建，不弹下拉。
- 输入框左下角的存储图标：卡片中增加“临时 · 不保存”选项（仅空对话可选）。
- 启动器（⌥Space）：**不新增控件**，沿用现有布局（顶部是上下文胶囊、输入框、麦克风和发送；中间是默认态建议；底栏是 + / 存储图标 / 模型 / 权限 | 截图，再加按键提示）。
  - 点底栏的存储图标（☁），在同一张存储卡片里选择「临时 · 不保存」；或者输入 `/temp`（命令列表里有这一项，再输入一次就关闭）；也可以按 ⌥⌘N。
  - 选中临时后：卡片改为青色虚线描边，存储图标变成 ⏳，发送按钮变成青色，输入框占位符改为“临时提问，不保存 · / 命令”，底栏按键提示前加上「⏳ 临时 · 不进历史」。
  - 默认态隐藏「继续对话」一段（临时只作用于新提问）；「针对选中」里的关键词动作（fy / sum / rw / ex）不受影响。
  - 打字后，“问 AI”这一行改为「⏳ 临时提问 “…” · 不保存 · 不使用记忆」。应用、计算等快捷结果不变。
  - 只影响这一次提问，下次唤起恢复默认。
- ⌘K 面板：增加“新临时对话”动作。

## 进行中的临时对话

- 标题栏右侧显示 `⏳ 临时对话` 标签，取代 credits / “仅存本机”标签。点击后弹出说明：不保存、不使用记忆、何时丢弃，并提供“保留这段对话”的按钮。
- 新对话页：标题仍然是“有什么想问的？”，不再重复展示临时对话的说明。
- 输入框使用青色虚线描边，发送按钮也是青色，和私密对话的紫色一样，只用颜色说明对话类型。
- 侧边栏：临时对话**不出现在历史分组里**。它进行期间，列表顶部固定显示一行虚线的“临时对话 · 进行中”，作为当前选中项。
- 窗口可以隐藏，临时对话会继续保留在内存中；用 ⌥Space 或菜单重新打开时仍然在。

## 丢弃时机与确认

满足下面任一条件时丢弃：

1. 用户点击“结束临时对话”（标题栏卡片中）；
2. 新建对话，或者在侧边栏选中另一段对话；
3. 退出 Typeflux、切换账号或退出登录。

对话里至少有一条消息时，情况 1、2 会弹出确认框：「结束这段临时对话？对话和工作区将被删除，无法恢复。」按钮依次为：`保留这段对话…`、`取消`、`结束`；附带“不再询问”选项，对应设置项“离开临时对话前确认”。情况 3 遵循现有的退出流程，不额外弹框，有正在运行的任务时仍然使用现有的“停止任务”确认。

切走就是离开：选中另一段对话或新建对话时，临时对话就结束了。侧边栏顶部那一行只用来标识当前对话，不能作为切回来的入口，这样行为简单，也容易预测。

## 保留这段对话

误开临时对话之后，用户可以把它升级为普通对话：

- 用云端模型运行的临时对话会变为**云端同步**的对话（服务端清除 `expires_at`）。
- 只用本机/自己模型运行的临时对话会变为**仅存本机**的私密对话（把内存中的记录写入 `AskLocal/`）。
- 升级之后不会补发记忆。标题会和普通对话一样自动生成。

## 数据边界（写什么，不写什么）

| 写入点 | 普通对话 | 临时对话 |
|---|---|---|
| `AskConversationCache`（SQLite 快照、草稿、工具日志） | 写 | **不写**，只在内存中保存 |
| `AskLocalEngine` JSON（`AskLocal/*.json`） | 私密对话写 | **不写**，引擎使用内存存储 |
| 服务端 `ask_conversations` | 云端对话写 | 写入，但带 `expires_at`；列表接口过滤；客户端结束时 DELETE；后台任务清理过期记录 |
| 启动器输入历史 `AskLauncherInputHistoryStore` | 写 | **不写** |
| 记忆注入（global soul / app 摘录 / explicit notes） | 默认开 | **不发送**，记忆胶囊隐藏 |
| `memory` 工具（remember / forget） | 可用 | **不提供** |
| 自动标题 | 生成 | **不生成**，标题固定为“临时对话” |
| 用量 / credits 计费 | 记录 | 照常记录（只有数字，不记录内容） |
| 工具审批“本对话内允许” | 进程内 | 对话结束时清除 |
| 对话工作区 | 普通对话保留 | 对话结束时删除整个工作区 |
| 笔记、日历等显式写入类工具 | 需要确认 | 需要确认；用户明确同意的副作用照常生效 |
| 截图 / 选中文本上下文 | 随消息上传或保存 | 只保存在内存中；云端运行时随请求上传，到期后和对话一起删除 |

产品文案要如实说明：用云端模型时，请求仍然经过 Typeflux Cloud，服务端最多保存 24 小时用于完成运行，然后删除。卡片中的写法是：“使用云端模型时，内容会在服务端临时保留，最长 24 小时后删除。”

## 实现映射

以下是实际实现的方式，和最初的方案略有不同。

客户端（`typeflux`）：

- `AskDraft` 新增 `temporary: Bool?`，`AskStorageKind`（`.cloud / .local / .temporary`）负责描述存储卡片和图标。没有替换 `storesLocally`，所以旧草稿不需要迁移。新增 `/temp` 命令，`/local` 保持不变。
- `AskConversationModel.temporaryConversation`（`AskTemporaryConversation(id, cloud)`）记录当前唯一的临时对话。路由用 `AskRoute.temporary(cloud:)`，缓存分区是 `AskRoutedAPI.temporaryOwner`。首条 `send` 带上 `temporary: true`。
- 对话在哪里运行，由首条消息使用的模型决定：云端模型在服务端运行；用户自己的模型交给 `AskLocalEngine`，引擎把这个对话的 id 记入 `temporaryIDs`，只保存在内存里，不写 `AskLocal/*.json`，也不出现在列表里。
- `AskTemporaryCache` 包装了原有缓存：`temporary` 分区的快照、草稿和工具日志都写入内存里的 SQLite，其他分区照常使用磁盘。
- 不发送记忆，不提供 `memory` 工具（`offeredTools`），标题策略关闭，启动器输入历史不记录，`updateSummary` 和 `scheduleTitle` 都会跳过临时对话。
- 离开前确认：`leaveTemporaryConversation(for:)`，对话框由 `AskTemporaryLeaveConfirmation` 弹出。结束对话：`discardTemporaryConversation()`，取消运行并删除服务端或引擎中的副本、内存缓存和对话工作区。保留对话：`keepTemporaryConversation()`，正在保留的对话不会被下一段临时对话删除。
- 界面：`AskNewConversationMenu`（点击 ✎ 弹出）、`AskTemporaryChip`、`AskTemporaryHistoryRow`；存储卡片和存储图标都增加第三种类型；`AskTheme.temporaryTint` 和 `temporaryDash` 用于青色虚线样式；设置页新增 `AskTemporarySettingsView`。

服务端（`typeflux-api`）：

- 迁移 `00071_add_ask_conversation_expiry.sql`：新增 `expires_at` 列，并为非空值建部分索引。过期时间只保存在这一列里，不写进 JSON。快照保存时不会改动它，所以过时的副本无法让已保留的对话重新变回临时对话。
- `temporary: true` 只在创建对话时生效，过期时间设为 24 小时后。`List` 过滤掉这些对话；`Get` 对已过期的对话返回 404；`POST /:id/keep` 把过期时间清空。临时对话不固定记忆，也不生成标题。
- 调度任务 `ask-temporary-cleanup` 每小时按批次（每批 500 条）删除过期的对话，steering 和 usage 行跟随级联删除。

iOS（`Apps/iOS`）：第一期只保证列表不显示临时对话（服务端已经过滤），入口留到第二期。

## 测试计划

- `AskTemporaryConversationTests`：路由、内存缓存、`refreshHistory` 不包含临时对话、离开时的确认和丢弃、“保留”分别升级为云端和本机、账号切换时清除。
- `AskLocalEngineTests`：内存存储模式下目录里没有新文件。
- `AskLauncherInputHistoryTests`：临时提问不写入输入历史。
- `AskMemoryTests`：临时路由下不注入记忆，也不提供 memory 工具。
- 渲染测试：深色、浅色主题下的临时对话页、标题栏卡片、确认框，以及启动器选中「临时」后的默认态和输入态。
- 服务端：`List` 过滤、`keep`、过期清理（Postgres 测试），`temporary` 只在首条消息生效。

## 不在本期范围

- iOS 的临时对话入口。
- 把临时对话设为默认（“总是以临时对话开始”）。
- 临时对话导出 / 分享。
