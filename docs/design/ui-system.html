基础规范：一套 Token，两种形态

核心原则：几何不随形态变化，材质与形状随形态变化。控件高度、间距、字号在“传统”和“Liquid Glass”下完全相同，切换形态时页面不会跳动；变化的只是圆角（经典 6pt / Glass 胶囊）、表面（不透明 / 半透明 + 模糊 + 边缘高光）和投影。切换右上角的开关可以看到所有色板实时变化。

设计原则

一个意图，一个组件

搜索、选择、切换、确认……每种交互意图只对应一个组件，不按页面重新实现。

内容优先

层级靠字重、留白、分组表达，不靠颜色和阴影。每个区域最多一个主按钮。

贴近原生

行为与 macOS 一致：⌘F 聚焦搜索、Esc 清空 / 关闭、回车确认、菜单勾选在前。

形态只是皮肤

组件不判断 usesGlass；它只读 token，由 token 层根据形态解析。

颜色 语义命名；组件只引用语义 token，不写具体色值

字体 8 档，替代现有 40 种字面量字号；系统字体 SF Pro / 苹方

组件库：每种意图只有一个组件

以下所有组件都是可交互的（悬停、点击、键盘、输入）。每个组件给出 SwiftUI 命名、规格和使用规则。切换右上角“形态”可看到同一组件在两种形态下的差异——只有形状和材质变化。

按钮 TFButton(role:, size:) · TFIconButton

角色 × 尺寸

sm 24 · md 30 · lg 36
  • primary：区域内唯一的推进动作（保存、添加、开始）。一个卡片 / 弹窗 / 页头最多一个。
  • secondary：其它显式动作（取消、测试连接、导入）。
  • plain：低优先级 / 内联动作（稍后、查看全部），悬停才出现底色。
  • destructive：删除 / 清空；确认弹窗内用 solid 变体。
  • 按钮顺序：次要在左，主按钮在最右；弹窗底部右对齐。
  • 不使用渐变、彩色投影；不和 .borderedProminent 等系统样式混搭。

落地路线：先 Token，后组件，再逐页替换

目标是在不打断功能迭代的前提下完成统一。每一步都可以单独合并、单独回滚，并有快照测试兜底。

阶段 0 · Token 层（约 1 周）

  • 新增 UI/DesignSystem/TFTokens.swift：TFColor / TFFont / TFSpace / TFRadius / TFHeight / TFElevation，按 (InterfaceStyle, ColorScheme, reduceTransparency) 解析。
  • StudioTheme、AskTheme、ModelVisualStyle、AskStyleMetrics 改为转发到新 token（保留旧名，标 @available(*, deprecated)），行为先不变。
  • 测试：token 解析表的单元测试（两种形态 × 两种外观 × 降低透明度）。

阶段 1 · 基础组件（约 2 周）

  • TFButton / TFIconButton、TFSearchField、TFSelect / TFMenuButton、TFSegmented / TFTabs、TFToggleRow、TFCard / TFListRow / TFSection、TFBadge / TFChip / TFKeyHint、TFBanner / TFToast / TFEmptyState、TFSheet。
  • 组件内部不再出现 usesGlass 判断，只读 token。
  • 测试：沿用 AskConversationVisualTests 的渲染方式，为每个组件输出 4 张快照（经典/Glass × 浅/深）+ 交互状态（hover/pressed/disabled/focus）。

阶段 2 · 逐页替换（按问题严重度）

2a设置窗口：词库、人设、模型、Agent、启动器、历史（P1 搜索/按钮/选择器）
2b浮动面板：启动器、⌘K、剪贴板 → 模板 C
2c资料库：笔记、单词本、随便问侧栏 → 模板 B
2d工作流编辑器、系统监控、截图编辑、引导、登录、关于

每个 PR 只迁移一个页面，附前后对比截图（两种形态 × 两种外观）。

阶段 3 · 防回退

  • SwiftLint 自定义规则：在 UI/DesignSystem/ 以外禁止 .font(.system(size: <数字>、cornerRadius: <数字>、NSColor(calibrated…)；以当前数量作为基线，只减不增。
  • 删除私有样式枚举：ModelVisualStyle、AskWordBookStyle、AskNotesStyle、AskWorkflowEditorStyle、SystemMonitorTheme、OnboardingProviderStyle。
  • 本文档（docs/design/ui-system.html + .md）作为新页面设计的唯一依据，新组件先加到这里再写代码。
