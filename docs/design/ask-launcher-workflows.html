脚本输出 JSON，就是一个列表

  • 脚本把 {"items": [...]} 打印到 stdout。格式兼容 Alfred Script Filter，已有的脚本可以直接用。
  • 每一行有 title / subtitle / icon / arg。↩ 按 action 执行（打开、复制、写回、在 Finder 中显示、带新参数重跑、问 AI）；⌥↩ 和 ⌘C 由 mods 决定。
  • ⇥ 把 autocomplete 填进输入框，可以逐级深入；rerun 可以定时刷新（例如构建状态）。
  • 分组标题右侧标明运行时和耗时，用户知道结果来自哪段脚本。

  • stdout 按行流式显示，操作和 AI 指令一样：↩ 复制、⌥↩ 写回或替换选中、⌘R 重新运行。

失败要说清楚，并给出下一步

  • 卡片显示退出码、耗时，以及 stderr 的最后几行。脚本也可以打印一行 {"error": "…"}，给出一句给人看的原因。
  • 常见的下一步做成按钮：重试、设置清单里声明的密钥、打开运行记录、编辑脚本。
  • 超时、输出超过上限、缺少解释器（例如「没有找到 python3，可以用 Homebrew 安装」）都在这里说明，启动器不关闭。
  • ⌘↩ 把错误交给 AI，帮忙改脚本。

一眼看出每个工作流的状态

  • 每行显示：图标、名称、运行时、关键字、状态和开关。
  • 状态有四种：已信任、文件已修改，需要重新确认（哈希变了，自动停用）、缺少运行时、清单有误（点开定位到出错的字段）。
  • 新建时从模板开始（Python / Node / Shell / 可执行文件 × 文本 / 列表 / 执行）；也可以导入文件夹或 .typefluxworkflow。
  • 工作流的关键字和内置插件的关键字放在一起校验重名。

运行别人写的代码前，先看清楚

  • 导入，或者文件在 Typeflux 之外被修改（哈希变了）时弹出。在设置里自己编辑保存的不会弹。
  • 列出关键字、实际运行的命令、是否要选中文字、需要的密钥、全部文件，并且可以查看代码。
  • 边打边出要单独勾选：它让脚本在每次按键时运行。
  • 参数只作为独立的 argv 传入，从不拼进 shell 命令；环境变量从干净的集合开始，不带 Typeflux 自己的凭据。
