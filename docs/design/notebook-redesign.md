# 笔记本改版与 Agent 笔记本技能 设计方案

> 状态：设计（GUL-322），未实现。可交互设计稿：`docs/design/notebook-redesign.html`，截图在 `docs/design/notebook-redesign/`。
> 前置：笔记本 v1 已上线（GUL-292，`docs/design/ai-command-results.md` §4），代码在 `Sources/Typeflux/Ask/Notes/`。外观沿用单词本改版（`docs/design/word-book-redesign.md`）的 Liquid Glass 窗口。

## 0. 一页结论

1. **定位**：笔记本是本机的 **Markdown 笔记本**。内容有四个来源：对话里存的回答（新增）、AI 指令结果 ⌘S、截图文字，以及自己写的和导入的笔记（新增）。默认按 Markdown 渲染显示，可以编辑原文，可以导出。
2. **窗口改用 Liquid Glass 三栏**：悬浮玻璃侧栏（新建 / 资料库 / 来源 / 标签 / 最近删除）、按天分组的列表、文档式详情（大标题 + 属性行 + 来源卡 + 正文 + 大纲），底部是玻璃操作条。
3. **编辑**：「阅读 / 编辑 / 分栏」三种模式（⌘E、⌥⌘E）。编辑区在原位显示带语法高亮的 Markdown 原文，上方有格式工具条，**自动保存**。阅读时可以直接勾选待办。被改过的 AI 结果可以「还原为原始结果」。
4. **整理**：⌘N 新建；多选后批量加标签、置顶、合并复制、导出、删除；删除先进「最近删除」，保留 30 天；把 `.md` 拖进窗口就能导入。
5. **导出**：单条可导出为 `.md`、`.html`、PDF，也可以复制 Markdown 或富文本、系统共享；批量导出为一个文件夹，每条笔记一个 `.md` 文件（带 YAML front matter）。
6. **Agent 能用笔记本**：新增内置技能 `notebook`（规定什么时候查、怎么引用、怎么写）和本机设备工具 `notebook`（`search` / `read` / `list` / `create` / `append` / `update` / `tag` / `delete`）。对话中提到笔记里的内容时，模型可以搜索、读取并引用笔记，也可以按用户要求写入或整理。读取和写入都按设备工具的方式确认；带「私密」类标签的笔记对 Agent 不可见。以后会把同一组操作做成本机 MCP 服务，开放给其他客户端。
7. **分 5 个 PR**：P1 数据层，P2 窗口改版，P3 编辑器，P4 入口（对话存入、`nb` 新建），P5 Agent 工具、技能和 MCP。

## 1. 现状与问题

截图见 issue。v1 的问题：

| 问题 | 现状 | 改版 |
|---|---|---|
| 只能被动收藏 | 只有 AI 指令 ⌘S 和截图文字会写入笔记本；**对话回答不能存**；也不能自己新建 | 对话回答和选中的文字都能存；⌘N 新建；可导入 `.md` |
| 编辑生硬 | 「编辑」进入左右分屏：左边是等宽 `TextEditor`，右边是预览；没有工具条，要点「完成」才保存 | 原位编辑 + 语法高亮 + 工具条 + 自动保存；分栏是可选模式 |
| 详情信息挤 | 来源、模型、时间挤在一行小字；原文默认折叠；5 个只有图标的按钮挤在底栏 | 属性行（来源 / 时间 / 标签）、来源卡（原文或提问，可「回到对话」）、玻璃操作条只放常用动作，其余收进「导出」和「⋯」菜单 |
| 列表单调 | 无分组；摘要只有一行；看不出笔记从哪来 | 按「置顶 / 今天 / 昨天 / 本周 / 更早」分组；两行摘要；来源图标；搜索命中高亮 |
| 导出弱 | 只能把当前笔记导出为 `.md` | md / html / pdf / 复制 / 共享；批量导出；front matter 可选 |
| 删除不可找回 | 只能在窗口打开期间撤销 | 「最近删除」保留 30 天 |
| 长笔记难读 | 没有目录 | 右侧大纲（有 2 个以上标题时显示）+ 字数和待办进度 |
| Agent 不知道笔记本 | 对话里无法引用已存的内容 | `notebook` 技能 + 工具（§6） |

- **尺寸**：默认 1240×760，最小 900×560。窄于 1080 时隐藏大纲；窄于 980 时侧栏收成图标列（与工作区一致）。
- **材质**：复用 `AskGlass`。侧栏、工具条、操作条、菜单、提示条用玻璃；列表和正文放在窗口底色上，保证可读。开启「减少透明度」时改用不透明底色。
- **侧栏**
  - 顶部是醒目的「新建笔记 ⌘N」。
  - 资料库：全部 / 置顶 / 最近 7 天。
  - 来源：对话 / AI 指令（下面按指令列出，沿用 v1 的「按指令」）/ 截图文字 / 手写 / 导入，只显示有笔记的来源。
  - 标签：带颜色圆点，「+」新建，右键可以重命名、改颜色、删除。
  - 最近删除。
  - 底部：「仅保存在本机」、导入、导出全部。
- **列表**
  - 标题行：范围名、条数、多选、排序（最近更新 / 创建时间 / 标题）。
  - 过滤框（⌘F）匹配标题、正文和原文；输入 `#标签` 按标签筛选。
  - 行：来源图标、标题、时间、两行摘要、指令名和标签。搜索时高亮命中的词。
  - 没有匹配时提供「以『关键词』为标题新建」。
- **详情**
  - 顶栏：面包屑（来源 · 指令 · 置顶）、自动保存状态、「阅读 / 编辑 / 分栏」切换、置顶、大纲开关、导出菜单、「⋯」（在独立窗口打开、复制链接、移到最近删除、显示 front matter）。
  - 文档区，阅读宽度 700：
    - 可编辑的大标题。
    - 属性行：来源（可点「回到对话」或「再次运行」）、时间（编辑过的显示「还原为原始结果」）、标签。
    - 来源卡：对话显示「你的提问」，指令显示「原文」，截图显示缩略图；可以折叠。
    - Markdown 正文。
  - 大纲：根据 `#`–`###` 标题生成，点击跳转，滚动时高亮当前标题。下方显示字数、阅读时间和待办进度。
  - 底部玻璃操作条（阅读模式）：复制 ⌘C、富文本 ⇧⌘C、问 AI、独立窗口 ⌘O、删除。编辑模式下操作条显示字数和「完成 ⌘E」。
- **提示条**：复制、导出、删除在底部用玻璃提示条反馈；删除提示带「撤销」，导出提示带「在 Finder 中显示」。
- **空状态**：图标、「笔记本还是空的」，加三条上手提示（对话里存入、⌘S、⌘N 或拖入 .md），以及「新建笔记」按钮。

### 2.1 Markdown 渲染

沿用 `AskTranscriptText` 和 `MarkdownHTMLRenderer`，并补充：

- **待办**：`- [ ]` 和 `- [x]` 显示为可点的复选框，点了直接改写原文的那一行（只改这一个字符，`updatedAt` 更新，`editedAt` 不变）。
- **代码块**：右上角显示语言和「拷贝」，悬停时出现。
- **表格**：圆角细边框，表头底色。
- **标题**：带锚点，供大纲和 Agent 引用 `笔记 › 标题` 时跳转。
- **搜索词高亮**：从列表搜索进入时，正文中的命中词高亮，⌘G 跳到下一处。

## 3. 编辑

| 模式 | 进入 | 显示 |
|---|---|---|
| 阅读 | 默认；`esc`；⌘E（编辑时） | 渲染后的 Markdown |
| 编辑 | ⌘E；双击正文；新建笔记 | 原位的 Markdown 原文，带语法高亮（标记变淡，标题和粗体加重，代码着色），上方有悬浮格式工具条 |
| 分栏 | ⌥⌘E | 左边原文，右边预览，滚动同步 |

- **自动保存**：停止输入 0.6 秒后保存，切换笔记、关闭窗口或失去焦点时立即保存。顶栏显示「已自动保存」。不再需要「完成」才能保存，「完成」只表示回到阅读。
- **撤销**：编辑器自带 ⌘Z / ⇧⌘Z，范围是本次编辑；跨编辑的版本恢复见下一条。
- **还原为原始结果**：来自 AI 的笔记首次被编辑时，在 `original_body` 里保存原文。属性行显示「还原为原始结果」，还原本身也可以撤销。
- **格式工具条和快捷键**：标题 ⌘1–3、粗体 ⌘B、斜体 ⌘I、删除线 ⇧⌘X、列表、待办 ⇧⌘L、引用、代码、链接 ⌘K、表格。编辑时 ⌘B 是粗体；只有焦点不在编辑器里时，⌘B 才保留「打开笔记本」的含义。
- **编辑体验**：列表里按回车自动续上列表标记，Tab 和 ⇧Tab 调整缩进；粘贴富文本时转换成 Markdown（复用 `AskRichCopy` 的反向转换，做不到时保留纯文本）。
- **标题**：新建笔记的标题为空时，自动取正文的第一个标题或第一行。用户改过标题后不再自动改。
- **实现**：编辑器用 `NSTextView` 包装（`NSViewRepresentable`），用 `NSTextStorage` 增量着色，替换 v1 的 `TextEditor`，以支持高亮、续写列表和大文本性能。

## 4. 整理、导入导出

- **新建 ⌘N**：建一条空笔记（来源「手写」）并进入编辑，光标放在标题上。当前范围是某个标签时，新笔记自动带上这个标签。
- **多选**：⌘ 点击加选，⇧ 点击连选，⌘A 全选，列表右上角也有多选按钮。详情区显示「已选择 N 条」，操作条变为批量操作：加标签、置顶、合并复制（按列表顺序用 `---` 拼接）、导出、删除。
- **最近删除**：删除时设置 `deleted_at`，30 天后在启动时清理。笔记可以恢复或彻底删除，也可以「清空」最近删除。v1 的窗口内撤销保留。
- **导入**：把 `.md`、`.markdown`、`.txt` 拖进窗口，或点侧栏底部的「导入」，每个文件生成一条笔记（来源「导入」）。如果文件有 front matter，保留其中的 `title`、`tags`、`created`。单个文件最大 1 MB，一次最多 200 个文件。
- **导出**
  - 单条：`.md`（默认带 front matter，可以关）、`.html`（独立页面，内联样式）、PDF（`WKWebView` 打印），也可以复制 Markdown 原文（⌥⌘C）、复制富文本（⇧⌘C），或用系统共享。
  - 批量或全部：选一个目标目录，生成「笔记本导出 YYYY-MM-DD」文件夹，每条笔记一个 `.md`，文件名用 `AskNoteExporter.fileName`。重名时加 ` 2`、` 3` 后缀。
  - 选项「附带原文 / 提问」：在正文前加一个引用块。

## 5. 新的保存入口

- **对话回答**：在回答下方的操作行（复制 / 重新生成 / 引用 / 用量）中加「存入笔记本」。
  - 存入时，标题取提问的前 24 个字，正文是回答的 Markdown，来源为「对话」；记下 `conversation_id` 和 `message_id`，以便在笔记里「回到对话」。
  - 已存过的回答，按钮显示为「已存入笔记本」。再点一次取消：没编辑过就删除；编辑过就只提示（规则与 v1 ⌘S 相同）。
- **选中文字**：在回答里选中一段文字时，浮层出现「引用 / 复制 / 存入笔记本」，只存选中的这一段。
- **`nb` 关键字**：输入文字后，第一行是「新建笔记：『…』」（⌘↩），其后是搜索结果（↩ 打开）。已有的 `nb` 行为不变。
- **AI 指令 ⌘S、截图文字**：不变。

## 6. Agent：内置技能 `notebook` + 本机工具 `notebook`

目标：用户在对话中提到笔记本里的内容（「我之前存的 HNSW 参数」「笔记里那份东京行程」），Agent 能找到并引用；用户让 Agent 「存到笔记本」或「整理一下笔记」时，Agent 能写入和整理。

### 6.1 为什么是「技能 + 设备工具」

- **工具**提供能力。笔记只在本机（`notes.sqlite`），而云端对话的设备工具本来就在本机执行（`AskLocalTools`，见 `docs/ASK_CONVERSATIONS.md`「Agent tools」），所以和 `memory`、`files` 一样做成设备工具。云端对话和私密对话都能用，确认流程、风险分级和执行日志直接复用。
- **技能**规定用法：什么时候该查、怎么写搜索词、怎么引用、写入时遵守什么规则。技能只在用到时加载，平时只占工具说明里的一行描述，不会让每次请求都背上笔记内容。
- **MCP**：本机 MCP 服务 `typeflux-notebook` 复用同一套 `AskNotebookTools`，让 Claude Desktop、Cursor 等外部客户端访问笔记本，作为 P5 的可选部分，默认关闭。Typeflux 自己的 Agent 不走 MCP：MCP 工具一律按「不可撤销」处理，每次都要确认，体验不如内置工具。

### 6.2 工具 `notebook`

一个工具，用 `action` 区分操作，与 `memory` 和 `files` 的写法一致。

| action | 参数 | 返回 | 风险 |
|---|---|---|---|
| `search` | `query`（多个词时用空格分隔，按任一词匹配）、`tag?`、`source?`、`limit?`（默认 8，最多 20） | 每条一行：`id`、标题、标签、更新时间，以及命中位置附近约 160 字的摘要 | 读取 |
| `read` | `id`、`heading?`（只读某个标题下的内容）、`offset?`、`limit?`（默认 8000 字） | front matter、正文，以及是否还有更多内容 | 读取 |
| `list` | `scope`（`recent` / `pinned` / `tag:<名>` / `tags`） | 最近或置顶的笔记列表，或者标签和数量 | 读取 |
| `create` | `title`、`body`（Markdown）、`tags?` | 新笔记的 `id` | 修改 |
| `append` | `id`、`body`、`heading?`（追加到某个标题下的末尾） | 新的字数 | 修改 |
| `update` | `id`，加上 `title?`、`body?`，或者 `find` + `replace`（`find` 必须只匹配一处，与 `files.edit` 相同） | 改动摘要 | 修改 |
| `tag` | `id`、`add?`、`remove?`、`pin?` | 当前的标签和置顶状态 | 修改 |
| `delete` | `id` | 移到「最近删除」（可恢复） | 修改 |

- **找不到笔记**时，返回空结果并提示「可以换个说法再搜一次」，不报错。
- **搜索**：短期内沿用 LIKE，因为中文分词问题见 v1 的决定。多个词分别匹配，按命中的词数和更新时间排序。之后可以接入向量检索（见 §9）。
- **输出上限**：单次输出最多 12,000 字，超出部分用 `offset` 分页。

### 6.3 技能 `notebook`

技能的描述（写进工具说明）是：「Use the user's local Markdown notebook: find, quote, save or organize notes when the user mentions their notes, saved answers, or asks to save something.」

技能正文要点（实现时为英文）：

1. **什么时候查**：用户提到「笔记 / 笔记本 / 我存过 / 之前保存的 / 收藏的」，或者问题明显依赖自己记下的内容时，先 `search` 再回答。不要为每个问题都去搜笔记本。
2. **怎么搜**：从问题中提取 2–4 个关键词（中英文都写），先搜，必要时换同义词再搜一次。找到后用 `read` 读取，可以只读相关的标题段落。
3. **怎么引用**：用到笔记内容时，写明出处 `[[笔记标题 › 小标题]]`，客户端会显示为可以点开的笔记卡片。不要编造笔记里没有的内容；笔记和问题有冲突时，要指出来。
4. **怎么写**
   - 只有用户明确要求「存 / 记 / 追加 / 整理」时才写。
   - 写入的正文用干净的 Markdown，以标题开头，不加客套话。
   - 修改已有笔记时优先 `append`，或用 `update` 的 find/replace 只改相关部分，避免整篇覆盖。
   - 打标签时先 `list tags`，沿用已有标签。
5. **不存敏感信息**：不存密码、密钥和证件号。即使用户要求，也要先提醒。
6. **和 `memory` 的分工**：`memory` 只记关于用户的一句话事实或偏好，会进入每次对话的上下文；笔记本存成篇的内容，只在需要时查阅。不要把笔记写进 `memory`。

### 6.4 确认、隐私与可见性

- **读取**是「读取」级。默认每个对话第一次读取时询问，确认卡写明「笔记内容会发送给 {模型}」。用户可以在设置里改成「不再询问」或「每次询问」。私密对话使用本机模型时，提示文案相应改变。
- **写入**是「修改」级。默认每次都询问，确认卡显示改动预览（新增内容或 diff），可以选「本对话内允许」。`delete` 虽然只是移到「最近删除」，也按「修改」级处理。
- **版本保护**：Agent 每次修改前保存一份上一版（`note_revisions` 表，每条笔记最多保留 20 份）。笔记详情的「⋯」里有「撤销 Agent 修改」。Agent 创建或修改过的笔记，属性行会显示「由 Agent 写入 / 修改（对话『…』）」。
- **Agent 不可见的标签**：在设置里指定（默认是「私密」）。带这些标签的笔记，`search`、`list` 和 `read` 都视为不存在。笔记本侧栏中，这些标签显示一个小锁。
- **总开关**：设置 → Agent → 笔记本 →「允许 Agent 使用笔记本」。关闭后，工具和技能都不再提供给模型。技能也可以在现有的技能列表里单独关闭（`askDisabledSkills`）。
- **引用卡片**：回答中的 `[[标题 › 小标题]]` 显示为「引用笔记」卡片，点击后打开笔记本并滚动到对应标题。找不到这条笔记时，显示为普通文本。

### 6.5 MCP 服务 `typeflux-notebook`（P5 可选）

- 本机 stdio MCP 服务：Typeflux 的可执行文件加上 `--mcp-notebook` 参数，以 stdio 运行，在设置里显示可以直接复制的客户端配置。
- 暴露的工具和 §6.2 相同（`notebook_search`、`notebook_read` 等），有「只读 / 读写」两档。只读模式下不提供写入工具。
- 「Agent 不可见的标签」同样生效。每次外部调用写一条记录，在设置里可以查看最近的调用。
- 默认关闭。

## 7. 数据

在 `notes` 表上加列（`ALTER TABLE ADD COLUMN`，启动时按 `PRAGMA table_info` 迁移，老数据取默认值）：

| 列 | 类型 | 说明 |
|---|---|---|
| `source_kind` | TEXT NOT NULL DEFAULT `command` | `command` / `chat` / `screenshot` / `manual` / `import`。老数据中，`command` 等于任一语言下 `screenshot.text.title` 文案的记为 `screenshot`，其余记为 `command`；新写入时由调用方显式传入，不再靠名称判断 |
| `conversation_id` / `message_id` | TEXT | 来自对话的笔记用于「回到对话」 |
| `original_body` | TEXT | 首次编辑 AI 内容前的原文，用于「还原为原始结果」 |
| `deleted_at` | REAL | 最近删除；`list` 和 `count` 默认排除 |
| `author` | TEXT NOT NULL DEFAULT `user` | `user` / `agent`，表示最后一次修改的是谁 |

新表：

- `tags(name PRIMARY KEY, color, agent_hidden INTEGER)`：标签的颜色和对 Agent 是否可见。笔记上的标签仍然存在 `tags_json` 中。
- `note_revisions(id, note_id, body, title, created_at, author)`：保存 Agent 修改前的版本，用于撤销。

`AskNoteStoring` 新增 `trash()`、`purge(olderThan:)`、`revisions(of:)`、`search(terms:limit:hiddenTags:)`（供 Agent 使用，返回命中摘要）。`AskNoteQuery.Scope` 新增 `.recent`、`.source(kind)`、`.trash`。

## 9. 不在本次范围

- **云同步**：笔记仍只存在本机，同步需要后端支持，另开 issue。
- **文件夹或多个笔记本**：本次用标签加来源组织。如果标签不够用，再考虑加文件夹。
- **所见即所得编辑**：本次是原文编辑加预览。
- **语义检索**：当前用 LIKE。如果以后笔记数量大，或者需要「意思相近」的搜索，可以加本机向量索引（嵌入模型 + SQLite 向量扩展），`search` 接口不变。
- **笔记里的图片和附件**：本次只支持文字。
