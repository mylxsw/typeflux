# 终端会话入口与窗口标签：优化设计（GUL-697 反馈）

> 状态：设计稿，待确认。配套可交互设计稿：`docs/design/launcher-terminal-sessions-polish.html`（`?s=<id>` 打开某一屏，`?light=1` 浅色，`?solo=1` 只显示一屏，`?notes=0` 隐藏标注）。截图在 `docs/design/launcher-terminal-sessions-polish/`。

## 1. 启动器首页的终端会话

### 问题
- 首页是两行图标网格（快捷入口 + 应用），「终端会话」是一个半宽的列表行，插在网格上方，样式和宽度都对不上。
- 已经结束、空闲的会话也一直占着首页最显眼的位置。
- `launcherNeedsFullWindow` 把 `terminalHomeSessions` 算进去，简洁模式下只要有后台会话，启动器就被撑开。
- 底部左侧的两个图标是 Chat / Work 对话类型开关，不是终端入口，不能拿来复用。

### 方案（推荐 A：输入框右侧状态按钮，截图 `a` `a-pop` `a-simple`）
- **去掉首页的「终端会话」分组。** 网格和应用区保持原样。
- 有会话时，在语音按钮左边显示一个**状态按钮**：终端图标 + 状态点，多于一个会话时加数量。
  - 状态点取最需要关注的会话：等待输入（橙）> 运行中（绿，呼吸）> 上一条失败（红）> 空闲（灰）。
  - 没有会话时不显示。
- **点按：**
  - 只有一个会话时直接回到它（在窗口中的会话则把窗口带到前面）。
  - 多个会话时展开列表，`⌘J` 也可以打开或收起。
- **列表：**
  - 每行是状态点、命令（等宽）、目录。
  - 右侧：运行中显示时长，等待输入显示橙字「等待输入」，在窗口中的会话带窗口图标。
  - 悬停时出现 ×，用来结束会话。
  - 排序按状态优先级，同级按最近活动排。
  - 不加标题和说明文字。
- **简洁模式：** 按钮同样出现在单行输入框里，启动器保持单行。实现时从 `launcherNeedsFullWindow` 去掉 `terminalHomeSessions`。
- 输入 `>` 回到最近会话的行为不变；`>` 提示列表里仍然列出全部会话。

### 备选 B：快捷入口网格中的一格（截图 `b`）
终端作为网格第一格，图标角标是状态点或数量，名称是最近会话的目录。风格一致，但会把用户的第 7 个快捷入口挤到下一行，而且一格只能代表一个会话。仅作对比，不推荐。

## 2. 独立窗口的标签

### 问题
- 标签没有关闭方式，只能关整个窗口。
- 同一目录的两个会话标签都叫 `codes`，无法区分。

### 方案（截图 `tabs` `tabs-confirm` `tabs-menu`）
- **关闭：**
  - 悬停时，标签前端的状态点变成 ×，点按关闭（与 Safari、Finder 的标签一致）。
  - 中键点按标签也会关闭。
  - `⌘W` 关闭当前标签。
  - 关闭最后一个标签时，窗口一起关闭。
- **确认：**
  - 运行中的会话沿用现有确认：「“%@” 仍在运行」/ 结束并关闭 / 取消（`terminal.runner.close.*`）。
  - 空闲、失败、已退出的会话直接关闭。
- **区分：** 标签名是目录名。目录名重复，或者会话正在运行时，名称后用灰色等宽字附上命令（`codes  df -h`、`codes  npm run dev`）。完整路径和命令放在悬停提示里。
- **状态点：** 运行中绿色呼吸，等待输入橙，失败红，空闲灰，与启动器状态按钮一致。
- **右键菜单：**
  - 关闭会话 `⌘W`
  - 关闭其他会话 `⌥⌘W`：运行中的会话逐个确认
  - 移到启动器 `⌘O`
- **排序：** 标签可拖动调整顺序。
- **溢出：** 标签宽度在 76–220pt 之间伸缩，放不下时横向滚动。

## 3. 新增文案（`en` / `zh-Hans`）
| 位置 | zh-Hans | en |
|---|---|---|
| 状态按钮 tooltip（多个会话）| 终端会话 ⌘J | Terminal Sessions ⌘J |
| 列表行 × tooltip | 结束会话 | End Session |
| 标签 × tooltip | 关闭 ⌘W | Close ⌘W |
| 右键菜单 | 关闭会话 / 关闭其他会话 / 移到启动器 | Close Session / Close Other Sessions / Move to Launcher |

其余沿用现有字符串（`terminal.launcher.waiting`、`terminal.runner.close.*`）。

## 4. 验证
可交互稿在 macOS 的 headless Chrome 里跑了 15 项交互检查，全部通过：状态按钮与数量、列表排序、点按进入、`⌘J`、结束会话、简洁模式不展开、同名区分、悬停 ×、空闲直接关闭、运行中需确认、取消保留、`⌘W`、最后一个标签关闭窗口、右键菜单。
